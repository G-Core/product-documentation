## Attach volumes to an existing Virtual Machine

<p>When a volume is attached to a Virtual Machine, the VM name appears on the **Volumes** page in the **Instance** column. Otherwise, the **Attach to Instance** link appears. More than one volume can be attached to a Virtual Machine. However, volumes can only be used in the same region where the VM is created.</p>

<p>Volumes can be attached to a Virtual Machine either from the **Volumes** page or from the VM settings.</p>

<Tabs>
  <Tab title="From the Volumes page">
    <p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

    <p>2. Select the volume to attach and click **Attach to Instance**.</p>

    <Frame>![Volumes page with annotated attach to Virtual Machine link](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/attach-volume.png)</Frame>

    <p>3. Select the Virtual Machine from the **Choose Instance to attach to** dropdown.</p>

    <p>4. (Optional) Enter a value in the **Tag** field.</p>

    <Frame>![Attach volume dialog with options to select Virtual Machine and add a tag](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/attach-volume-to-instance.png)</Frame>

    <p>5. Click **Attach volume**.</p>

<p>The volume has been attached to the Virtual Machine.</p>
  </Tab>
  <Tab title="From Virtual Machine settings">
    <p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Virtual Instances**.</p>

    <p>2. Select the target Virtual Machine and click its name to open it.</p>

    <Frame>![Virtual Machines tab with two created instances](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/cloud-instances.png)</Frame>

    <p>3. Open the **Volumes** tab.</p>

    <p>4. Click **Add Volume**.</p>

    <Frame>![Volumes tab with Add volume button highlighted](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/attach-volume-instance-settings.png)</Frame>

    <p>5. Click **Select existing** to attach an existing volume to a Virtual Machine.</p>

<p>A new volume can also be created here. Click **Create new** and follow [Create&nbsp;a&nbsp;volume](/cloud/virtual-instances/volumes/create-a-volume).</p>

    <p>6. Select the volume to attach to the Virtual Machine.</p>

    <p>7. (Optional) Enter a value in the **Tag** field.</p>


    <Frame>![Add volume menu with options to add Virtual Machine and tags](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/add-volume-to-instance.png)</Frame>

    <p>8. Click **Add Volume**.</p>

<p>The volume has been attached to the Virtual Machine.</p>
  </Tab>
</Tabs>

## Manage volumes

<p>Volume management options depend on whether the target volume is boot or regular.</p>

<p>When many volumes exist, filter the list by name or UUID to locate a specific volume.</p>

### Rename a volume

<p>Both boot and regular volumes can be renamed:</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the target volume.</p>


<Frame>![Volumes tab with expanded settings menu](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/three-dot-menu-regular.png)</Frame>



<p>3. Click **Rename**.</p>

<p>4. Enter a new name.</p>

<p>5. Select **Save** to apply the changes.</p>


<Frame>![Rename volume dialog](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/rename-volume.png)</Frame>



<p>The volume has been renamed.</p>

### Manage volume tags

<p>Volume tags can be added during creation or managed later from the volume context menu:</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the volume.</p>

<p>3. Click **Tags**.</p>

<p>4. Add, edit, or remove key-value tag pairs and save the changes.</p>

### Detach a volume from a Virtual Machine

<p>Only regular volumes can be detached. The boot volume cannot be detached from a Virtual Machine as long as the VM exists. To detach a boot volume, delete the VM first.</p>

<p>To detach a volume:</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the target volume.</p>


<Frame>![Volumes tab with expanded settings menu](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/three-dot-menu-attached.png)</Frame>



<p>3. Click **Detach**.</p>

<p>4. In the confirmation dialog, click **Detach** again to confirm.</p>


<Frame>![Detach volume confirmation dialog](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/detach-volume-dialog.png)</Frame>



<p>The volume has been detached from the Virtual Machine.</p>

<Warning>
Detaching a volume does not stop billing unless the volume is deleted. A detached volume can be attached to any Virtual Machine at any time.
</Warning>

### Resize a volume

<p>Both boot and regular volumes can be resized:</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the target volume.</p>


<Frame>![Volumes tab with expanded settings menu](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/three-dot-menu-regular.png)</Frame>



<p>3. In the **Resize volume** dialog that opens, the current volume size in GB is shown. Enter the new size.</p>

<p>4. Click **Resize** to apply the changes.</p>


<Frame>![Dialog asking for a new volume size](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/resize-volume.png)</Frame>



<p>The volume size has been changed.</p>

<Warning>
When snapshots exist for a volume, increasing the size prevents a revert to the [latest&nbsp;snapshot](/cloud/virtual-instances/snapshots/take-a-snapshot-of-your-file-system#revert-a-volume-to-the-latest-snapshot). Only a new volume can be created from this volume's snapshot.
</Warning>

### Change volume type

<p>**Retype** changes a Standard volume to High IOPS SSD, or a High IOPS SSD volume to Standard. The action is available for a regular volume and for a boot volume.</p>

<Info>
The volume can stay attached to the Virtual Machine. **Retype** is in the volume menu while the status is **In Use**, and the Virtual Machine keeps running.
</Info>

<p>To retype a volume:</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the target volume.</p>


<Frame>![Volumes tab with expanded settings menu](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/three-dot-menu-regular.png)</Frame>



<p>3. Click **Retype**.</p>

<p>4. Select the desired volume type and then click **Retype** to apply the updates.</p>


<Frame>![Dialog asking to select a new volume type](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/retype-volume.png)</Frame>



<p>The volume type has been changed.</p>

<p>When multiple volumes are attached to one Virtual Machine, use the `rsync` and `cp` utilities to migrate data between volumes within an operating system.</p>

### Create an image from a bootable volume

<p>An image can be created from a boot volume and used to create a new Virtual Machine.</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the volume to use as the image source.</p>


<Frame>![Volumes tab with expanded settings menu](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/three-dot-menu-boot.png)</Frame>



<p>3. Select **Create Image**.</p>

<p>4. Specify the image name.</p>

<p>5. Select architecture.</p>

<p>6. Click **Create Image**.</p>


<Frame>![Dialog to select image and and architecture](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/create-image.png)</Frame>



<p>Within a few minutes, the image will be created and available on the **Images** page.</p>

### Delete volume

<p>A regular volume that is not attached to a Virtual Machine can be deleted. Boot volumes cannot be deleted directly. They must be detached first, which requires deleting the Virtual Machine. When the VM is deleted, the boot volume is retained by default and can be reused to create a new Virtual Machine.</p>

<p>To delete a volume:</p>

<p>1. In the Gcore Customer Portal, navigate to **Cloud** > **Storage**.</p>

<p>2. Click the three-dot icon next to the volume to delete.</p>


<Frame>![Volumes tab with expanded settings menu](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/three-dot-menu-regular.png)</Frame>



<p>3. Click **Delete**.</p>

<p>4. Type "Delete" in the confirmation field.</p>

<p>5. Click **Delete Volume**.</p>


<Frame>![Dialog asking to confirm volume deletion](/images/docs/cloud/virtual-instances/volumes/create-and-configure-volumes/delete-volume.png)</Frame>



<p>The volume has been removed from the Gcore Customer Portal.</p>

<Tip>
The **Group actions** button deletes multiple volumes at once. This option is available when at least one regular volume is not attached to a Virtual Machine.
</Tip>

<MethodSection id="api" label="REST API">

<p>Attach, resize, detach, or delete an existing volume.</p>

<Info>
An [API&nbsp;token](/account-settings/api-tokens) is required, along with a [project&nbsp;ID](/api-reference/cloud/projects/list-projects) and a [region&nbsp;ID](/api-reference/cloud/regions/list-regions).
</Info>

<p>Open a bash terminal and set these as environment variables before running the examples:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export GCORE_CLOUD_PROJECT_ID="{YOUR_PROJECT_ID}"
export GCORE_CLOUD_REGION_ID="{YOUR_REGION_ID}"
export VOLUME_ID="{VOLUME_ID}"
export INSTANCE_ID="{INSTANCE_ID}"
```

<p><code>VOLUME_ID</code> is the UUID of a volume created in [Create&nbsp;a&nbsp;volume](/cloud/virtual-instances/volumes/create-a-volume). <code>INSTANCE_ID</code> is required for attach and detach.</p>

## Attach a volume

<p>A volume attaches to one Virtual Machine at a time. Both must be in the same region. After attachment the operating system sees a new block device, <code>/dev/sdb</code>.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `instance_id` | Yes | UUID of the target Virtual Machine. |

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    client.cloud.volumes.attach_to_instance_and_poll(
        os.environ["VOLUME_ID"],
        instance_id=os.environ["INSTANCE_ID"],
    )
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "log"
        "os"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cloud"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        err := client.Cloud.Volumes.AttachToInstanceAndPoll(ctx, os.Getenv("VOLUME_ID"), cloud.VolumeAttachToInstanceParams{
            InstanceID: os.Getenv("INSTANCE_ID"),
        })
        if err != nil {
            log.Fatalf("attach volume: %v", err)
        }
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X POST \
      "https://api.gcore.com/cloud/v2/volumes/$GCORE_CLOUD_PROJECT_ID/$GCORE_CLOUD_REGION_ID/$VOLUME_ID/attach" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{\"instance_id\": \"$INSTANCE_ID\"}"
    ```

    <p>The response is a task ID. Poll <code>GET&nbsp;/cloud/v1/tasks/{task_id}</code> every 5 seconds until <code>state</code> is <code>FINISHED</code>. The volume status changes to <code>in-use</code>.</p>
  </Tab>
</Tabs>

## Resize a volume

<p>Volume size can only be increased. Resizing works while the volume is attached to a running Virtual Machine.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `size` | Yes | New size in GiB. Must be greater than the current size. |

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    volume = client.cloud.volumes.resize_and_poll(os.environ["VOLUME_ID"], size=20)
    print(f"New size: {volume.size} GiB")
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "log"
        "os"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cloud"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        resized, err := client.Cloud.Volumes.ResizeAndPoll(ctx, os.Getenv("VOLUME_ID"), cloud.VolumeResizeParams{
            Size: 20,
        })
        if err != nil {
            log.Fatalf("resize volume: %v", err)
        }
        fmt.Printf("New size: %d GiB\n", resized.Size)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X POST \
      "https://api.gcore.com/cloud/v1/volumes/$GCORE_CLOUD_PROJECT_ID/$GCORE_CLOUD_REGION_ID/$VOLUME_ID/extend" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{\"size\": 20}"
    ```

    <p>The response is a task ID. Poll <code>GET&nbsp;/cloud/v1/tasks/{task_id}</code> every 5 seconds until <code>state</code> is <code>FINISHED</code>.</p>
  </Tab>
</Tabs>

<p>After resizing, extend the filesystem inside the operating system so it can use the new space. On ext4, run <code>resize2fs</code>. On XFS, run <code>xfs_growfs</code>.</p>

<Warning>
If the volume has snapshots, resizing it prevents reverting to those snapshots. Only snapshots taken after the resize can be used. Reversion is described in [Take&nbsp;a&nbsp;snapshot](/cloud/virtual-instances/snapshots/take-a-snapshot-of-your-file-system#revert-a-volume-to-the-latest-snapshot).
</Warning>

## Detach a volume

<p>Only a non-boot volume can be detached. Detaching keeps the data. The volume status returns to <code>available</code>, and the volume can be attached to another Virtual Machine in the same region.</p>

<Tabs>
  <Tab title="Python SDK">

    ```python
    from gcore import Gcore

    client = Gcore()
    client.cloud.volumes.detach_from_instance_and_poll(
        os.environ["VOLUME_ID"],
        instance_id=os.environ["INSTANCE_ID"],
    )
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

        "context"
        "log"
        "os"

        client := gcore.NewClient()

            InstanceID: os.Getenv("INSTANCE_ID"),

        }
    }
    ```
  </Tab>
  <Tab title="curl">

## Delete a volume

<p>Only a detached volume can be deleted. A boot volume cannot be deleted directly. It is retained when the Virtual Machine is deleted.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    client.cloud.volumes.delete_and_poll(os.environ["VOLUME_ID"])
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "log"
        "os"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cloud"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        err := client.Cloud.Volumes.DeleteAndPoll(ctx, os.Getenv("VOLUME_ID"), cloud.VolumeDeleteParams{})
        if err != nil {
            log.Fatalf("delete volume: %v", err)
        }
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X DELETE \
      "https://api.gcore.com/cloud/v1/volumes/$GCORE_CLOUD_PROJECT_ID/$GCORE_CLOUD_REGION_ID/$VOLUME_ID" \
      -H "Authorization: APIKey $GCORE_API_KEY"
    ```

    <p>The response is a task ID. Poll <code>GET&nbsp;/cloud/v1/tasks/{task_id}</code> every 5 seconds until <code>state</code> is <code>FINISHED</code>. Billing for the volume stops after deletion.</p>
  </Tab>
</Tabs>

<MethodSection id="terraform" label="Terraform">

<p>Attach, resize, retype, or delete an existing volume using the [`gcore_cloud_volume`](https://registry.terraform.io/providers/G-Core/gcore/latest/docs/resources/cloud_volume) resource.</p>

## Attach to a Virtual Machine

<p>Set <code>instance_id_to_attach_to</code> to attach the volume to a [Virtual&nbsp;Machine](/cloud/virtual-instances/create-an-instance). Both the volume and the Virtual Machine must be in the same region.</p>

```hcl
resource "gcore_cloud_volume" "example" {
  project_id               = var.project_id
  region_id                = var.region_id
  name                     = "data-volume"
  source                   = "new-volume"
  size                     = 10
  type_name                = "standard"
  instance_id_to_attach_to = var.instance_id
}
```

<p>To detach, remove the <code>instance_id_to_attach_to</code> attribute and run <code>terraform apply</code>.</p>

## Resize a volume

<p>Increase <code>size</code> and run <code>terraform apply</code>. Volume size can only be increased.</p>

```hcl
resource "gcore_cloud_volume" "example" {
  project_id = var.project_id
  region_id  = var.region_id
  name       = "data-volume"
  source     = "new-volume"
  size       = 20
  type_name  = "standard"
}
```

```bash
terraform apply
```

## Change volume type

<p>Change <code>type_name</code> and run <code>terraform apply</code>.</p>

<Warning>
Changing <code>type_name</code> recreates the volume. The existing volume is deleted and a new one is created with a new ID. Detach the volume from any Virtual Machine before this change.
</Warning>

```hcl
resource "gcore_cloud_volume" "example" {
  project_id = var.project_id
  region_id  = var.region_id
  name       = "data-volume"
  source     = "new-volume"
  size       = 20
  type_name  = "ssd_hiiops"
}
```

```bash
terraform apply
```

## Delete a volume

<p>Remove the resource block. Terraform deletes the volume on the next <code>terraform apply</code>.</p>

```hcl
# Remove or comment out this block:
# resource "gcore_cloud_volume" "example" {
#   name      = "data-volume"
#   source    = "new-volume"
#   size      = 20
#   type_name = "ssd_hiiops"
#   ...
# }
```

```bash
terraform apply
```

## Import a volume

<p>Import brings a volume that was created outside Terraform under management as code.</p>

```hcl
resource "gcore_cloud_volume" "example" {
  project_id = var.project_id
  region_id  = var.region_id
  name       = "data-volume"
  source     = "new-volume"
  size       = 20
  type_name  = "standard"
}
```

```bash
terraform import gcore_cloud_volume.example '<project_id>/<region_id>/<volume_id>'
```

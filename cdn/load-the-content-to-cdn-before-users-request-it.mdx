title: CDN content prefetching
sidebarTitle: Prefetch
ai-navigation: Upload files to CDN cache from the Customer Portal by entering paths without a domain.
---

Prefetch requests files from the origin and stores them in CDN cache before visitors request them, so edge locations can serve the content without fetching it from the origin on the first request. A [CDN&nbsp;resource](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource) is required.

<Warning>
Prefetch causes CDN servers to request the listed files from the origin, which increases origin load and traffic.
</Warning>

Prefetch is recommended for files larger than 200 MB and smaller than 5 GB. Each request is limited to 100 paths, and one prefetch request is allowed per CDN resource per minute. To prefetch more than 100 files, divide the paths into batches of up to 100 and wait at least 1 minute between batches for the same CDN resource.

<Steps>
  <Step title="Open Prefetch">
    In the [Gcore&nbsp;Customer&nbsp;Portal](https://portal.gcore.com), navigate to **CDN** > **Prefetch**.
  </Step>
  <Step title="Select the CDN resource">
    Select the resource whose origin holds the files. The dropdown shows each option as CNAME and ID.
  </Step>
  <Step title="Enter file paths">
    Enter one path per line without a domain, starting with a slash: `/path/file1.jpg`.

    <Frame>
      ![Prefetch form with resource dropdown and path field](/images/docs/cdn/load-the-content-to-cdn-before-users-request-it/prefetch-hint.png)
    </Frame>
  </Step>
  <Step title="Submit the prefetch request">
    Click **Prefetch**.
  </Step>
  <Step title="Confirm the files are cached">
    Prefetch processing time depends on the number and size of the files — allow time for the operation to complete before testing.

    To verify, send a request to a listed path and inspect the `Cache` response header. The following command performs a GET request and prints only the response headers:

    ```bash
    curl -sS -D - -o /dev/null https://cdn.example.com/path/file1.jpg
    ```

    - `Cache: HIT` means the file was already cached at that edge location when tested. To attribute the hit specifically to prefetch, test a new URL or [purge](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all) the file before prefetching.
    - `Cache: MISS` on the first request followed by `Cache: HIT` on the next means the first request filled the cache. That edge was not populated by prefetch — either prefetch has not yet completed, or that location was not reached.
  </Step>
</Steps>

To replace files that are already in cache, [purge](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all) those files, then prefetch.

Prefetch requests are not retained in a history log and do not appear in [purge history](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all#purge-history), which contains only cache-purge operations.

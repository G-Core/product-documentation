HTTP 5xx codes can come from an error on an origin server or on CDN edge servers.

## Check for incidents or maintenance

If 5xx responses increase sharply or end users report widespread failures, the [Status&nbsp;Page](https://status.gcore.com) lists incidents or maintenance that affect:

  * CDN
  * Other Gcore services used as an origin (Object Storage, VPS, Dedicated Server, or Cloud)

## Check the origin server

Confirm that the origin is available.

If the origin is not responding or returns an HTTP error, contact the hosting provider or server administrator.

  * An HTTP 504 response usually means the origin did not answer within CDN [timeout&nbsp;defaults](/cdn/getting-started/cdn-timeouts) — 5 seconds to establish a connection (`proxy_connect_timeout`) and 30 seconds between successive reads while receiving the origin response (`proxy_read_timeout`). Tune the origin so it responds in time, or adjust [Custom&nbsp;connection&nbsp;timeout](/cdn/cdn-resource-options/general/customize-connection-and-read-timeouts) / **Custom read timeout** in the CDN resource settings when the plan allows.
  * If access to the origin is restricted by IP or a DDoS Protection service, allowlist CDN edge IPs. Retrieve the current public IP list:

```sh
curl -i -X GET https://api.gcore.com/cdn/public-ip-list
```

The public IP list changes over time, so keep the allowlist updated with a recurring script. The [Origin&nbsp;ACL](/cdn/getting-started/configure-an-origin/add-cdn-servers-to-the-origin-acl-whitelist) guide covers allowlisting CDN edges. Authentication on the origin can also use [Request&nbsp;headers](/cdn/cdn-resource-options/http-headers/specify-http-headers-that-cdn-adds-to-requests-to-the-origin) that CDN adds when pulling content.

## Check CDN resource settings

Incorrect CDN resource settings can also cause HTTP 5xx errors. Review the common cases below.

### Incorrect Origin pull protocol

In the resource settings, select an **Origin pull protocol** that matches the protocol the origin uses. The [Origin&nbsp;pull](/cdn/cdn-resource-options/general/specify-an-origin-and-the-origin-pull-protocol) option controls which scheme CDN uses when requesting content from the origin.

If Cloudflare or CloudFront is the origin, select **HTTP** as the Origin pull protocol. If the origin supports only HTTPS, or redirects HTTP to HTTPS, contact [Gcore&nbsp;Support](mailto:support@gcore.com) for additional settings.

### Incorrect Host header

Enable **Change Host header** and set a value that matches the origin or the host configured on the origin. The [Host&nbsp;header](/cdn/cdn-resource-options/http-headers/configure-and-check-the-host-header) option controls which virtual host the origin uses.

Open [Reports](/cdn/view-statistics-of-a-cdn-resource) → **Statistics** and select the **Response codes** report to track 5xx responses.

The [Log&nbsp;viewer](/cdn/logs/log-viewer-view-and-download-cdn-resource-logs) in the [Gcore Customer Portal](https://portal.gcore.com) shows recent request details. For long-term log export, [Logs&nbsp;uploader](/cdn/logs/logs-uploader) is a paid option that must be enabled by support. To activate it, contact the account manager or [Gcore&nbsp;Support](mailto:support@gcore.com).

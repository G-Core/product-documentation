Check the origin for errors or misconfigurations that can reduce delivery speed. Contact the hosting provider or server administrator if origin-side analysis is needed.

## Compare CDN and origin delivery speed

1. Measure delivery speed from both the CDN resource and the origin using:

   - Browser DevTools (open the Network tab and reload the page)
   - An online speed test — account for the selected location and network settings
   - `wget -S` with a static file URL

```bash
wget -S https://cdn.example.com/files/test.jpg
```

2. Compare the CDN result with the origin result.

3. If the CDN is slower than expected, review the CDN resource settings below.

## Check CDN resource settings

1. Confirm that a VPN or proxy is not in use. A VPN or proxy can route traffic through a suboptimal edge and reduce delivery speed.

2. Confirm that content is cached. Open **CDN** > **Reports** > **Statistics** and select the **Cache hit ratio** report. If the ratio is low, follow [Low&nbsp;cache&nbsp;percentage](/cdn/troubleshooting/cache-percentage-is-low-how-to-solve-the-issue).

3. For slow delivery of large files, turn on **Enable large files delivery optimization** and consider CDN or origin compression. Related guides: [Large&nbsp;file&nbsp;delivery](/cdn/cdn-resource-options/optimize-large-file-delivery) and [GZip&nbsp;and&nbsp;Brotli](/cdn/cdn-resource-options/compression/configure-gzip-and-brotli-compression).

## Diagnostic information for technical support

If delivery speed is still too low after reviewing settings, contact [Gcore&nbsp;Support](mailto:support@gcore.com) and include:

- The file URL
- The JSON output from `https://gcore.com/.well-known/cdn-debug/json` (open the URL and copy the full response)
- Results from the [Gcore&nbsp;speed&nbsp;test](https://speedtest.gcore.com/) — click **Run test**, then save the result
- `wget -S` output for the CDN resource URL
- A [HAR&nbsp;file](https://toolbox.googleapps.com/apps/har_analyzer/?lang=en) captured while loading the file or page

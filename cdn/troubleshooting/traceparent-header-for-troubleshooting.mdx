Gcore CDN supports the `traceparent` HTTP header from the [W3C specification](https://www.w3.org/TR/trace-context/). The header standardizes how tracing data is sent and updated between services, so a request can be followed from the client through the CDN to the origin. The usual reason to collect this value is a troubleshooting case with [Gcore Support](mailto:support@gcore.com).

<Info>
Gcore CDN forwards the `tracestate` request header, which is part of the same specification, without changing it.
</Info>

## Request header

The [traceparent header](https://www.w3.org/TR/trace-context/#traceparent-header) has four fields: `version`, `trace-id`, `parent-id`, and `trace-flags`. The fields are defined in [ABNF notation](https://www.w3.org/TR/trace-context/#bib-rfc5234) and identify a request in a tracing system.

When a client sends a valid `traceparent` request header, the Gcore Edge Network keeps `trace-id` and changes only `parent-id`, then forwards the header to the origin. The trace stays intact as the request moves through the CDN.

If the client omits `traceparent` or the value is invalid, the CDN generates a header that matches the specification.

## Response header

Every response that went through the Gcore network includes `traceparent`. Read the value in browser developer tools (Chrome DevTools) or with curl.

<Frame>![traceparent header in Chrome DevTools](/images/docs/cdn/troubleshooting/traceparent-header-for-troubleshooting/traceparent-devtools.png)</Frame>

<Frame>![traceparent header in a curl response](/images/docs/cdn/troubleshooting/traceparent-header-for-troubleshooting/traceparent-curl.png)</Frame>

Copy the `traceparent` response header and send it to Gcore Support when opening a troubleshooting case. Support uses that value to locate the request in Gcore systems. If the origin or application already records W3C Trace Context, match the same 16-byte `trace-id` in those logs.

## Traceparent in Raw logs

[Raw logs](/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage) include the `$http_traceparent` field. A sample value looks like this:

```
00-d5fe1dc9035165ce36952daf29686b6c-14330be33197dd1a-01
```

In this example, `d5fe1dc9035165ce36952daf29686b6c` is the 16-byte `trace-id`, and `14330be33197dd1a` is the 8-byte `parent-id`. The `trace-id` stays the same for the whole request. Match it to origin or APM traces that follow W3C Trace Context. The `parent-id` identifies the CDN span, so it will differ from the parent ID recorded by the origin.

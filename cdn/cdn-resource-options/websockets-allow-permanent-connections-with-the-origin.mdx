A WebSocket stays open so either side can send data at any time, while ordinary HTTP closes after one response. A CDN resource proxies that connection to the origin that already runs the application.

Clients open the socket on the resource hostname, and the CDN forwards the opening request to the origin. The connection stays up while data keeps moving. After a period with no data, the CDN or the network in between closes it.

## Connection path

The WebSocket server stays on the origin. Clients open `wss://` on the CDN resource hostname and keep the path the application already serves, `/socket`. The origin group points at the host and port that accept this traffic.

The client request carries an `Upgrade` header, so the CDN passes that request through and proxies each client connection as its own connection to the origin. Either side can then send data without opening a new HTTP request. Page loads and ordinary API calls stay on HTTP.

## Default setting

DNS delegation enables WebSocket, while a CNAME resource leaves the option off. The opening request on a CNAME resource cannot complete until the option is turned on. Create either resource from the [CDN&nbsp;resource&nbsp;guide](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource).

## Client hostname

Point the application client at the CDN resource hostname. Keep the path and query string the origin already expects, and leave the origin hostname in the origin group:

```text
wss://cdn.example.com/socket
```

A socket opened on the origin hostname never reaches the CDN.

## Accepted connection

When the origin accepts the `Upgrade` request, the client receives `101 Switching Protocols` and the connection stays open. Further data from the client arrives on that same origin connection as WebSocket frames.

WAAP (Web Application and API Protection) applies blocking policies to that opening request. It rejects a matching `Upgrade` request with `403 Forbidden`, so the connection is not established. A frame sent after `101 Switching Protocols` still reaches the origin.

An idle connection with no data closes after the resource [read&nbsp;timeout](/cdn/cdn-resource-options/general/customize-connection-and-read-timeouts), which defaults to 30 seconds. Send a ping frame more often than that timeout, and treat a missing pong as a closed connection.

<p>Some applications need the server to send updates immediately without waiting for the browser or application to make another request. Chat, live dashboards, notifications, and collaborative tools use WebSockets for this.</p>

<p>A WebSocket keeps one two-way connection open between the application and the server, so either side can send data at any time. Ordinary HTTP uses a request-response model.</p>

<Frame>![Side-by-side comparison of HTTP polling and a WebSocket connection](/images/docs/cdn/cdn-resource-options/websockets-allow-permanent-connections-with-the-origin/websockets-allow-permanent-connections-with-the-origin-image3.png)</Frame>

<p>With Gcore CDN, browsers and applications connect to the CDN resource hostname, and the CDN proxies that WebSocket connection to the origin that runs the WebSocket server.</p>

## Connection path

<p>The WebSocket server stays on the origin. An end-user application opens `wss://` on the CDN resource hostname and keeps the path the origin already serves, `/socket`. The origin group points at the host and port that accept this traffic.</p>

<p>The opening request carries an `Upgrade` header, so the CDN passes that request through and proxies each WebSocket connection as its own connection to the origin. Either side can then send data without opening a new HTTP request. Page loads and ordinary API calls continue as request-response exchanges.</p>

## Default setting

<p>For a resource created with DNS delegation, WebSocket proxying is on by default. A CNAME resource leaves the option off, and the opening request cannot complete until the option is turned on. Create either resource from the [CDN&nbsp;resource&nbsp;guide](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource).</p>

## End-user hostname

<p>Point the browser or application at the CDN resource hostname. Keep the path and query string the origin already expects, and leave the origin hostname in the origin group:</p>

```text
wss://cdn.example.com/socket
```

<p>A socket opened on the origin hostname never reaches the CDN.</p>

## Accepted connection

<p>When the origin accepts the `Upgrade` request, the end-user application receives `101 Switching Protocols` and the connection stays open. Further data from the application arrives on that same origin connection as WebSocket frames.</p>

<p>WAAP (Web Application and API Protection) applies blocking policies to that opening request. It rejects a matching `Upgrade` request with `403 Forbidden`, so the connection is not established. A frame sent after `101 Switching Protocols` still reaches the origin.</p>

<p>A WebSocket connection closes when no data is received from the origin within the resource [read&nbsp;timeout](/cdn/cdn-resource-options/general/customize-connection-and-read-timeouts), which defaults to 30 seconds. Send a ping frame more often than that timeout, and treat a missing pong as a closed connection.</p>

  <MethodSection id="api" label="REST API">

<p>Allow WebSocket connections from the CDN resource hostname through to an origin that already runs a WebSocket server. Applications connect with `wss://` and the path expected by the origin, and each connection is proxied as a separate connection to the origin. The origin accepts the opening request with `101 Switching Protocols`.</p>

<p>A connection closes when no data is received from the origin within the resource [read&nbsp;timeout](/cdn/cdn-resource-options/general/customize-connection-and-read-timeouts).</p>

<Info>
An [API&nbsp;token](/account-settings/api-tokens) is required.
</Info>

<p>Export these variables. `CDN_RESOURCE_ID` is the `id` from [list&nbsp;CDN&nbsp;resources](/api-reference/cdn/cdn-resources/list-cdn-resources).</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export CDN_RESOURCE_ID="{YOUR_RESOURCE_ID}"
```

## WebSockets

<p>Send `options.websockets` with `enabled` and `value`. Both fields are required. Set both to `true` to allow WebSocket connections to the origin. Set both to `false` to turn the option off. A request that omits either field returns HTTP 400. Sending `null` removes `options.websockets`.</p>

<p>The request sets both fields to `true`.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()

    resource = client.cdn.cdn_resources.update(
        12345,  # CDN resource ID
        options={"websockets": {"enabled": True, "value": True}},
    )
    print(resource.options.websockets.enabled, resource.options.websockets.value)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        resource, err := client.CDN.CDNResources.Update(ctx, 12345, cdn.CDNResourceUpdateParams{
            Options: cdn.CDNResourceUpdateParamsOptions{
                Websockets: cdn.CDNResourceUpdateParamsOptionsWebsockets{
                    Enabled: true,
                    Value:   true,
                },
            },
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(resource.Options.Websockets.Enabled, resource.Options.Websockets.Value)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X PATCH "https://api.gcore.com/cdn/resources/$CDN_RESOURCE_ID" \
      -H "Authorization: APIKey $GCORE_API_KEY" \

      -d '{
        "options": {
          "websockets": {
            "enabled": true,

          }
        }
      }'
    ```

    ```json

      "id": 12345,
      "options": {
        "websockets": {
          "enabled": true,
          "value": true
        }
      }
    }
    ```

  <MethodSection id="terraform" label="Terraform">

<p>Proxy WebSocket connections to the origin with the [Terraform&nbsp;provider](/developer-tools/terraform/overview) v2. With `websockets` enabled, an application opens `wss://` on the CDN resource hostname, and CDN servers proxy that connection to the origin. The origin accepts the opening request with `101 Switching Protocols`. A connection closes when no data is received from the origin within the resource read timeout. Run `terraform apply` after editing `options`.</p>

## WebSockets

<p>Set `websockets` `enabled` to `true` and `value` to `true`. A resource created without this block leaves WebSocket proxying unset. Set both fields to `false` to stop WebSocket proxying. The saved option then stays `enabled` `false` and `value` `false`.</p>

```hcl
resource "gcore_cdn_origin_group" "example" {
  name = "my-origin-group"

  sources = [
    {
      source  = "example.com"
      enabled = true
    }
  ]
}

resource "gcore_cdn_resource" "example" {
  cname           = "cdn.example.com"
  origin_group    = gcore_cdn_origin_group.example.id
  origin_protocol = "HTTPS"

  options = {
    websockets = {
      enabled = true
      value   = true
    }
  }
}
```

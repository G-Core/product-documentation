WebSockets is a CDN resource option that allows persistent TCP connections between clients and origin servers. When enabled, the CDN proxies WebSocket upgrade requests to the origin, maintaining the connection for the full duration of the session.

## WebSocket protocol

WebSocket is a connection protocol based on TCP. Unlike HTTP, which requires a new connection for every request, WebSocket establishes a single persistent connection that remains open until either party terminates it.

WebSocket is well-suited for applications requiring constant data exchange — chat rooms, online games, real-time trading platforms, and collaborative tools. For static or infrequently updated content — blogs and product catalogs — HTTP is more efficient because connections are short-lived and require no persistent state.

## Persistent vs. short-lived connections

HTTP and WebSocket differ in two fundamental ways.

**Connection direction:** WebSocket is bidirectional — both client and server can send data at any time without waiting for the other party to request it. HTTP is unidirectional: the server sends data only in response to a client request. A real-time chat or notification feed that uses WebSocket can push messages to all connected clients as they arrive; with HTTP, each client must repeatedly poll the server to check for updates.

**Connection lifecycle:** WebSocket establishes one connection and holds it open for the session. HTTP establishes a new connection for every request and closes it once the server responds.

## Default behavior

By default:

- WebSocket is enabled for CDN resources using DNS delegation.
- WebSocket is disabled for CNAME-based CDN resources.

Both setup types are described in the [CDN&nbsp;resource guide](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource).

## Enable or disable WebSockets

1. Navigate to **CDN** in the [Gcore Customer Portal](https://portal.gcore.com) and click the custom domain of the target resource.

<Frame>
![CDN resources list with custom domain names highlighted](/images/docs/cdn/cdn-resource-options/websockets-allow-permanent-connections-with-the-origin/websockets-allow-permanent-connections-with-the-origin-image1.png)
</Frame>

2. In the **Content** section, find **WebSockets** and enable or disable the toggle.

<Frame>
![WebSockets toggle inside the Content section of CDN resource settings](/images/docs/cdn/cdn-resource-options/websockets-allow-permanent-connections-with-the-origin/websockets-allow-permanent-connections-with-the-origin-image2.png)
</Frame>

3. Click **Save changes**.

## Keep connections alive

WebSocket connections may be closed after a period of inactivity by the CDN or by intermediate network components. To maintain long-lived connections during idle periods, implement a client-side heartbeat — have the client send a ping frame at a regular interval and confirm receipt of the server's pong response. A 30-second ping interval is sufficient to prevent most idle timeouts.

<p>Resize reduces the width and height of an original JPG or PNG before the CDN delivers it. The target dimensions are set per image using query parameters, and the reduction method — proportional scaling or cropping — is controlled by the `fit` parameter.</p>

<p>An origin server hosts an 1100×1500 px image. With `width=200, height=150`, the CDN reduces the image before delivering it to end users. The origin retains the original 1100×1500 version; users receive the 200×150 reduced version:</p>

  </Tab>

<p>To set a new height and width for an image, add the relevant query string to the image URL in the website source. These query strings are described in the [Use&nbsp;Resize](/cdn/cdn-resource-options/image-optimization-paid/image-stack-tools/reduce-image-size#use-resize) section. When a user requests a page, the CDN delivers it with the reduced images.</p>

## Enable resize

<p>Resize is included in the paid Image Stack option. This option optimizes images by converting them to WebP or AVIF format, cropping them, or adjusting their quality and size. To use Resize, activate Image Stack according to the [Enable&nbsp;Image&nbsp;Stack](/cdn/cdn-resource-options/image-optimization-paid/enable-image-stack) guide.</p>

## Use resize

<p>Add the relevant Resize query parameters to the image URLs in the website source code.</p>

<p>1. Open the website source code.</p>

<p>2. Find the strings with the URLs of the images to reduce using Resize.</p>

<p>3. Add the query strings to the URLs of the images.</p>

<p>A query parameter should be set as follows:</p>

```
image.jpg?parameter=value
```

<p>Two or more parameters should be set as follows:</p>

```
image.jpg?parameter1=value1&parameter2=value2
```

<p>where image.jpg is the URL of an image on the website.</p>

<p>The available parameters control how the image is resized:</p>

<AccordionGroup>
  <Accordion title="Width">
    <p>Width compresses an image while preserving the aspect ratio of the original image. This parameter sets the target width of the new image in pixels. The height is automatically adjusted to maintain the original aspect ratio. An origin server hosts a 900×600 image (W×H). With `width=300`: the width is reduced by three, and the height is also reduced by three. Result: 300×200. The pictures below are a separate 500×333 image.</p>

  <Accordion title="Fit">
    <p>Fit controls how the image is reduced: cropped from sides, compressed keeping the original aspect ratio, or compressed ignoring the aspect ratio. To use `fit`, specify both `width` and `height`, then add the `fit` parameter: `image.jpg?width=300&height=100&fit=…` If only `width` and `height` are specified without `fit`, the default `fit=fit` is applied. There are four possible values for `fit`:</p>
    <Tabs>
      <Tab title="Before: image.jpg">

        <AccordionGroup>
          <Accordion title="1. fit=fit">
            <p>The image is scaled proportionally and then cropped centrally to exactly fit the specified dimensions. This is the default value — `fit=fit` can be omitted. An image is 500×333 pixels. With `width=200, height=100, fit=fit`: the image is first scaled to 200×133 (factor 0.4, keeping proportions), then 33 pixels are cropped centrally from the height (17 px from the top, 16 px from the bottom). Result: 200×100. | After: `image.jpg?width=200&height=100&fit=fit` or `image.jpg?width=200&height=100`</p>

            <Frame>![fit=fit](/images/docs/cdn/cdn-resource-options/image-optimization-paid/image-stack-tools/reduce-image-size/11031151666193.png)</Frame>
            <p>200×100</p>
          </Accordion>
          <Accordion title="2. fit=bounds">
            <p>The image is compressed proportionally. Resize selects the greater of the two target dimensions and uses it to resize, ignoring the other dimension value. That dimension matches the target exactly, and the other dimension keeps the original aspect ratio. An origin server hosts a 1000×500 image. With `width=500, height=300, fit=bounds`: the width value is greater (500 pixels), so the height value is ignored. The original aspect ratio is 2:1, so the height is calculated as 500 ÷ 2 = 250. Result: 500×250. The picture below is a separate case, the 500×333 image with `width=200` and `height=100`. | After: `image.jpg?width=200&height=100&fit=bounds`</p>

            <Frame>![fit=bounds](/images/docs/cdn/cdn-resource-options/image-optimization-paid/image-stack-tools/reduce-image-size/11031151470993.png)</Frame>
            <p>200×133</p>
          </Accordion>
          <Accordion title="3. fit=cover">
            <p>The image is compressed proportionally. Resize selects the dimension that results in the larger scale factor and uses it to resize, so the image covers the specified region. The other dimension is proportionally larger and is cropped from the center. An origin server hosts a 1000×500 image. With `width=500, height=300, fit=cover`: the height scale factor (300 ÷ 500 = 0.6) is larger than the width scale factor (500 ÷ 1000 = 0.5), so the image is scaled by height to 600×300. The center crop then removes the extra width and leaves 500×300. The picture below is a separate case. | After: `image.jpg?width=200&height=100&fit=cover`</p>

            <Frame>![fit=cover](/images/docs/cdn/cdn-resource-options/image-optimization-paid/image-stack-tools/reduce-image-size/11031151470993.png)</Frame>
            <p>200×100</p>
          </Accordion>
          <Accordion title="4. fit=force">
            <p>The final image matches the specified width and height exactly. The image is compressed in both dimensions, and the original aspect ratio is ignored. | After: `image.jpg?width=200&height=50&fit=force`</p>

            <Frame>![fit=force](/images/docs/cdn/cdn-resource-options/image-optimization-paid/image-stack-tools/reduce-image-size/11031138745617.png)</Frame>
            <p>200х50</p>

<p>4. Save the changes in the website source code.</p>

<p>Images on the website are now delivered to end users with the dimensions specified in the query parameters.</p>

## Check HTTP headers

<p>The `X-Img-Operations` header reflects all conversions performed on an image. If the value includes `resize`, the image size has changed.</p>

<Frame>![Check HTTP headers](/images/docs/cdn/cdn-resource-options/image-optimization-paid/image-stack-tools/reduce-image-size/11031152077329.png)</Frame>

<p>If the HTTP header contains no `resize` value and the CDN returns the origin image, check the `Img-skip-reason` HTTP header. This header explains why the resize operation was skipped.</p>

## Turn Image Stack on

<p>Gcore CDN reads `width`, `height`, and `fit` from the image URL only when Image Stack is enabled. A `width`, `height`, or `fit` key inside `image_stack` is not stored.</p>

<p>`enabled` is required. This call sets `quality` to 80 and turns WebP on. AVIF and `png_lossless` stay off.</p>

<p>A field left out of the request is stored as its default, so send every field that should stay set. The JSON field is `image_stack`; `imageStack` is ignored.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    resource_id = int(os.environ["CDN_RESOURCE_ID"])

    updated = client.cdn.cdn_resources.update(
        resource_id,
        options={
            "image_stack": {
                "enabled": True,
                "quality": 80,
                "webp_enabled": True,
                "avif_enabled": False,
                "png_lossless": False,
            }
        },
    )
    saved = updated.options.image_stack
    print(saved.enabled, saved.quality, saved.webp_enabled, saved.avif_enabled, saved.png_lossless)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()
        resourceID, err := strconv.ParseInt(os.Getenv("CDN_RESOURCE_ID"), 10, 64)
        if err != nil {
            panic(err)
        }

        updated, err := client.CDN.CDNResources.Update(ctx, resourceID, cdn.CDNResourceUpdateParams{
            Options: cdn.CDNResourceUpdateParamsOptions{
                ImageStack: cdn.CDNResourceUpdateParamsOptionsImageStack{
                    Enabled:     true,
                    Quality:     gcore.Int(80),
                    WebpEnabled: gcore.Bool(true),
                    AvifEnabled: gcore.Bool(false),
                    PngLossless: gcore.Bool(false),
                },
            },
        })
        if err != nil {
            panic(err)
        }
        saved := updated.Options.ImageStack
        fmt.Println(saved.Enabled, saved.Quality, saved.WebpEnabled, saved.AvifEnabled, saved.PngLossless)
    }
    ```

## Resize the image URL

<p>`width`, `height`, and `fit` are not API fields. Add them to the image URL:</p>

```
image.jpg?width=300
image.jpg?height=300
image.jpg?width=200&height=100
image.jpg?width=200&height=100&fit=fit
image.jpg?width=200&height=100&fit=bounds
image.jpg?width=200&height=100&fit=cover
image.jpg?width=200&height=50&fit=force
```

<p>`width` alone sets the width in pixels and keeps the aspect ratio. `height` alone does the same for the height. With both dimensions, `fit` decides the reduction. `fit=fit` is the default: the image is scaled, then cropped at the center to the exact size. `fit=bounds` uses the greater target dimension and keeps the aspect ratio on the other. `fit=cover` covers the box and crops the center. `fit=force` uses the exact width and height and ignores the aspect ratio.</p>

## Check the delivered image

<p>The `X-Img-Operations` header lists the conversions. If the value includes `resize`, the image size changed.</p>

<p>If `X-Img-Operations` does not contain `resize` and the CDN returns the origin image, the `Img-skip-reason` header explains the skip.</p>

<p>Resize makes the picture Gcore CDN delivers smaller in width and height. The new size is `width`, `height`, and `fit` on the image URL, and Image Stack has to be on before those parameters are applied. ## Turn Image Stack on

<p>Gcore CDN reads `width`, `height`, and `fit` from the image URL only when Image Stack is enabled. Set `enabled`, `quality`, `webp_enabled`, `avif_enabled`, and `png_lossless`. A field left out of the object is stored as its default, so an omitted `quality` becomes 95 and omitted flags become false. Keep every field that should stay set, then run `terraform apply`.</p>

```hcl
resource "gcore_cdn_origin_group" "example" {
  name = "my-origin-group"

  sources = [
    {
      source  = "example.com"
      enabled = true
    }
  ]
}

resource "gcore_cdn_resource" "example" {
  cname           = "cdn.example.com"
  origin_group    = gcore_cdn_origin_group.example.id
  origin_protocol = "HTTPS"

  options = {
    image_stack = {
      enabled      = true
      quality      = 80
      webp_enabled = true
      avif_enabled = false
      png_lossless = false
    }
  }
}
```

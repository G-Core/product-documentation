<p>CORS (Cross-Origin Resource Sharing) is a browser security mechanism. When a browser makes a cross-origin request, it checks `Access-Control-Allow-Origin` to decide whether the calling page can read the response, and blocks access without a permitting header even if the server returned `200 OK` with the full content.</p>

<p>Consider a user visiting `http://site-a.com` who requests an image hosted at `http://cdn.site-b.com/image.jpg`. The browser sends a request to `http://cdn.site-b.com/`:</p>

```
GET /image.jpg HTTP/1.1
Host: cdn.site-b.com
Origin: http://site-a.com
```

<p>The `Origin` header tells the server which site sent the request. The `http://cdn.site-b.com` server uses this value to decide whether to include `Access-Control-Allow-Origin` in the response.</p>

- If the header is present and permits `http://site-a.com`, the browser allows the page to read the response and the image is displayed.
- If the header is absent or does not permit `http://site-a.com`, the browser blocks access to the response — even though the server returned a `200 OK` with the image.

<p>Gcore CDN adds the `Access-Control-Allow-Origin` header to browser responses, which controls which origins can read the response. Without the header, the browser reports _XMLHttpRequest cannot load http://domain.com_ and _No `Access-Control-Allow-Origin` header is present on the requested resource_.</p>

## Configure CORS header support

<p>Add the header in one of three places:</p>

- Resource settings apply it to all files delivered over the CDN.
- A rule applies it only to particular files.
- The origin server sends `Access-Control-Allow-Origin` on its own response.

### Configure CORS in the resource settings

<p>Resource settings add the header to every file on the CDN resource.</p>

<Steps>
  <Step title="Open the CDN resource">
    In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **CDN** > **CDN resources** and click the CDN resource to configure.

    <Frame>![CDN resources list showing active CDN resources](/images/docs/cdn/cdn-resource-options/http-headers/add-the-access-control-allow-origin-header-to-the-browser-response/add-the-access-control-allow-origin-header-to-the-browser-response-image1.png)</Frame>
  </Step>
  <Step title="Open CORS header support">
    In the resource settings panel, click **HTTP headers** to expand the section, then click **CORS header support**.

    <Frame>![CDN resource Options tab with the HTTP headers section expanded in the left panel](/images/docs/cdn/cdn-resource-options/http-headers/add-the-access-control-allow-origin-header-to-the-browser-response/add-the-access-control-allow-origin-header-to-the-browser-response-image2.png)</Frame>
  </Step>
  <Step title="Enable the toggle">
    Enable the **CORS header support** toggle.
  </Step>
  <Step title="Select an origin mode">
    Select one of three options:

<AccordionGroup>
  <Accordion title="*, for all domains">
    The CDN includes `Access-Control-Allow-Origin: *` in every response, allowing browsers from any origin to read it.

    ```
    HTTP/1.1 200 OK
    Date: Mon, 01 Dec 2020 00:23:53 GMT
    Server: Apache/2.0.61
    Access-Control-Allow-Origin: *
    Keep-Alive: timeout=2, max=100
    Connection: Keep-Alive
    Transfer-Encoding: chunked
    Content-Type: application/xml
    ```
  </Accordion>
  <Accordion title="'$http_origin' if an origin is listed below">
    Enter a permitted domain name — `site-a.com`. A resource accepts up to 20 domain names. When CDN servers receive a request, they check the value of the `Origin` header to determine which site the request came from.

    - If it matches any of the listed domains, the CDN includes `Access-Control-Allow-Origin` in the response set to the matched origin, and the browser allows the page to read the response:

      ```
      HTTP/1.1 200 OK
      Date: Mon, 01 Dec 2008 00:23:53 GMT
      Server: Apache/2.0.61
      Access-Control-Allow-Origin: https://site-a.com
      Keep-Alive: timeout=2, max=100
      Connection: Keep-Alive
      Transfer-Encoding: chunked
      Content-Type: application/xml
      ```

    - If it does not match, the `Access-Control-Allow-Origin` header is omitted from the response. The browser blocks cross-origin access.

  </Accordion>
  <Accordion title="'$http_origin', for all domains">
    Similar to the first option, but use it when the `*` value is unsuitable — when a request includes credentials. The CDN echoes the request `Origin` value in `Access-Control-Allow-Origin`, so a browser on any origin can read the response. A request from `http://site-b.com` produces this response:

    ```
    HTTP/1.1 200 OK
    Date: Mon, 01 Dec 2008 00:23:53 GMT
    Server: Apache/2.0.61
    Access-Control-Allow-Origin: https://site-b.com
    Keep-Alive: timeout=2, max=100
    Connection: Keep-Alive
    Transfer-Encoding: chunked
    Content-Type: application/xml
    ```
  </Accordion>
</AccordionGroup>
  </Step>
  <Step title="Set the status-code behavior">
    (Optional) Enable **Always add the header to response from CDN regardless of response code** to add `Access-Control-Allow-Origin` on every status code, including a response for unavailable content. With the toggle off, the header is added only on status 200, 201, 204, 206, 301, 302, 303, 304, 307, and 308.
  </Step>
  <Step title="Save the resource">
    Click **Save changes**.
  </Step>
</Steps>

### Configure CORS on the origin server

<p>Apache sets `*` on images only when the request includes `Origin`, and sets `*` on fonts, CSS, and JavaScript for every request.</p>

```
<IfModule mod_setenvif.c>
<IfModule mod_headers.c>
<FilesMatch "\.(gif|png|jpe?g|svg|svgz|ico|webp)$">
SetEnvIf Origin ":" IS_CORS
Header set Access-Control-Allow-Origin "*" env=IS_CORS
</FilesMatch>
</IfModule>
</IfModule>
<IfModule mod_headers.c>
<FilesMatch "\.(ttf|ttc|otf|eot|woff|woff2|font.css|css|js)$">
Header set Access-Control-Allow-Origin "*"
</FilesMatch>
</IfModule>
```

<p>Nginx sets `*` on fonts, CSS, and JavaScript:</p>

```
location ~ \.(ttf|ttc|otf|eot|woff|woff2|font.css|css|js)$ {
add_header Access-Control-Allow-Origin "*";
}
```

## Check CORS

<p>Clear the CDN resource or file cache in [clear&nbsp;CDN&nbsp;cache](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all), then confirm the header with cURL or browser DevTools.</p>

### Check CORS through cURL

<p>Send the file URL with an `Origin` header. That header is required for the `$http_origin` modes, because without it the CDN omits `Access-Control-Allow-Origin` even when the option is set, while the `*` mode returns the header whether or not `Origin` is present.</p>

<Steps>
  <Step title="Request the file">
    Run this command with the file URL and the site origin:

    ```sh
    curl -I -H "Origin: https://site-a.com" https://cdn.testdomain.com/assets/image.jpg
    ```
  </Step>
  <Step title="Confirm the header value">
    In the output, confirm that `Access-Control-Allow-Origin` is present and the value is `*` or the origin of the request.

    ```
    HTTP/1.1 200 OK
    Server: nginx/1.13.1
    Date: Fri, 24 Feb 2023 12:54:24 GMT
    Content-Type: image/jpeg
    Content-Length: 124024
    Connection: keep-alive
    X-Image-Generated: 29
    X-Image-Meta: 1024x768
    X-Image-Read: 71
    Expires: Fr, 10 March 2023 12:51:43 GMT
    Cache-Control: max-age=15552000
    Access-Control-Allow-Origin: *
    Last-Modified: Sun, 29 Jan 2023 12:00:00 GMT
    Cache-Control: max-age=315360000, public
    Cache: HIT
    X-Cached-Since: 2022-12-09T12:51:43+00:00
    X-ID: m9-up-e245
    ```
  </Step>
</Steps>

<p>For a page to read a file from another site, the response must include an `Access-Control-Allow-Origin` header that permits the requesting origin. The `cors` option stores those origins on the CDN resource, and Gcore CDN adds the header to the response the browser receives.</p>

## Allow every origin

<p>Set `value` to `["*"]`. The response header is `Access-Control-Allow-Origin: *`, so a browser on any site can read it.</p>

<p>`enabled` and `value` are both required, and a request that omits either field returns HTTP 400. With `always` set to `false`, the header is added only on status 200, 201, 204, 206, 301, 302, 303, 304, 307, and 308.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    resource_id = int(os.environ["CDN_RESOURCE_ID"])

    updated = client.cdn.cdn_resources.update(
        resource_id,
        options={
            "cors": {
                "enabled": True,
                "value": ["*"],
                "always": False,
            }
        },
    )
    cors = updated.options.cors
    print(cors.enabled, cors.value, cors.always)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()
        resourceID, err := strconv.ParseInt(os.Getenv("CDN_RESOURCE_ID"), 10, 64)
        if err != nil {
            panic(err)
        }

        updated, err := client.CDN.CDNResources.Update(ctx, resourceID, cdn.CDNResourceUpdateParams{
            Options: cdn.CDNResourceUpdateParamsOptions{
                Cors: cdn.CDNResourceUpdateParamsOptionsCors{
                    Enabled: true,
                    Value:   []string{"*"},
                    Always:  gcore.Bool(false),
                },
            },
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(updated.Options.Cors.Enabled, updated.Options.Cors.Value, updated.Options.Cors.Always)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X PATCH "https://api.gcore.com/cdn/resources/$CDN_RESOURCE_ID" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "options": {
          "cors": {
            "enabled": true,
            "value": ["*"],
            "always": false
          }
        }
      }'
    ```

    ```json

      "always": false
    ```

## Add CORS on a file rule

<p>A resource rule applies `cors` only where `rule` matches. `ruleType` `0` is a regular expression and must start with `^/` or `/`.</p>

<p>The call adds `Access-Control-Allow-Origin: *` for paths under `/assets/`.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    resource_id = int(os.environ["CDN_RESOURCE_ID"])

    rule = client.cdn.cdn_resources.rules.create(
        resource_id,
        name="cors-assets",
        rule="^/assets/.*",
        rule_type=0,
        options={
            "cors": {
                "enabled": True,
                "value": ["*"],
                "always": False,
            }
        },
    )
    print(rule.id, rule.rule, rule.options.cors.value, rule.options.cors.always)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go

    import (
    ```

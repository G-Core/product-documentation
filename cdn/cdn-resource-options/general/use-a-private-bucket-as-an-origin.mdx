<p>Private S3-compatible buckets — from Amazon or Gcore — can be used as a [CDN&nbsp;resource&nbsp;origin](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource#origin). CDN servers authenticate to private buckets using AWS Signature V4. The configuration requires an Access Key ID, a Secret Access Key, and provider-specific region and endpoint information. Origin groups support multiple origins with individual authentication settings per origin, and an optional Host header override per origin.</p>

## Authentication data

<p>The required authentication data is available in the S3 storage account.</p>

<Tabs>
  <Tab title="Amazon AWS">
    <p>Get the **Access Key ID** and **Secret Access Key** as described in Amazon's [Managing&nbsp;access&nbsp;keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html) guide. Use the AWS region where the bucket is located.</p>
  </Tab>
  <Tab title="Gcore">
    <p>In the [Gcore Customer Portal](https://portal.gcore.com), go to **Storage** > **Object Storages**. Hostname and location are in **Details**. The access key and secret key are created in [access keys](/storage/manage-object-storage/manage-s3-access-keys).</p>

    <Caution>
    **Caution**

    Gcore does not store the secret key after it is shown, so copy it when the key is created. For a Gcore Object Storage origin, use a read-only key on S3 Standard.
    </Caution>
  </Tab>
</Tabs>


## Configure a private bucket as an origin

<p>These steps add the private origin during CDN resource creation. To create the group first, open **CDN** > **Origin groups** and click **Add origin group**. Fill in the same S3 form, from storage type through Host header, and click **Add group**. Attach the saved group on the CDN resource as described in [Origin&nbsp;group&nbsp;attachment](/cdn/add-an-origin-group#origin-group-attachment). The last two steps below apply only during CDN resource creation.</p>

<Steps>
  <Step title="Add an origin">
    <p>Go to the [CDN resource creation page](https://portal.gcore.com/cdn/resources/create) and select the **Specify content origin** option in the **Origin** section. Click **Add origin**.</p>
  </Step>
  <Step title="Select the S3 storage type">
    <p>Select the **S3 storage** tab. Under **Choose S3 storage**, select **Amazon** or **Other**. Gcore Object Storage uses **Other**.</p>
  </Step>
  <Step title="Enter authentication data">
    <p>Specify the authentication data for the selected storage type:</p>

    - For **Amazon**: **Access Key ID**, **Secret access key**, and **AWS region**
    - For **Other**: **Hostname**, **Access Key ID**, **Secret access key**, and **Region (optional)**

    <Tip>
    **Tip**

    To determine the region of a Gcore Object Storage bucket, use the [S3 service URLs and default region names](/storage/manage-object-storage/s3-service-urls-and-default-region-names) guide.
    </Tip>
  </Step>
  <Step title="Configure bucket addressing">
    <p>Enter the **Bucket name**. CDN servers use this value only when calculating the AWS Signature V4 `Authorization` header for the private origin. The CDN does not automatically add the value from this field to the request URL sent to the origin.</p>

    <p>If the origin requires the bucket name in the request URL, check the S3 or storage provider documentation to determine whether the bucket must be included in the origin hostname or the request path.</p>

    - **Origin hostname:** Include the bucket in the hostname: `my-bucket.s3.amazonaws.com` or `my-bucket.luxembourg-2.storage.gcore.dev`. No rewrite rule is required.
    - **Path:** To keep the bucket name out of end-user URLs, such as `https://my.domain.com/content.png`, add a [Rewrite](/cdn/cdn-resource-options/rewrite-redirect-requests-from-the-cdn-to-the-origin) rule that prepends it to requests sent to the origin. The rule `/(.*) /my-bucket/$1` transforms the end-user request into an origin request for `/my-bucket/content.png`.
  </Step>
  <Step title="Configure the Host header">
    <p>Optional: enter the storage hostname in the **Host header override** field for this origin. When left empty, the Host header configured in the resource settings applies to all origins. When set, it overrides the global value for this specific origin. A per-origin value is required when multiple origins point to different buckets that each need a unique hostname.</p>

    <p>The Host header format depends on the storage provider:</p>

    - For Gcore Object Storage: `my-bucket.luxembourg-2.storage.gcore.dev`
    - For most other providers (including Amazon): `my-bucket.s3.us-east-1.amazonaws.com`

    <Info>
    Specifying the bucket in the Host header restricts CDN access to that bucket only, preventing unintended access to other data in the storage account.
    </Info>

    <p>The form looks like this when **S3 storage** and **Other** are selected:</p>

    <Frame>![S3 origin form with Other selected, showing Hostname, access keys, Region, Bucket name, and Host header override](/images/docs/cdn/cdn-resource-options/general/use-a-private-bucket-as-an-origin/s3-other-origin-form.png)</Frame>
  </Step>
  <Step title="Add other origins">
    <p>To add more origins to the group, click **+ Add origin** again and repeat the S3 storage, authentication, bucket addressing, and Host header steps. Each origin can have different credentials and a separate Host header override.</p>
  </Step>
  <Step title="Set the resource Host header">
    <p>During CDN resource creation, if the per-origin **Host header override** is not used, open **Host header** in the resource **HTTP headers** settings and enter the storage hostname for the selected provider: `my-bucket.luxembourg-2.storage.gcore.dev` for Gcore Object Storage, or `my-bucket.s3.us-east-1.amazonaws.com` for Amazon S3. Click **Save changes**.</p>

    <Frame>![Host header and Save changes](/images/docs/cdn/cdn-resource-options/general/use-a-private-bucket-as-an-origin/image-3719.png)</Frame>
  </Step>
  <Step title="Continue resource creation">
    <p>Continue the CDN resource creation according to the [Create CDN resource for static assets only](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource) guide.</p>
  </Step>
</Steps>

## Key replacement in private origins

<p>Origin credentials can be rotated without recreating the origin group. Create a replacement storage key, update the origin, confirm the CDN can read a private object with the new key, and then delete the old key.</p>

<p>1. Go to **CDN** > **Origin groups**.</p>

<p>2. Click the origin group.</p>

<p>3. Click the pencil icon next to **Access Key ID** and **Secret access key**, because saved values are masked.</p>

<p>4. Enter the new values.</p>

<p>5. Click **Save changes**.</p>

<p>6. Request an object that exists only in the private bucket through the CDN resource. A successful response shows that the new key works.</p>

<p>7. Delete the old storage key. For Gcore Object Storage, delete it in [Key&nbsp;deletion](/storage/manage-object-storage/manage-s3-access-keys#key-deletion). For Amazon, delete the previous key in [Managing&nbsp;access&nbsp;keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html).</p>

</MethodSection>

<p>Create an origin group with a private S3 source, then replace the access keys on that source without recreating the group.</p>

<Info>
An [API token](/account-settings/api-tokens) is required.
</Info>

<p>Open a terminal and export the required variable:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
```

<p>Each S3 source uses `origin_type` `s3` and a `config` object. Set `s3_type` to `other` for Gcore Object Storage, or `amazon` for AWS S3. The [origin groups](/api-reference/cdn/origins/create-origin-group) reference lists every field. A `201` response returns the origin group ID. Response bodies mask `s3_access_key_id` and `s3_secret_access_key` as `*****`.</p>

<p>CDN uses the bucket name only when calculating the AWS Signature V4 `Authorization` header. The bucket name is not added to the origin request URL. When the storage requires the bucket in the URL, include it in the hostname, or add a rewrite rule that prepends the bucket path.</p>

## Create an S3 origin

<p>Create the origin group for Gcore Object Storage or for Amazon S3. `host_header_override` sets the Host header for that source only.</p>

<Tabs>
  <Tab title="Gcore Object Storage">

<p>`s3_storage_hostname` is required for `s3_type` `other`.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `s3_type` | Yes | `other` for Gcore Object Storage |
| `s3_storage_hostname` | Yes | Storage hostname, such as `luxembourg-2.storage.gcore.dev` |
| `s3_region` | No | Storage region, such as `s-ed1` |
| `s3_bucket_name` | Yes | Bucket name used in the signature |
| `s3_access_key_id` | Yes | Access key ID for the private bucket |
| `s3_secret_access_key` | Yes | Secret access key for the private bucket |
| `host_header_override` | No | Host header for this source, such as `my-bucket.luxembourg-2.storage.gcore.dev` |

<Tabs>
  <Tab title="Python SDK">

```python
from gcore import Gcore

client = Gcore()

origin_group = client.cdn.origin_groups.create(
    name="my-origin-group",
    use_next=True,
    sources=[
        {
            "origin_type": "s3",
            "enabled": True,
            "backup": False,
            "host_header_override": "my-bucket.luxembourg-2.storage.gcore.dev",
            "config": {
                "s3_type": "other",
                "s3_storage_hostname": "luxembourg-2.storage.gcore.dev",
                "s3_region": "s-ed1",
                "s3_bucket_name": "my-bucket",
                "s3_access_key_id": "EXAMPLEACCESSKEYID001",
                "s3_secret_access_key": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
            },
        }
    ],
)
print(origin_group.id)
```

```go
package main

import (
    "context"
    "fmt"

    gcore "github.com/G-Core/gcore-go"
    "github.com/G-Core/gcore-go/cdn"
)

func main() {
    client := gcore.NewClient()
    ctx := context.Background()

    created, err := client.CDN.OriginGroups.New(ctx, cdn.OriginGroupNewParams{
        OfNoneAuth: &cdn.OriginGroupNewParamsBodyNoneAuth{
            Name:    "my-origin-group",
            UseNext: gcore.Bool(true),
            Sources: []cdn.OriginGroupNewParamsBodyNoneAuthSourceUnion{{
                OfS3Source: &cdn.OriginGroupNewParamsBodyNoneAuthSourceS3Source{
                    OriginType:         "s3",
                    Enabled:            gcore.Bool(true),
                    Backup:             gcore.Bool(false),
                    HostHeaderOverride: gcore.String("my-bucket.luxembourg-2.storage.gcore.dev"),
                    Config: cdn.OriginGroupNewParamsBodyNoneAuthSourceS3SourceConfig{
                        S3Type:            "other",
                        S3StorageHostname: gcore.String("luxembourg-2.storage.gcore.dev"),
                        S3Region:          gcore.String("s-ed1"),
                        S3BucketName:      "my-bucket",
                        S3AccessKeyID:     "EXAMPLEACCESSKEYID001",
                        S3SecretAccessKey: "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
                    },
                },
            }},
        },
    })
    if err != nil {
        panic(err)
    }
    fmt.Println(created.AsNoneAuth().ID)
}
```

## Create an origin group

<p>One S3 source creates the group. Set `s3_credentials_version` before the first apply so Terraform sends the access keys.</p>

<Tabs>
  <Tab title="Gcore Object Storage">

<p>`s3_type` is `other`. `s3_storage_hostname` is the storage address, and `host_header_override` sets the Host header for this source.</p>

```hcl
resource "gcore_cdn_origin_group" "example" {
  name                   = "my-origin-group"
  s3_credentials_version = 1

  sources = [
    {
      enabled              = true
      origin_type          = "s3"
      host_header_override = "my-bucket.s-ed1.cloud.gcore.lu"
      config = {
        s3_type              = "other"
        s3_storage_hostname  = "s-ed1.cloud.gcore.lu"
        s3_region            = "s-ed1"
        s3_bucket_name       = "my-bucket"
        s3_access_key_id     = var.s3_access_key_id
        s3_secret_access_key = var.s3_secret_access_key
      }
    }
  ]
}
```

## Rotate origin credentials

<p>Terraform sends new access keys only when `s3_credentials_version` changes. Update the key variables, increment the version, and run `terraform apply`. Keep `host_header_override` on the source so the Host header stays.</p>

```hcl
resource "gcore_cdn_origin_group" "example" {
  name                   = "my-origin-group"
  s3_credentials_version = 2

  sources = [
    {
      enabled              = true
      origin_type          = "s3"
      host_header_override = "my-bucket.s-ed1.cloud.gcore.lu"
      config = {
        s3_type              = "other"
        s3_storage_hostname  = "s-ed1.cloud.gcore.lu"
        s3_region            = "s-ed1"
        s3_bucket_name       = "my-bucket"
        s3_access_key_id     = var.s3_access_key_id
        s3_secret_access_key = var.s3_secret_access_key
      }
```

## Troubleshooting Amazon S3 (403 Forbidden for HEAD requests)

If an Amazon S3 origin serves GET requests successfully but returns `403 Forbidden` for HEAD requests, check the permissions and request configuration. The mismatch typically has one of four causes:

1. **Restricted object-level permissions:** The bucket or IAM policy permits public read access, but the object's Access Control List (ACL) denies access to the IAM user or role — AWS S3 returns 403 for HEAD in this case.

2. **Different policies in effect:** The IAM identity making the HEAD request lacks `s3:GetObjectAttributes` or equivalent metadata-read permissions, causing AWS S3 to return 403 for HEAD while GET succeeds under a broader policy.

3. **Incorrect parameters in presigned URLs:** A [presigned&nbsp;URL](/storage/manage-object-storage/configure-aws-sli-s3cmd-and-aws-javascript-sdk/generate-temporary-links-to-files-with-aws-cli-and-s3cmd) generated with mismatched parameters (access key, secret access key, bucket name, or object key) causes AWS to return 403. The parameters must be consistent for both HEAD and GET requests.

4. **Different owners for bucket and object:** When the bucket and object belong to different AWS accounts and the object owner hasn't granted the necessary permissions to the bucket owner, AWS returns 403 for HEAD and 200 for GET.

To resolve the issue, modify the bucket policy, IAM permissions, or the object's ACL as required.

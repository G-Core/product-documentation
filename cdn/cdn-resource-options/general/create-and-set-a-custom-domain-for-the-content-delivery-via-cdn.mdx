<p>A custom domain is a unique, branded domain name used for content delivery through a CDN. A website at `mywebsite.com` can configure a [CDN&nbsp;resource](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource) for static content with the custom domain `cdn.mywebsite.com`. Static assets are then delivered with URLs like `cdn.mywebsite.com/sample.jpg`.</p>

<p>Any domain or subdomain for which DNS records can be edited is valid as a custom domain. For CNAME-based resources, a third-level domain is typical, e.g. `cdn.mywebsite.com`. For CDN resources using DNS delegation to Gcore, a second-level domain is used, e.g. `mywebsite.com`.</p>

<Caution>
<p>The custom domain cannot be changed after the CDN resource has been created. To use a different domain, add it as an [additional&nbsp;domain](#specify-additional-domains-only-for-static-cdn-resources). This option is only available for CDN resources for static content, not for CDN resources integrated with entire sites.</p>
</Caution>

## Set a custom domain (for static CDN resources)

<p>The instructions below apply to CNAME-based CDN resources. For CDN resources using DNS delegation to Gcore, the custom domain is set via nameserver change at the domain registrar — CDN resource creation covers both DNS delegation and CNAME-based setup.</p>

<p>1. During CDN resource creation, enter the domain or subdomain name in the **Add domain*** section. To add multiple custom domains, click **Add CNAME**.</p>

<Warning>
<p>Multiple custom domains can only be added when creating a CDN resource for static assets. For CDN resources covering an entire site, adding additional custom domains is not supported.</p>
</Warning>

<Frame>![CDN resource creation form — Add domain section](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image2.png)</Frame>

<p>2. Click **Create**. The **Resource was created** page appears, showing the CNAME value assigned to the resource (formatted as `cl-XXXX.gcdn.co`) along with step-by-step DNS setup instructions and an example in BIND zone file format.</p>

<Frame>![Resource was created page showing the assigned CNAME value](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image3.png)</Frame>

<p>3. At the DNS provider's website, create a [CNAME&nbsp;record](https://gcore.com/learning/dns-cname-record-explained) for the custom domain pointing to the value shown on the **Resource was created** page:</p>

```
cdn.mywebsite.com. cl-XXXX.gcdn.co
```

<p>Replace `cl-XXXX.gcdn.co` with the value specific to the account.</p>

<p>If multiple custom domains were added in step 1, create CNAME records for all of them.</p>

<p>Verify the record with `dig` or the Gcore [DNS&nbsp;lookup](https://gcore.com/dev-tools/dns-lookup) tool.</p>

## Check the DNS setup status

<p>The Setup guide in resource settings verifies that the DNS configuration was completed successfully and identifies any issues.</p>

<p>1. Open the settings of the CDN resource.</p>

<p>2. Click **Setup guide**.</p>

<Frame>![CDN resource settings with Setup guide button](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image4.png)</Frame>

<p>3. A 3-step wizard opens. Navigate to **Check DNS setup status** and click the button to run the DNS check.</p>

<Frame>![Setup guide wizard showing the Set up your DNS step](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image5.png)</Frame>

<p>If the message "DNS record hasn't been set up" appears, check the DNS settings for configuration errors.</p>

<Frame>![Setup guide showing DNS record has not been set up](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image6.png)</Frame>

<p>If "DNS record has been successfully set up" appears, the configuration is complete.</p>

<p>To verify the frontend of the integrated website, right-click any static file and select **Inspect**. This shows the content delivery URL from which the file is served.</p>

## Specify additional domains (only for static CDN resources)

<p>Additional custom domains can be added to an existing CDN resource at any time through the resource settings.</p>

<p>1. In the [CDN&nbsp;resource&nbsp;list](https://portal.gcore.com/cdn/resources/list), click the CNAME value of the resource to configure.</p>

<Frame>![CDN resource list showing resources with CNAME values](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image1.png)</Frame>

<p>2. In the **Custom domain (to create a CNAME record)** section, click **+** and enter the domain name.</p>

<Frame>![Custom domain section in CDN resource settings with the add button](/images/docs/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn-image7.png)</Frame>

<p>3. Click **Save changes** at the bottom of the page.</p>

<Note>
<p>For each additional domain, create a CNAME record following the [instructions&nbsp;above](#set-a-custom-domain-for-static-cdn-resources).</p>
</Note>

<p>Once the additional domains are set up, the website can deliver different types of static files from separate domains.</p>

## Read the account CNAME target

<p>A [CDN&nbsp;account](/api-reference/cdn/cdn-service/get-cdn-service-details) request returns `cname`. Use that value as the target of the DNS CNAME record for each custom domain.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()  # Reads GCORE_API_KEY from env

    account = client.cdn.get_account_overview()
    print(account.cname)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
    )

    func main() {
        client := gcore.NewClient() // Reads GCORE_API_KEY from env
        ctx := context.Background()

        account, err := client.CDN.GetAccountOverview(ctx)
        if err != nil {
            panic(err)
        }
        fmt.Println(account.Cname)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl "https://api.gcore.com/cdn/clients/me" \
      -H "Authorization: APIKey $GCORE_API_KEY"
    ```

    <p>The API returns:</p>

    ```json
    {
      "cname": "cl-glb1d1a539.gcdn.co"
    }
    ```

## Create the resource with a custom domain

<p>Set `cname` to the custom domain and `origin` to a resolvable hostname, and include `secondaryHostnames` when the resource also serves additional domains. The [create&nbsp;endpoint](/api-reference/cdn/cdn-resources/create-cdn-resource) returns `originGroup` for the group created with the resource.</p>

<p>A later update that sends `cname` returns HTTP 400 with the message `This field is read only`, so the original domain stays in place.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `cname` | Yes | Custom domain that viewers request |
| `secondaryHostnames` | No | Additional domains set at creation |
| `origin` | Yes | Resolvable origin hostname, without a scheme or a path |
| `originProtocol` | No | Optional in the API. Set to `HTTPS` for this resource |

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()

    resource = client.cdn.cdn_resources.create(
        cname="cdn.mywebsite.com",
        origin="example.com",
        origin_protocol="HTTPS",
        secondary_hostnames=["img.mywebsite.com"],
    )
    print(resource.id, resource.cname, resource.secondary_hostnames)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        resource, err := client.CDN.CDNResources.New(ctx, cdn.CDNResourceNewParams{
            Cname:              "cdn.mywebsite.com",
            Origin:             gcore.String("example.com"),
            OriginProtocol:     cdn.CDNResourceNewParamsOriginProtocolHTTPS,
            SecondaryHostnames: []string{"img.mywebsite.com"},
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(resource.ID, resource.Cname, resource.SecondaryHostnames)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X POST "https://api.gcore.com/cdn/resources" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "cname": "cdn.mywebsite.com",
        "origin": "example.com",
        "originProtocol": "HTTPS",
        "secondaryHostnames": ["img.mywebsite.com"]
      }'
    ```

    <p>The API returns:</p>

    ```json
    {
      "id": 1001,
      "cname": "cdn.mywebsite.com",
      "secondaryHostnames": ["img.mywebsite.com"],
      "originProtocol": "HTTPS",
      "originGroup": 1002
    }
    ```
  </Tab>
</Tabs>

<p>Create a CNAME record for each custom domain and point it to the account `cname` returned above.</p>

```text
cdn.mywebsite.com. cl-glb1d1a539.gcdn.co
img.mywebsite.com. cl-glb1d1a539.gcdn.co
```

## Replace the additional domain list

<p>A [resource&nbsp;update](/api-reference/cdn/cdn-resources/change-cdn-resource) replaces `secondaryHostnames` with the list in the request, so hostnames omitted from that list are removed. The primary `cname` stays unchanged.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `secondaryHostnames` | No | Additional domains that replace the current list |

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()

    resource = client.cdn.cdn_resources.update(
        1001,
        secondary_hostnames=["static.mywebsite.com"],
    )
    print(resource.cname, resource.secondary_hostnames)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        resource, err := client.CDN.CDNResources.Update(ctx, 1001, cdn.CDNResourceUpdateParams{
            SecondaryHostnames: []string{"static.mywebsite.com"},
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(resource.Cname, resource.SecondaryHostnames)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X PATCH "https://api.gcore.com/cdn/resources/1001" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "secondaryHostnames": ["static.mywebsite.com"]
      }'
    ```

    <p>The API returns:</p>

    ```json
    {
      "id": 1001,
      "cname": "cdn.mywebsite.com",
      "secondaryHostnames": ["static.mywebsite.com"]
    }
    ```
  </Tab>
</Tabs>

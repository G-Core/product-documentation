<p>CDN reporting includes Overview for current performance and health, Statistics for standard traffic and response metrics, and optional Advanced Analytics for detailed audience and traffic breakdowns.</p>

## CDN Overview in the portal

<p>The **Overview** page is the default CDN landing page in the [Gcore&nbsp;Customer&nbsp;Portal](https://portal.gcore.com). It summarizes CDN performance and traffic across all resources or a selected resource for a specified period.</p>

<Steps>
  <Step title="Open CDN Overview">
    In the Customer Portal, navigate to **CDN** > **Overview**.
  </Step>
  <Step title="Filter dashboard data">
    Select all resources or a specific CDN resource, then select a predefined or custom period.

    <Frame>![CDN Overview with resource and period filters and traffic by geography](/images/docs/cdn/view-statistics-of-a-cdn-resource/view-statistics-of-a-cdn-resource-image1.png)</Frame>
  </Step>
</Steps>

<p>The dashboard groups the metrics into cards:</p>

| Card | Information |
|---|---|
| Health status and traffic summary | Overall health, requests, data transfer, response time, and trends compared with the previous period |
| Traffic by geography | Request distribution by country |
| Cache performance | Cached requests, cache hit rate, cached data transfer, and data transfer hit rate |
| Errors | 4xx and 5xx counts and rates |
| Security | Encrypted requests and encrypted data transfer |
| Network protocols | HTTP version and content type |

<Frame>![CDN Overview cards for cache performance, errors, security, and network protocols](/images/docs/cdn/view-statistics-of-a-cdn-resource/view-statistics-of-a-cdn-resource-image2.png)</Frame>

### Metric status rules

<p>Health status combines the 5xx response rate with the response-time baseline:</p>

* **Healthy** — the 5xx rate is below 2% and latency is below 1.25 times the baseline
* **Degraded** — the 5xx rate is between 2% and 5%, or latency is between 1.25 and 2 times the baseline
* **Unhealthy** — the 5xx rate is at least 5%, or latency is at least 2 times the baseline

<p>The status appears only when the selected period contains more than 1,000 requests and the latest 15-minute window contains more than 20 requests. Otherwise, the dashboard displays **Insufficient data**.</p>

<p>Cache hit rates above 90% appear in green, rates from 70% through 90% appear as degraded, and rates below 60% appear in red. The red threshold is a visual highlight on the dashboard and is not the troubleshooting threshold used in [low cache hit ratio](/cdn/troubleshooting/cache-percentage-is-low-how-to-solve-the-issue). Encryption rates above 90% appear in green.</p>

## Statistics reports for CDN resources

<p>The **Statistics** report provides traffic, bandwidth, response, cache, request, and timing metrics for selected CDN resources. Basic reports are available on all plans.</p>

<Note>
For complete data, view statistics at least two days after the selected period ends. Recently completed periods may contain incomplete data.
</Note>

<Steps>
  <Step title="Open Statistics">
    Navigate to **CDN** > **Reports** > **Statistics**.

    <Frame>![Statistics report with resource and Aggregated data selected](/images/docs/cdn/view-statistics-of-a-cdn-resource/view-statistics-of-a-cdn-resource-image3.png)</Frame>
  </Step>
  <Step title="Select resources and the report">
    In **CDN resource**, select one or more resources, then select a report.

    Reports other than **Aggregated data** include a time interval and an auto-refresh period. Auto-refresh reloads the selected chart on a timer while the page stays open.
  </Step>
  <Step title="Review the report">
    The chart and summary metrics adapt to the selected report.

    Charts on this page update while the selected period is still in progress, so they are useful for live monitoring. Complete data for a finished period is available at least two days later, and live charts can still differ from invoice totals because the two sources use different granularity periods.
  </Step>
</Steps>

### Available reports

<p>The report menu includes Aggregated data, Traffic, Bandwidth, Response classes, Response codes, Cache hit ratio, Requests, Traffic by region, Traffic by country, Image optimization, Request time, and Upstream response time.</p>

| Report | What it shows |
|---|---|
| Aggregated data | Traffic and bandwidth for the previous three months, with **MAX**, **MIN**, and 95th-percentile bandwidth |
| Traffic by region | Traffic from servers in each region |
| Traffic by country | Traffic from the five countries with the highest traffic |
| Image optimization | Hourly WebP conversion count |
| Request time | Time from processing the first request bytes until logging after the last response bytes are sent |
| Upstream response time | Time to receive an origin response |

## Advanced Analytics for CDN resources

<p>Advanced Analytics adds reports for requests, traffic, and unique visitors, with filters for geography, directories, browsers, devices, and operating systems. This paid option requires activation through [Support](mailto:support@gcore.com) or an account manager.</p>

<p>Until the option is activated, the page shows that Advanced Analytics is not available and an example report with random data. After activation, allow 24 hours for data collection.</p>

<Steps>
  <Step title="Open Advanced Analytics">
    Navigate to **CDN** > **Reports** > **Advanced Analytics**.

    <Frame>![Advanced Analytics example report with unavailable banner](/images/docs/cdn/view-statistics-of-a-cdn-resource/view-statistics-of-a-cdn-resource-image4.png)</Frame>
  </Step>
  <Step title="Select report criteria">
    Select a CDN resource, a metric type (**Requests**, **Traffic**, or **Unique visitors**), a reporting period, and **UTC** or local time. Local time only changes how the chart labels timestamps. The stored values remain UTC, which is also the time zone for Overview and Statistics.

    <Note>Unique visitors are counted by the combination of IP address and user agent, not as individual people.</Note>
  </Step>
  <Step title="Filter the report">
    Select **Geography**, **Directories**, **Browsers**, **Devices**, or **OS**, then select the values to include in the chart.
  </Step>
</Steps>

<p>The **Geography** filter maps traffic by country and compares selected countries in a chart.</p>

## Differences between report charts and billing

<p>Invoice totals can differ from the charts above because billing and the Customer Portal read different NGINX sources.</p>

<p>Gcore calculates billing and portal reports from different data sources:</p>

* Billing statistics use NGINX access logs because invoice calculation prioritizes accuracy over processing speed.
* Customer Portal reports use the NGINX virtual host traffic status module to provide current resource statistics.

</MethodSection>
  <MethodSection id="api" label="REST API">

<p>Read traffic and response statistics for a CDN resource, and query advanced analytics for requests, visitors, and bytes.</p>

<Info>
An [API&nbsp;token](/account-settings/api-tokens) is required. The CDN resource ID is visible under **CDN** → **CDN Resources**, or from the [resources&nbsp;list](/api-reference/cdn/cdn-resources/list-cdn-resources) call.
</Info>

<p>A [statistics&nbsp;series](/api-reference/cdn/cdn-statistics/cdn-resource-statistics) returns one value per time block. [Aggregated&nbsp;statistics](/api-reference/cdn/cdn-statistics/aggregated-statistics) return one total for the whole period. Each metric is a separate `metrics` parameter. A comma-separated list returns HTTP 204 and an empty body. `request_time` and `upstream_response_time` are separate requests; the series names those values `request_time_ms` and `upstream_response_time_ms`.</p>

<p>Open a terminal and export the required variables:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export CDN_RESOURCE_ID="{YOUR_CDN_RESOURCE_ID}"
```

## Read traffic over time

<p>Set `granularity` to `1m`, `5m`, `15m`, `1h`, or `1d`. `sent_bytes` is traffic from CDN servers to clients. `group_by=region` splits that series by edge region, and `group_by=client_country` splits it by the viewer's country code.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    resource_id = int(os.environ["CDN_RESOURCE_ID"])

    stats = client.cdn.statistics.get_resource_usage_series(
        service="CDN",
        from_="2026-09-01T00:00:00Z",
        to="2026-09-20T00:00:00Z",
        granularity="1d",
        metrics="sent_bytes",
        resource=resource_id,
    )
    print(stats.metrics)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()
        resourceID, err := strconv.ParseInt(os.Getenv("CDN_RESOURCE_ID"), 10, 64)
        if err != nil {
            panic(err)
        }

        stats, err := client.CDN.Statistics.GetResourceUsageSeries(ctx, cdn.StatisticGetResourceUsageSeriesParams{
            Service:     "CDN",
            From:        "2026-09-01T00:00:00Z",
            To:          "2026-09-20T00:00:00Z",
            Granularity: "1d",
            Metrics:     "sent_bytes",
            Resource:    gcore.Int(resourceID),
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(stats.Metrics)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -G "https://api.gcore.com/cdn/statistics/series" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      --data-urlencode "service=CDN" \
      --data-urlencode "from=2026-09-01T00:00:00Z" \
      --data-urlencode "to=2026-09-20T00:00:00Z" \
      --data-urlencode "granularity=1d" \
      --data-urlencode "metrics=sent_bytes" \
      --data-urlencode "resource=$CDN_RESOURCE_ID"
    ```

    <p>The API returns HTTP 200. Each pair is a UNIX timestamp and the bytes sent in that block:</p>

    ```json
    {
      "metrics": {
        "sent_bytes": [
          [1788220800, 16506237],
          [1788307200, 2658488]
        ]
      }
    }
    ```
  </Tab>
</Tabs>

## Read aggregated bandwidth

<p>`max_bandwidth`, `min_bandwidth`, and `95_percentile` are bytes per second for the whole period. In the REST request, repeat the `metrics` parameter to request them together. The Python and Go SDKs send one `metrics` value per call.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os

    from gcore import Gcore

    client = Gcore()
    resource_id = int(os.environ["CDN_RESOURCE_ID"])

    stats = client.cdn.statistics.get_resource_usage_aggregated(
        service="CDN",
        from_="2026-09-01T00:00:00Z",
        to="2026-09-20T00:00:00Z",
        metrics="max_bandwidth",
        resource=resource_id,
    )
    print(stats.metrics)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()
        resourceID, err := strconv.ParseInt(os.Getenv("CDN_RESOURCE_ID"), 10, 64)
        if err != nil {
            panic(err)
        }

        stats, err := client.CDN.Statistics.GetResourceUsageAggregated(ctx, cdn.StatisticGetResourceUsageAggregatedParams{
            Service:  "CDN",
            From:     "2026-09-01T00:00:00Z",
            To:       "2026-09-20T00:00:00Z",
            Metrics:  "max_bandwidth",
            Resource: gcore.Int(resourceID),
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(stats.Metrics)

    ```
  </Tab>
  <Tab title="curl">

    ```bash
      --data-urlencode "metrics=min_bandwidth" \

    ```

    <p>The API returns HTTP 200:</p>

    ```json

        "min_bandwidth": 0,
        "95_percentile": 0
      }
    }
    ```

## Read advanced analytics

<p>Advanced Analytics is a paid option. Activate it through [Support](mailto:support@gcore.com) or an account manager before querying it. After activation, allow 24 hours for data collection.</p>

<p>The query reads `requests`, `visitors`, and `bytes`. `groupBy` accepts `COUNTRY`, `DIR`, `BROWSER`, `DEVICE`, and `OS`.</p>

<Tabs>
  <Tab title="curl">
    ```bash
    curl -X POST "https://api.gcore.com/cdn/advanced/v2/query" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{\"query\":\"query (\$resourceID: Int!) { aggs(resourceID: \$resourceID) { nodes { measures { requests visitors bytes } } } }\",\"variables\":{\"resourceID\":$CDN_RESOURCE_ID}}"
    ```

    <p>The API returns HTTP 200:</p>

    ```json
    {
      "data": {
        "aggs": {
          "nodes": [
            {
              "measures": {
                "requests": 8271,
                "visitors": 615,
                "bytes": 82772202
              }
            }
          ]
        }
      }
    }
    ```
  </Tab>
</Tabs>

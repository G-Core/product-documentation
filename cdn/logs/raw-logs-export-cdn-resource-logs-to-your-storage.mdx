Raw Logs is the account-level hourly export of CDN request logs to Amazon Simple Storage Service (S3), File Transfer Protocol (FTP), or SSH File Transfer Protocol (SFTP) storage. Logs include requests to edge cache servers. Pre-cache server requests are included only when [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding) is enabled and **Add logs from origin shielding** is selected.

Raw Logs remains available for existing hourly S3, FTP, or SFTP exports. For new log-export setups, use [Logs&nbsp;Uploader](/cdn/logs/logs-uploader). Logs Uploader is the current workflow: it supports 5–60 minute delivery, selectable fields, HTTP(S) and Alibaba Cloud Simple Log Service (SLS) destinations, and per-resource policies. To move an existing Raw Logs configuration to Logs Uploader, contact [Gcore&nbsp;Support](mailto:support@gcore.com).

<Info>
This is a paid feature. Contact [Gcore&nbsp;Support](mailto:support@gcore.com) to activate Raw Logs. After activation, enable **Receive Raw Logs** in the [Gcore Customer Portal](https://portal.gcore.com) and configure export to S3, FTP, or SFTP storage.
</Info>

## Raw Logs settings

The **CDN** > **Logs** page stores the export destination, empty-file preference, and Origin Shielding inclusion. Status, the hourly interval, and traffic totals come from that configuration.

### Origin Shielding log inclusion

When Origin Shielding is enabled for the account, the **Add logs from origin shielding** checkbox appears in Raw Logs settings. Select it so the export includes requests to both edge servers and the pre-cache server.

<Frame>![Raw Logs page with the checkbox highlighted](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/add-logs-from-origin-shielding.png)</Frame>

<Tip>
If **Add logs from origin shielding** is not visible, Origin Shielding is not activated for the account. See the [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding) guide.
</Tip>

### Raw Logs statuses

The Raw Logs status in the Customer Portal can be:

- **Pending**: interval between connecting to storage and the first export
- **OK**: logs are exported from at least one CDN server
- **Failed**: a storage connection error occurred, or no export completed within 24 hours
- **Pause**: Raw Logs is paused

### Export interval

Logs are exported at the end of each hour. If Raw Logs is activated at 00:30, the first export runs between 00:45 and 01:00, and the next between 01:45 and 02:00.

If the covered CDN resources receive no requests during the export interval and **Do not send empty logs** is not selected, an empty log file (about 20 bytes) is sent to storage.

### Log traffic calculation

Raw Logs traffic totals depend on whether **Add logs from origin shielding** is selected. For CDN report metrics, see [View statistics on CDN resources](/cdn/view-statistics-of-a-cdn-resource).

<AccordionGroup>
<Accordion title="Origin Shielding disabled">
```
total_bytes = upstream_bytes + sent_bytes
```

- `upstream_bytes` is `$upstream_response_length`: response length from the origin, in bytes
- `sent_bytes` is `$bytes_sent`: bytes sent to the client from edge cache servers

Example: `$upstream_response_length` `10485760` and `$bytes_sent` `1514848` produce `12000608` bytes.
</Accordion>

<Accordion title="Origin Shielding enabled">
```
total_bytes = upstream_bytes + sent_bytes + shield_bytes
```

- `upstream_bytes` is `$upstream_response_length`: response length from the origin, in bytes
- `sent_bytes` is `$bytes_sent`: bytes sent to the client from edge cache servers
- `shield_bytes` is `$bytes_sent` on the pre-cache server: bytes sent from the shielding node
</Accordion>
</AccordionGroup>

<Info>
Log totals can differ from billing statistics when some files are missing. Common causes:

- Origin Shielding is enabled, but **Add logs from origin shielding** is not selected
- The storage imposes a rate limit, so some files are not delivered to storage
</Info>

### Log format

```
"$remote_addr" "-" "$remote_user" "[$time_local]" "$request" "$status"
"$body_bytes_sent" "$http_referer" "$http_user_agent" "$bytes_sent"
"$edgename" "$scheme" "$host" "$request_time"
"$upstream_response_time" "$request_length" "$http_range" "[$responding_node]"
"$upstream_cache_status" "$upstream_response_length" "$upstream_addr"
"$gcdn_api_client_id" "$gcdn_api_resource_id" "$uid_got" "$uid_set"
"$geoip_country_code" "$geoip_city" "$shield_type" "$server_addr" "$server_port"
"$upstream_status" "-" "$upstream_connect_time" "$upstream_header_time"
"$shard_addr" "$geoip2_data_asnumber" "$connection" "$connection_requests"
"$http_traceparent" "$http_x_forwarded_proto" "$gcdn_internal_status_code" "$ssl_cipher"
"$ssl_session_id" "$ssl_session_reused" "$sent_http_content_type" "$tcpinfo_rtt"
"$server_country_code" "$gcdn_tcpinfo_snd_cwnd" "$gcdn_tcpinfo_total_retrans" "$gcdn_rule_id"
"$request_completion" "$sent_http_content_length" "$gcdn_finalize_reason"
```

New fields can appear at the end of the line. When fields are added, Gcore sends an email notification.

### Internal status codes

`$gcdn_internal_status_code` identifies the CDN rule or feature that generated the response.

| Reason | HTTP code | Internal code | Comment |
| :----- | :-------- | :------------ | :------ |
| Country ACL | 403 | 1001 | |
| Referer ACL | 403 | 1002 | |
| IP ACL | 403 | 1003 | |
| User-Agent ACL | 403 | 1004 | |
| Secure Token | 403 | 1005 | Returned when Secure Token validation fails and `$secure_link` is empty |
| Secure Token | 410 | 1006 | Returned when the link lifetime has expired and `$secure_link` is `"0"` |
| WAF | 403 | 1007 | Request blocked by WAF |
| Bot challenge / Testcookie | 307 | 1008 | Redirection sent by bot challenge (testcookie) |
| Blocklist | 403 | 1009 | Request blocked by bot protection blocklist |
| HTTP method | 405 | 1200 | Returned when `AllowedHttpMethods` is enabled and the request method is not in the allowed list |
| Streaming disabled (`.ts` or `.m3u8` files) | 402 | 1201 | Streaming feature disabled for the client |
| LE validation /.well-known/acme-challenge/ | 404 | 1202 | Returned when `http_user_agent` is not `cert-manager-challenges`, `acme.zerossl.com`, `Cpanel-HTTP-Client`, `Buypass validation client`, `Google-Certificates-Bridge`, `vercel-fetch`, `win-acme`, `Typhoeus`, or `Go-http-client` |
| Shield requestor header | 403 | 1203 | Unauthorized request to the shield |
| Force Return | ANY | 1204 | Response generated by the Force Return status code option |

When a Secure Token link passes the authenticity check, `$secure_link` is set to the link extracted from the request URI. That successful validation does not produce a `403` or `410`.

## S3 export

<Tabs>
  <Tab title="Amazon S3">
    <Steps>
      <Step title="Open Raw Logs">
        In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **CDN** > **Logs**.
      </Step>
      <Step title="Enable the export">
        Turn on **Receive Raw Logs**. Keep **Do not send empty logs** selected to skip empty files, or clear it to receive empty files.
      </Step>
      <Step title="Include Origin Shielding logs">
        If Origin Shielding is enabled, select **Add logs from origin shielding** to include edge and pre-cache logs.
      </Step>
      <Step title="Select Amazon S3">
        Select S3 as the delivery method, then select Amazon as the storage type.

        <Frame>![Raw logs settings for Amazon S3](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/export-logs-from-amazon-1.png)</Frame>
      </Step>
      <Step title="Enter credentials">
        Enter the AWS access key ID and AWS secret access key. See the [Amazon access key guide](https://docs.aws.amazon.com/powershell/latest/userguide/pstools-appendix-sign-up.html).
      </Step>
      <Step title="Set region and buckets">
        Optionally enter the AWS region. Then choose one bucket for all CDN resources or a separate bucket per resource, and enter an existing bucket name. Add a folder name to write files inside that bucket.

        <Frame>![Raw logs settings for Amazon S3](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/export-logs-from-amazon-2.png)</Frame>
      </Step>
      <Step title="Save the configuration">
        Click **Save changes**.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Other S3-compatible storage">
    <Steps>
      <Step title="Open Raw Logs">
        In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **CDN** > **Logs**.
      </Step>
      <Step title="Enable the export">
        Turn on **Receive Raw Logs**. Keep **Do not send empty logs** selected to skip empty files, or clear it to receive empty files.
      </Step>

        If Origin Shielding is enabled, select **Add logs from origin shielding** to include edge and pre-cache logs.
      </Step>
      <Step title="Select other S3 storage">
        Select S3 as the delivery method, then select Other as the storage type.

        <Frame>![Raw logs settings for third-party S3 storage](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/export-logs-from-s3-other-1.png)</Frame>
      </Step>
      <Step title="Enter the hostname">
        Enter the storage hostname. For Gcore Object Storage, copy the hostname from **Details**.
      </Step>
      <Step title="Enter credentials">
        Enter the access key ID and secret access key. For Gcore Object Storage, create the key under [access keys](/storage/manage-object-storage/manage-s3-access-keys) and copy the secret when the key is created.
      </Step>

      </Step>
      <Step title="Enter the region">
        Optionally enter the region (location ID). For Gcore Object Storage this field is required. The location ID is the hostname prefix before the first dot. See [storage Details](/storage/request-content-directly-from-the-storage).
      </Step>
      <Step title="Set buckets">
        Choose one bucket for all CDN resources or a separate bucket per resource, and enter an existing bucket name. Add a folder name to write files inside that bucket.

        <Frame>![Raw logs settings for third-party S3 storage](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/export-logs-from-s3-other-2.png)</Frame>
      </Step>
      <Step title="Save the configuration">
        Click **Save changes**.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## FTP and SFTP export

<Tabs>
  <Tab title="SFTP">
    <Steps>
      <Step title="Open Raw Logs">
        In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **CDN** > **Logs**.
      </Step>
      <Step title="Enable the export">
        Turn on **Receive Raw Logs**. Keep **Do not send empty logs** selected to skip empty files, or clear it to receive empty files.
      </Step>
      <Step title="Include Origin Shielding logs">
        If Origin Shielding is enabled, select **Add logs from origin shielding** to include edge and pre-cache logs.
      </Step>
      <Step title="Select SFTP">
        Select SFTP as the delivery method.

        <Frame>![Raw logs settings for SFTP storage](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/export-logs-from-sftp-1.png)</Frame>
      </Step>
      <Step title="Enter the hostname and port">
        Enter `hostname:port`. For Gcore SFTP Storage, copy the hostname from [Details](/storage/request-content-directly-from-the-storage) and append port `2200`, for example `ams.origin.gcdn.co:2200`. For another provider, use that host and its SFTP port.

        <Warning>
        Omitting the port returns a wrong connection settings error.
        </Warning>
      </Step>
      <Step title="Enter credentials">
        Enter the username and password. For Gcore SFTP Storage, the username is **Storage/User name** in [Details](/storage/create-an-s3-or-sftp-storage#sftp).
      </Step>
      <Step title="Enter the destination folder">
        Enter the export folder. For Gcore SFTP Storage, use the root folder at the end of the **Upload path** in Details. The home folder is receive-only and cannot be written to directly. The only writable default folder is **htdocs**. For another provider, enter the folder that should receive files, or leave the field empty if the account starts in that folder.
      </Step>
      <Step title="Organize folders">
        Choose one folder for all CDN resources or a separate folder per resource. A missing folder name sends files to the root folder.

        <Frame>![Raw logs settings for SFTP storage](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/export-logs-from-sftp-2.png)</Frame>
      </Step>
      <Step title="Save the configuration">
        Click **Save changes**.
      </Step>
    </Steps>
  </Tab>
  <Tab title="FTP">
    <Warning>
    FTP sends credentials and log data without transport encryption. Use SFTP when logs contain IP addresses, cookies, or request URLs.
    </Warning>

    <Steps>
      <Step title="Open Raw Logs">
        In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **CDN** > **Logs**.
      </Step>

      </Step>

        <Warning>
        Omitting the port returns a wrong connection settings error.
        </Warning>
      </Step>
      <Step title="Enter credentials">
        Enter the FTP username and password.
      </Step>
      <Step title="Enter the destination folder">

      </Step>
      <Step title="Organize folders">

## Raw Logs deactivation

<Steps>
  <Step title="Turn off the export">
    In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **CDN** > **Logs** and turn off **Receive Raw Logs**.
  </Step>
  <Step title="Save the change">
    Click **Save changes**. Delivery stops only after this save. The stored S3, FTP, or SFTP settings remain and apply again when **Receive Raw Logs** is turned on and saved.

    <Frame>![Raw Logs page](/images/docs/cdn/logs/raw-logs-export-cdn-resource-logs-to-your-storage/deactivate-logs.png)</Frame>
  </Step>
</Steps>

**Discard changes** restores the last saved configuration. If **Receive Raw Logs** was on when the page was last saved, **Discard changes** turns the toggle back on and does not deactivate the export.

---
title: Use an AWS S3 static website as a CDN origin
sidebarTitle: AWS S3 static website
ai-navigation: Configure Gcore CDN to deliver public Amazon S3 static website content through an HTTP origin and a custom CDN domain.
---

Gcore CDN can cache and deliver objects from a public Amazon S3 static website endpoint. A [private&nbsp;S3&nbsp;origin](/cdn/cdn-resource-options/general/use-a-private-bucket-as-an-origin) is required when objects must not be exposed by a public-read bucket policy.

<Warning>
The public-read policy in this procedure allows anyone to retrieve matching bucket objects. Do not use it for private or sensitive content.
</Warning>

<Steps>
  <Step title="Create and populate the S3 bucket">
    1. Log in to the [AWS&nbsp;Management&nbsp;Console](https://console.aws.amazon.com/) and open **Amazon S3**.

    2. Create a general purpose bucket and select its AWS Region.

    3. Upload the objects to deliver through the CDN, including `index.html` and a `logo.png` verification object.
  </Step>

  <Step title="Allow public website access">
    Account-level Block Public Access settings must permit public bucket policies. If those settings are centrally managed, contact the AWS account administrator before changing the bucket.

    1. Open the bucket and select **Permissions**.

    2. Under **Block public access (bucket settings)**, click **Edit**.

    3. Clear **Block all public access**.

    4. Select **I acknowledge that the current settings might result in this bucket and the objects within becoming public**.

    <Frame>![Block Public Access options cleared with the public-access acknowledgment selected](/images/docs/cdn/getting-started/integrate-cdn-with-cms/integrate-cdn-resource-with-aws-s3/integrate-cdn-resource-with-aws-s3-image1.png)</Frame>

    5. Click **Save changes**, then confirm the change in the dialog.
  </Step>

  <Step title="Enable static website hosting">
    1. Open the bucket's **Properties** tab.

    2. Under **Static website hosting**, click **Edit**.

    3. Set **Static website hosting** to **Enable**.

    4. Set **Hosting type** to **Host a static website**.

    5. In **Index document**, enter `index.html` or the name of another uploaded default object.

    <Frame>
      ![Static website hosting enabled with index.html as the index document](/images/docs/cdn/getting-started/integrate-cdn-with-cms/integrate-cdn-resource-with-aws-s3/integrate-cdn-resource-with-aws-s3-image2.png)
    </Frame>

    6. Save the changes and copy the **Bucket website endpoint**.

    Use the endpoint provided by AWS instead of constructing it manually because its format depends on the Region.
  </Step>

  <Step title="Add a public-read bucket policy">
    On the **Permissions** tab, click **Edit** under **Bucket policy**. Replace `example-bucket` with the bucket name in this policy:

    ```json
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Sid": "PublicReadGetObject",
          "Effect": "Allow",
          "Principal": "*",
          "Action": "s3:GetObject",
          "Resource": "arn:aws:s3:::example-bucket/*"
        }
      ]
    }
    ```

    <Frame>
      ![Bucket policy editor with a public-read policy](/images/docs/cdn/getting-started/integrate-cdn-with-cms/integrate-cdn-resource-with-aws-s3/integrate-cdn-resource-with-aws-s3-image3.png)
    </Frame>

    Click **Save changes**.
  </Step>

  <Step title="Test the S3 website endpoint">
    Append `/logo.png` to the HTTP website endpoint copied from AWS and open the resulting URL.

    Confirm that the object loads without a `403` or `404` response. Amazon S3 website endpoints support HTTP but not HTTPS.
  </Step>

  <Step title="Create the CDN resource">
    1. Log in to the [Gcore&nbsp;Customer&nbsp;Portal](https://portal.gcore.com) and select **CDN** > **CDN resources**.

    2. Click **Create CDN resource**.

    3. In **Add domain**, enter the custom domain.

    4. In **Origin**, keep **Specify content origin** selected.

    5. Select **URL**.

    6. Select **HTTP** as the origin pull protocol.

    7. In **Origin source**, enter the S3 website endpoint without `http://` and without an object path.

    8. Click **Create**.

    The resource may initially have the **Processing** status. Wait until its status changes to **Active** before testing delivery.
  </Step>

  <Step title="Configure the custom domain">
    1. Configure the [custom&nbsp;domain](/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn) by pointing its CNAME record to the `*.gcdn.co` hostname shown in the CDN resource's **Setup guide**.

    2. For HTTPS delivery, attach an [SSL&nbsp;certificate](/cdn/ssl-certificates/add-an-ssl-certificate-to-deliver-content-over-https) to the custom domain.
  </Step>

  <Step title="Test delivery through the CDN">
    1. Open the verification object through the custom CDN domain:

       ```text
       https://cdn.example.com/logo.png
       ```

    2. Confirm that the object loads.

    3. (Optional) Configure the application to use the CDN domain, then use the browser's **Network** panel to confirm that asset requests use that domain. Creating a CDN resource does not rewrite asset URLs in HTML or application code.
  </Step>
</Steps>

[XenForo](https://xenforo.com) serves avatars, attachment thumbnails, and JavaScript from URLs set in `src/config.php`. Point those URLs at a Gcore CDN custom domain so browsers request the files from CDN instead of the origin. A [CDN&nbsp;resource](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource) must exist first, and the [custom&nbsp;domain](/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn) must have a CNAME record pointing at the assigned `cl-****.gcdn.co` hostname.

<Warning>
Back up `src/config.php` and the database before editing. Incorrect URL values can break avatars and JavaScript.
</Warning>

## CDN values before XenForo

Collect the custom domain and confirm DNS and HTTPS before editing `src/config.php`. The hostname looks like `cdn.example.com`.

<Steps>
  <Step title="Open the CDN resource">
    In the [Gcore&nbsp;Customer&nbsp;Portal](https://portal.gcore.com), navigate to **CDN** > **CDN resources** and open the resource.
  </Step>
  <Step title="Copy the custom domain">
    Note the **custom domain** shown for the resource, because that hostname is used in `externalDataUrl` and `javaScriptUrl`.
  </Step>
  <Step title="Confirm the DNS CNAME">
    Confirm that the custom domain has a CNAME record pointing to the Gcore target hostname shown in the Customer Portal (`cl-****.gcdn.co`). Do not put the `gcdn.co` hostname in the XenForo URLs.
  </Step>
  <Step title="Confirm SSL">
    Confirm the custom domain has a valid SSL certificate so assets can load over HTTPS. Attach a certificate in [SSL&nbsp;certificates](/cdn/ssl-certificates/configure-your-own-ssl-certificate).
  </Step>
</Steps>

## XenForo URL configuration

`externalDataUrl` is the public URL for the `data` directory (avatars and attachment thumbnails), and `javaScriptUrl` is the public URL for the `js` directory.

<Steps>
  <Step title="Open the configuration file">
    Open `src/config.php` in the XenForo installation.
  </Step>
  <Step title="Set the CDN URLs">
    Add or update the following keys, using the custom domain and no trailing slash after the directory name. If XenForo is installed in a subdirectory, include that path in both URLs:

    ```php
    $config['externalDataUrl'] = 'https://cdn.example.com/data';
    $config['javaScriptUrl'] = 'https://cdn.example.com/js';
    ```
  </Step>
  <Step title="Save the configuration">
    Save `src/config.php`.
  </Step>
  <Step title="Confirm CDN delivery">
    Open the site, then open browser developer tools and select the **Network** tab. Refresh. Avatar, thumbnail, and JavaScript requests should use the custom domain and return HTTP 200. After cache fills, later requests can show `Cache: HIT`.
  </Step>
</Steps>

## Optional style image URLs

Logo and related style images use a separate XenForo setting.

Log in to the XenForo admin control panel, navigate to **Appearance** > **Style properties** > **Basic options**, and set logo and related image URLs to the custom domain when those assets should also load from CDN.

---
title: Add CDN servers to the origin ACL whitelist
sidebarTitle: Add CDN servers to ACL
ai-navigation: Allow Gcore CDN edge servers to pull content from a restricted origin using request headers, public IP addresses, or public network ranges.
---

If the origin restricts which clients can pull content, add Gcore CDN edge servers to the origin ACL in one of these ways:

- HTTP request headers (recommended)
- CDN server IP addresses
- CDN server network ranges (subnets)

<Info>
The list of CDN edge IPs and networks changes as the network expands. New addresses and subnets appear in the public lists 30–60 minutes before a new server starts serving traffic. Missing an address from the origin ACL blocks content for users served by that edge. Prefer the HTTP header method, or automate ACL updates from the public list endpoints.
</Info>

## Allow via HTTP headers

Configure [Add&nbsp;request&nbsp;headers](/cdn/cdn-resource-options/http-headers/specify-http-headers-that-cdn-adds-to-requests-to-the-origin) so the CDN sends a custom header on every request to the origin, then allow only that header on the origin.

This method does not need updates when CDN edge IPs change. IP and subnet lists must be refreshed regularly.

## Allow via IP addresses

Fetch the current CDN edge IP addresses with this public API request (no authorization required):

```bash
curl -i -X GET https://api.gcore.com/cdn/public-ip-list
```

The JSON response includes `addresses` (IPv4) and `addresses_v6` (IPv6). Add those values to the origin IP ACL, and refresh the list on a schedule — the set changes over time.

## Allow via network ranges

Fetch the current CDN edge network ranges with this public API request (no authorization required):

```bash
curl -i -X GET https://api.gcore.com/cdn/public-net-list
```

The JSON response includes `addresses` (IPv4 networks) and `addresses_v6` (IPv6 networks). Add those CIDR ranges to the origin ACL, and refresh the list on a schedule.

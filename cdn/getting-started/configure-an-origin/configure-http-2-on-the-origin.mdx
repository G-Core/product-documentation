Gcore CDN edge servers support HTTP/2 and enable it by default. When a client browser supports HTTP/2 and the CDN resource uses HTTPS, the CDN can deliver content over HTTP/2.

Browsers use HTTP/2 only over HTTPS. Add an [SSL&nbsp;certificate](/cdn/ssl-certificates/add-an-ssl-certificate-to-deliver-content-over-https) to the CDN resource before relying on HTTP/2 for client delivery.

If the origin does not speak HTTP/2, the CDN can still deliver to clients over HTTP/2. Origin responses continue over the origin pull protocol configured for the resource (HTTP, HTTPS, or both). Configure HTTP/2 on the origin when the origin itself should serve multiplexed HTTPS (or cleartext `h2c`) traffic.

## Configure Nginx

**Requirements:** Nginx 1.9.5 or later with the HTTP/2 module.

1. Open the HTTPS `server` block in the Nginx configuration (often `/etc/nginx/nginx.conf` or a file under `/etc/nginx/sites-available/`).
2. Enable HTTP/2:

   **Nginx 1.25.1 and later** (current syntax):

   ```nginx
   listen 443 ssl;
   http2 on;
   ```

   **Nginx 1.9.5 through 1.25.0** (legacy syntax):

   ```nginx
   listen 443 ssl http2;
   ```

3. Test and reload Nginx:

   ```bash
   sudo nginx -t
   sudo systemctl reload nginx
   ```

## Configure Apache

**Requirements:** Apache 2.4.17 or later.

1. Enable the [`mod_http2`](https://httpd.apache.org/docs/2.4/mod/mod_http2.html) module (also known as `mod_h2`).
2. Add the matching `Protocols` line to the virtual host configuration:

   ```apache
   # HTTPS
   Protocols h2 http/1.1
   ```

   ```apache
   # HTTP (cleartext HTTP/2)
   Protocols h2c http/1.1
   ```

3. Restart Apache so the change takes effect.

## Benefits of HTTP/2 with CDN

With HTTP/2, a client can reuse a single TCP connection for many requests. That reduces connection overhead compared with opening many parallel HTTP/1.1 connections, and avoids the older pattern of splitting assets across several hostnames only to raise connection limits.

Gcore Video CDN delivers prepared HLS, MPEG-DASH, HTTP-FLV, and MP4 content globally without transcoding. After setup, viewers request streams and files through a CDN domain while the CDN retrieves content from the configured origin.

Prepared HLS and MPEG-DASH delivery requires approval from Gcore Support. HTTP-FLV and MP4 delivery do not require video delivery approval, although every format requires a paid CDN plan.

## Video CDN or Gcore Video Streaming

Select Video CDN when prepared streams already exist, or Gcore Video Streaming when transcoding and a hosted workflow are required.

### Video CDN

[Video&nbsp;CDN](/cdn/video-cdn/video-cdn-overview) delivers prepared content without transcoding and is suitable when:

- HLS, MPEG-DASH, HTTP-FLV, or MP4 content is available
- Global delivery is required
- Geo-blocking, secure token authentication, custom domains, or Origin Shielding is required
- Origin bandwidth must be reduced

It supports HLS `.m3u8` playlists with `.ts` or `.m4s` segments, MPEG-DASH `.mpd` manifests, HTTP-FLV `.flv` streams, and progressive MP4 downloads.

### Gcore Video Streaming

[Gcore&nbsp;Video&nbsp;Streaming](/streaming) adds raw RTMP or SRT transcoding, automatic adaptive-bitrate renditions, encoder input, DVR, and recording.

## Quick setup

Complete three core steps, plus format-specific activation: request approval for HLS or MPEG-DASH and enable the LIVE STREAMING preset for live delivery.

<Steps>
  <Step title="Request HLS or DASH approval">
    <Warning>
    Prepared HLS and MPEG-DASH delivery requires legal approval from Gcore Support before setup can continue.
    </Warning>

    Contact [Gcore&nbsp;Support](mailto:support@gcore.com) or use the account chat to request prepared HLS or MPEG-DASH delivery for the CDN account.

    Provide:

    - Account ID (found in the profile dropdown or [Account&nbsp;overview](/account-settings/account/overview))
    - Domain name and company name
    - Content type: sports, education, entertainment, or news
    - Sample stream URL: an example of the typical stream format
    - Viewer geography: where the audience is located
    - Broadcasting license or content compliance policy
    - Abuse or copyright contact email

    For sports, TV channels, events, or other third-party protected content, Support may request proof that the account holder or its clients have rights to distribute the content. Requests without the necessary licensing details, company identity, or abuse handling information may be declined or closed.

    Processing time is usually 1–2 business days.

    <Frame>![Account ID location in the profile dropdown](/images/docs/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming/create-a-cdn-resource-for-video-streaming-image1.png)</Frame>
  </Step>

  <Step title="Activate a paid CDN plan">
    Video streaming requires a paid CDN subscription.

    1. Navigate to **CDN** in the [Gcore&nbsp;Customer&nbsp;Portal](https://portal.gcore.com).

    2. On the free plan, upgrade to:
       - **Start** (1.5 TB included traffic)
       - **Pro** (5 TB included traffic)

    Video bandwidth delivered to viewers is billed according to the selected [CDN&nbsp;plan](/cdn/how-the-cdn-service-and-its-additional-options-are-billed).
  </Step>

  <Step title="Create a CDN resource">
    Once Support activates streaming, create the CDN resource:

    1. Navigate to **CDN** > [CDN&nbsp;resources](https://portal.gcore.com/cdn/resources/list).

    2. Click **Create CDN resource**.

    3. Enter the domain that will serve the Video CDN — for instance, `video.example.com`. Use **Add CNAME** to add more domains if needed.

    4. Under **Origin**, keep **Specify content origin** selected and configure one source:
       - URL — enter a resolvable media server domain or IP in **Origin source** — `live.example.com`
       - S3 storage — select the Gcore Storage bucket that contains the VOD files
       - FastEdge — select the FastEdge app that generates the response

    5. Click **Create**.

    For each [custom&nbsp;domain](/cdn/cdn-resource-options/general/create-and-set-a-custom-domain-for-the-content-delivery-via-cdn), create a CNAME record that points to the assigned CDN domain and issue or upload a valid SSL certificate before testing over HTTPS.

  </Step>

  <Step title="Configure caching rules">
    Optimize caching for the delivery type.

    Live HLS and MPEG-DASH use the same baseline cache settings:

    1. Navigate to **CDN Resource** > **Cache**.

    2. Enable **Always online** and add these error types:
       - error
       - timeout

    When an error or timeout occurs, Always Online can serve previously cached content while a valid stale response remains available.

    <Warning>
    Do not add "updating" to the error types list for live streaming. Add only "error" and "timeout".
    </Warning>

    3. Set **CDN cache expiry time** to 60 seconds. With DVR enabled, increase this value to match the DVR window.

    4. Navigate to **CDN Resource** > **Rules**, click **Create rule**, and select **Playlists template (.m3u8)**.

    <Frame>![Create rule dropdown with the Playlists and Video segments templates](/images/docs/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming/create-a-cdn-resource-for-video-streaming-image2.png)</Frame>

    5. Review the pre-filled **Cache time** of 2 seconds and **Browser cache** of 0 seconds, then click **Create rule**.

    For a rule that covers both HLS and MPEG-DASH manifests, select **Create blank rule** and use `^/.+\.(m3u8|mpd|ism)$` as the pattern. A 60 s segment cache and 2 s manifest cache balance segment availability with playlist freshness; with DVR enabled, the segment cache should match the DVR window.

    <Tabs>
      <Tab title="Live HLS">
        LL-HLS requires its delivery parameters in the cache key.

        1. Navigate to **CDN Resource** > **Cache**.

        2. Enable **Query parameters allowlist**.

        3. Add these parameters: `_HLS_msn`, `_HLS_part`, `_HLS_skip`.
           - These are required for LL-HLS to work correctly
           - Other parameters are excluded from the cache key but are still forwarded to the origin
      </Tab>
      <Tab title="VOD">
        VOD cache duration depends on whether content URLs are immutable or reused.

        Enable Always online first:

        1. Navigate to **CDN Resource** > **Cache**.

        2. Enable **Always online** and add these tags to the list of error types that trigger it:
           - error (serve stale cache if origin returns errors)
           - timeout (serve stale cache if origin times out)

        When an error or timeout occurs, Always Online can serve previously cached video while a valid stale response remains available.

        Set long-term cache for all content:

        1. Still in **CDN Resource** > **Cache**.

        2. For immutable or versioned URLs, set **CDN cache expiry time** to 1 year (31,536,000 seconds).
           - This caches successful responses (2xx, 3xx) for 1 year
           - For content replaced at the same URL, use a shorter TTL or purge the cache after replacement

        3. Set **Custom cache time for 404 errors** to 1 second.
           - Protects the origin from repeated requests for non-existent files

        A one-year TTL is appropriate only when content URLs are immutable or versioned. After replacing content at the same URL, [purge&nbsp;the&nbsp;cache](/cdn/purge-the-cdn-cache) to remove the older object.

        (Optional) Large file optimization for MP4 progressive download:

        1. Navigate to **CDN Resource** > **Content**.

        2. Enable **Large files delivery optimization**.
           - Enables HTTP range requests for seeking
           - The origin must support Range requests
           - Enabling this invalidates existing cache

        Requirements:

        - Origin server supports HTTP Range Request (Content-Range headers)
        - If using an origin group, files must have identical Content-Length and ETag across all origins
        - Do not enable GZIP compression when using large file optimization

        (Optional) Query string handling:

        1. Navigate to **CDN Resource** > **Cache**.

        2. Enable **Ignore query string** if VOD URLs do not use query parameters for logic, and caching `video.mp4?ref=email` and `video.mp4?ref=social` as the same file is preferred.

        3. Before removing query parameters from the cache key, confirm that they are not required for analytics or access control. Ignored parameters are still forwarded to the origin.

        Common file extensions:

        - Manifests: `.m3u8`, `.mpd`
        - Segments: `.ts`, `.m4s`, `.m4v`, `.m4a`, `.m4i`
        - Progressive: `.mp4`, `.webm`
        - Subtitles: `.vtt`, `.webvtt`, `.ttml`
      </Tab>
      <Tab title="Live MPEG-DASH CMAF">
        Low-latency MPEG-DASH with an external transcoder requires Chunked-Proxy.

        <Warning>
        When using MPEG-DASH with an external transcoder (not Gcore Video Streaming), enable the Chunked-Proxy module for low-latency delivery by contacting Gcore Support or the account manager.

        Without Chunked-Proxy, the CDN uses store-and-forward delivery, which can increase latency.
        </Warning>

        ### Chunked-Proxy module

        Standard CDNs wait for files to download fully from origin before sending them to viewers. The Chunked-Proxy module sends bytes to viewers while receiving them from the origin, using chunked transfer encoding and protocol framing.

        The [low-latency&nbsp;streaming](/streaming/live-streaming/how-low-latency-streaming-works) configuration targets 2–4 seconds. Actual end-to-end latency depends on the transcoder, segment duration, player buffering, and network conditions.

        ### Chunked-Proxy activation

        Request activation from Support:

        1. Contact Gcore Support or the account manager.

        2. Request Chunked-Proxy module activation for the CDN resource.

        3. Provide:
           - The CDN resource ID or domain
           - Confirmation of using LL-DASH with CMAF segments
           - Origin transcoder details (Wowza or Nginx-RTMP)

        After activation, the CDN can stream chunks as they arrive from the origin instead of waiting for complete segments.

        <Info>
        When using Gcore Video Streaming (the Gcore transcoding service), Chunked-Proxy is already enabled by default. Activation is only needed for an external transcoder.
        </Info>

        ### DASH cache settings

        Apply the shared live cache settings above. For a DASH-only manifest rule, use `^/.+\.mpd$` as the pattern.

        Common DASH/CMAF file extensions:

        - Manifests: `.mpd`
        - Segments: `.m4s`, `.m4v`, `.m4a`, `.cmfv`, `.cmfa`
        - Initialization: `.mp4` (init segments)
      </Tab>
      <Tab title="FLV">
        [FLV&nbsp;streaming](/cdn/video-cdn/flv-streaming) uses a single continuous connection, so its cache settings require Support configuration.
      </Tab>
    </Tabs>

    <Info>
    For high-traffic streaming or specific performance requirements, contact Gcore Support to configure cache sharding across multiple servers, cache lock timing for concurrent requests, custom TTL strategies per file type, and origin connection limits that protect the origin from traffic spikes.
    </Info>
  </Step>

  <Step title="Enable the LIVE STREAMING preset">
    <Info>
    For live streams only — skip this step when delivering VOD.
    </Info>

    The LIVE STREAMING preset enables RAM-based caching for reduced latency.

    1. Navigate to CDN resources.

    2. Click the **three dots** next to the Video CDN resource.

    3. Select **Turn on LIVE STREAMING preset**.

    <Frame>![Turn on LIVE STREAMING preset](/images/docs/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming/create-a-cdn-resource-for-video-streaming-image3.png)</Frame>

    It caches video segments in RAM instead of disk for faster delivery and lower latency.
  </Step>
</Steps>

## Test video delivery

Confirm that the HTTPS CDN URL plays correctly before going to production.

### CDN URL

Replace the origin hostname with the CDN hostname.

Before (origin):

```text
https://live.example.com/playlist.m3u8
```

After (CDN):

```text
https://video.example.com/playlist.m3u8
```

Or with an auto-generated domain:

```text
https://123456.gcdn.co/playlist.m3u8
```

### Test playback

Select a playback check that matches the delivery format:

- HLS — enter the CDN URL in the [HLS.js&nbsp;demo](https://hls-js.netlify.app/demo/) or a native HLS player, then verify that the playlist and segments load
- MPEG-DASH — [VLC&nbsp;Media&nbsp;Player](https://videolan.org) and other MPEG-DASH players can open the `.mpd` URL; verify continuous playback
- HTTP-FLV — open the `.flv` URL in an HTTP-FLV player and verify that the continuous response plays
- MP4 — open the CDN URL in a browser or desktop player, then verify playback and seeking

## Advanced configuration

After the resource is live, Origin Shielding, geo-restrictions, and secure tokens can further protect the origin and control who can watch.

### Origin Shielding

Origin Shielding routes cache misses through a designated shield location before requests reach the origin, consolidating requests and reducing direct origin traffic.

<Steps>
  <Step title="Open Origin Shielding settings">
    Navigate to **CDN Resource** > **General** > **Origin shielding**.
  </Step>
  <Step title="Enable and select a location">
    Toggle **Enable origin shielding**, then select the shield location closest to the origin.
  </Step>
</Steps>

The [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding) settings support location selection and failover, so select a shield location close to the origin.

### Geo-restrictions

[Geo-restrictions](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#country-access-policy) combine country access with referrer, IP, and user-agent rules.

<Steps>
  <Step title="Open the country access policy">
    Navigate to **CDN Resource** > **Security** > **Country access policy**.
  </Step>
  <Step title="Select allow or block">
    Select **Allow only** to make content available only in selected countries, or **Block** to block content in selected countries.
  </Step>
  <Step title="Apply the countries">
    Select countries, then save changes.
  </Step>
</Steps>

Example: "Allow only in Dominican Republic" for regional sports rights.

### Secure tokens

[Secure&nbsp;Tokens](/cdn/cdn-resource-options/security/use-a-secure-token/about-secure-token) protect paid content, private videos, and time-limited previews with authenticated URLs.

<Steps>
  <Step title="Open Secure Token settings">
    Navigate to **CDN Resource** > **Security** > **Secure Token**.
  </Step>
  <Step title="Configure and generate tokens">
    Enable and configure token settings, then generate tokens on the backend for each user.
  </Step>
</Steps>

## Troubleshooting

Use checks that match the delivery format and determine whether failure occurs at the origin, CDN, DNS, or player. Contact Gcore Support or use the account chat if the issue remains.

### Playback failures

Check the origin, domain, media files, and CDN response in order.

1. Open the origin URL directly and confirm that it returns the expected content.

2. For a custom domain, confirm that its CNAME points to the CDN domain and that the SSL certificate is valid.

3. Check the format-specific response:
   - HLS — verify the `.m3u8` playlist and referenced `.ts` or `.m4s` segments
   - MPEG-DASH — verify the `.mpd` manifest and referenced `.m4s` segments
   - HTTP-FLV — verify that the `.flv` endpoint maintains a continuous HTTP response
   - MP4 — verify a successful response and HTTP Range support for seeking

4. Check 4xx and 5xx responses in [CDN&nbsp;statistics](/cdn/view-statistics-of-a-cdn-resource).

### High live-stream latency

For HLS or MPEG-DASH latency, review the live-delivery settings before requesting workload-specific tuning.

1. Confirm that the **LIVE STREAMING preset** is enabled.

2. Check that manifest cache time is appropriate for the stream.

3. For low-latency MPEG-DASH with an external transcoder, confirm that Chunked-Proxy is active.

4. Contact Gcore Support for workload-specific tuning.

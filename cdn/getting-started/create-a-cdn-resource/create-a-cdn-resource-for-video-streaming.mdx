<p>Gcore Video CDN delivers prepared HTTP Live Streaming (HLS), Dynamic Adaptive Streaming over HTTP (MPEG-DASH), HTTP Flash Video (HTTP-FLV), and MP4 content globally without transcoding. After setup, viewers request streams and files through a CDN domain while the CDN retrieves content from the configured origin.</p>

<p>Activation requirements differ by delivery format:</p>

- HLS and MPEG-DASH — require video-delivery approval from Gcore Support and a paid CDN plan.
- HTTP-FLV Live — requires a sales agreement and a dedicated service profile. Contact your account manager or [sales@gcore.com](mailto:sales@gcore.com).
- HTTP-FLV video on demand (VOD) and MP4 VOD — self-service; only a paid CDN plan is required.

## Video CDN or Gcore Video Streaming

<p>Select Video CDN when prepared streams already exist, or Gcore Video Streaming when transcoding and a hosted workflow are required.</p>

### Video CDN

<p>[Video&nbsp;CDN](/cdn/video-cdn/video-cdn-overview) delivers prepared content without transcoding and is suitable when:</p>

- HLS, MPEG-DASH, HTTP-FLV, or MP4 content is available
- Global delivery is required
- Geo-blocking, secure token authentication, custom domains, or Origin Shielding is required
- Origin bandwidth must be reduced

<p>It supports HLS `.m3u8` playlists with `.ts` or `.m4s` segments, MPEG-DASH `.mpd` manifests, HTTP-FLV `.flv` streams, and progressive MP4 downloads.</p>

### Gcore Video Streaming

<p>[Gcore&nbsp;Video&nbsp;Streaming](/streaming) accepts Real-Time Messaging Protocol (RTMP) or Secure Reliable Transport (SRT) input and transcodes it into adaptive-bitrate renditions. It also provides encoder integration, digital video recorder (DVR), and recording.</p>

## Quick setup

<p>Follow the steps below. The approval step applies to HLS, MPEG-DASH, and HTTP-FLV Live; HTTP-FLV VOD and MP4 VOD can proceed directly to resource creation. The LIVE STREAMING preset step applies to live delivery only.</p>

HTTP-FLV VOD and MP4 VOD are self-service and do not require this step.</p>

        <p>9. Navigate to **CDN Resource** > **Cache**.</p>

        <p>11. Add these parameters: `_HLS_msn`, `_HLS_part`, `_HLS_skip`.</p>
            - These are required for LL-HLS to work correctly
            - Other parameters are excluded from the cache key but are still forwarded to the origin

        <p>12. Click **Save changes**.</p>
      </Tab>
      <Tab title="MPEG-DASH live">
        <p>Configure the baseline cache settings:</p>

        <p>1. Navigate to **CDN Resource** > **Cache**.</p>

           - error
           - timeout

        <p>When an error or timeout occurs, Always Online serves previously cached content while a valid stale response is available.</p>

        <Warning>
        <p>Do not add `updating` to the error types list for live streaming. Add only `error` and `timeout`.</p>
        </Warning>

        <p>3. In the **CDN caching** dropdown, select **CDN controlled**.</p>

        <p>4. Set **Cache expiry** to 60 seconds. With DVR enabled, increase this value to match the DVR window.</p>

        <p>5. Click **Save changes**.</p>

        <p>Next, create a manifest caching rule:</p>

        <p>6. Navigate to **CDN Resource** > **Rules** and click **Create rule**.</p>

        <p>7. Select **Create blank rule** and use `^/.+\.mpd$` as the pattern.</p>

        <p>8. Set **Cache time** to 2 seconds and **Browser cache** to 0 seconds, then click **Create rule**.</p>

        <p>For Low-Latency DASH (LL-DASH) with Common Media Application Format (CMAF) segments, low-latency delivery with an external transcoder requires the Chunked-Proxy module.</p>

        <Warning>
        <p>When using MPEG-DASH with an external transcoder (not Gcore Video Streaming), enable the Chunked-Proxy module for low-latency delivery by contacting Gcore Support or the account manager.</p>

        <p>Without Chunked-Proxy, the CDN uses store-and-forward delivery, which can increase latency.</p>
        </Warning>

        <p>Standard CDNs wait for files to download fully from origin before sending them to viewers. The Chunked-Proxy module sends bytes to viewers while receiving them from the origin, using chunked transfer encoding and protocol framing.</p>

        <p>The [low-latency&nbsp;streaming](/streaming/live-streaming/how-low-latency-streaming-works) configuration targets 2–4 seconds. Actual end-to-end latency depends on the transcoder, segment duration, player buffering, and network conditions.</p>

        <p>To activate Chunked-Proxy, contact Gcore Support or the account manager and provide:</p>

        <p>1. The CDN resource ID or domain</p>
        <p>2. Confirmation of using LL-DASH with CMAF segments</p>
        <p>3. Origin transcoder details (for example, Wowza or NGINX RTMP)</p>

        <p>After activation, the CDN streams chunks as they arrive from the origin instead of waiting for complete segments.</p>

        <Info>
        <p>When using Gcore Video Streaming (the Gcore transcoding service), Chunked-Proxy is already enabled by default. Activation is only needed for an external transcoder.</p>
        </Info>

        <p>Common DASH/CMAF file extensions:</p>

        - Manifests: `.mpd`
        - Segments: `.m4s`, `.m4v`, `.m4a`, `.cmfv`, `.cmfa`
        - Initialization: `.mp4` (init segments)
      </Tab>

        <p>Enable Always online first:</p>

        <p>5. Set **Cache expiry** to 1 year (31,536,000 seconds) for immutable or versioned URLs.</p>
           - In CDN-controlled mode, responses with status codes 200, 206, 301, and 302 are cached by default; responses with other codes are not cached unless configured separately
           - In origin-controlled mode, caching is governed by the `Cache-Control` header the origin sends
           - For content replaced at the same URL, use a shorter TTL or [purge&nbsp;the&nbsp;cache](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all) after replacement

        <p>6. Click **Save changes**.</p>

        <p>7. To limit caching of 404 responses, add an advanced caching rule: in **CDN caching** settings, click **Add rule**, set **Response code** to `404`, and set **Caching time** to 1 second. Click **Save changes**. This protects the origin from repeated requests for non-existent files.</p>

        <p>A 1-year TTL is appropriate only when content URLs are immutable or versioned. After replacing content at the same URL, [purge&nbsp;the&nbsp;cache](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all) to remove the older object.</p>

        <p>Optionally, configure query string handling:</p>

        <p>8. Navigate to **CDN Resource** > **Cache**.</p>

        <p>9. Enable **Ignore query string** if VOD URLs do not use query parameters for logic, and caching `video.mp4?ref=email` and `video.mp4?ref=social` as the same file is preferred.</p>

        <p>10. Before removing query parameters from the cache key, confirm that they are not required for analytics or access control. Ignored parameters are still forwarded to the origin.</p>

        <p>11. Click **Save changes**.</p>

        <p>Common file extensions:</p>

        - Manifests: `.m3u8`, `.mpd`
        - Segments: `.ts`, `.m4s`, `.m4v`, `.m4a`, `.m4i`
        - Subtitles: `.vtt`, `.webvtt`, `.ttml`
      </Tab>

      </Tab>

        <p>4. Still in **CDN Resource** > **Cache**, select **CDN controlled** from the **CDN caching** dropdown.</p>

        <p>5. Set **Cache expiry** to 1 year (31,536,000 seconds) for immutable or versioned URLs.</p>
           - In CDN-controlled mode, responses with status codes 200, 206, 301, and 302 are cached; other codes require additional configuration
           - For content replaced at the same URL, use a shorter TTL or [purge&nbsp;the&nbsp;cache](/cdn/clear-cdn-resource-cache-by-url-pattern-or-all) after replacement

        <p>6. Click **Save changes**.</p>

        <p>7. To limit caching of 404 responses, add an advanced caching rule: in **CDN caching** settings, click **Add rule**, set **Response code** to `404`, and set **Caching time** to 1 second. Click **Save changes**.</p>

        <p>Optionally, enable large file optimization for MP4 progressive download:</p>

           - Retrieves content from the origin in 10 MB chunks using HTTP range requests and caches each chunk independently — intended for large single-file MP4 content
           - Generally unnecessary for segmented HLS or MPEG-DASH, which already divide media into small independently cached chunks

        <p>10. Click **Save changes**.</p>

        <p>Optionally, configure query string handling:</p>

        <p>14. Click **Save changes**.</p>

        <p>Common file extensions:</p>

        - Progressive: `.mp4`, `.webm`, `.flv`
        - Subtitles: `.vtt`, `.webvtt`, `.ttml`
      </Tab>
    </Tabs>

## Video delivery testing

<p>Confirm that the HTTPS CDN URL plays correctly before going to production.</p>

### CDN URL

<p>Replace the origin hostname with the CDN hostname.</p>

<p>Before (origin):</p>

```text
https://live.example.com/playlist.m3u8
```

<p>After (CDN):</p>

```text
https://video.example.com/playlist.m3u8
```

<p>Or with an auto-generated domain:</p>

```text
https://123456.gcdn.co/playlist.m3u8
```

### Playback test

<p>Select a playback check that matches the delivery format. Playback alone can succeed while assets are still loaded from the origin — always verify that segment requests use the CDN hostname and return `HIT` in the `Cache` response header.</p>

- HLS — enter the CDN URL in the [HLS.js&nbsp;demo](https://hls-js.netlify.app/demo/) or a native HLS player. Confirm the playlist loads and that segment URLs use relative paths or the CDN hostname, not the origin. Request the same segment URL twice and confirm the second response returns `HIT` in the `Cache` response header.
- MPEG-DASH — open the `.mpd` URL in [VLC&nbsp;Media&nbsp;Player](https://videolan.org) or another MPEG-DASH player. Verify continuous playback and that segment URLs reference the CDN hostname. Request a segment URL twice and confirm `HIT` in the `Cache` response header.
- HTTP-FLV — open the `.flv` URL in an HTTP-FLV player and verify that the continuous response plays.
- MP4 — open the CDN URL in a browser or player, verify playback and seeking, and confirm that a repeated request returns `HIT` in the `Cache` response header.

## Advanced configuration

<p>After the resource is live, Origin Shielding, geo-restrictions, and secure tokens can further protect the origin and control who can watch.</p>

### Origin Shielding

<p>Origin Shielding routes cache misses through a designated shield location before requests reach the origin, consolidating requests and reducing direct origin traffic.</p>

<Steps>
  <Step title="Open Origin Shielding settings">
    <p>Navigate to **CDN Resource** > **General** > **Origin shielding**.</p>
  </Step>
  <Step title="Enable and select a location">
    <p>Toggle **Enable origin shielding**, then select the shield location closest to the origin. Click **Save changes**.</p>
  </Step>
</Steps>

<p>The [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding) settings support location selection and failover, so select a shield location close to the origin.</p>

### Geo-restrictions

<p>[Geo-restrictions](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#country-access-policy) combine country access with referrer, IP, and user-agent rules.</p>

<Steps>
  <Step title="Open the country access policy">
    <p>Navigate to **CDN Resource** > **Security** > **Country access policy**.</p>
  </Step>
  <Step title="Select allow or block">
    <p>Select **Allow only** to make content available only in selected countries, or **Block** to block content in selected countries.</p>
  </Step>
  <Step title="Apply the countries">
    <p>Select countries, then click **Save changes**.</p>
  </Step>
</Steps>

<p>Example: "Allow only in Dominican Republic" for regional sports rights.</p>

### Secure tokens

<p>[Secure&nbsp;Tokens](/cdn/cdn-resource-options/security/use-a-secure-token/about-secure-token) protect paid content, private videos, and time-limited previews with authenticated URLs.</p>

<Steps>
  <Step title="Open Secure Token settings">
    <p>Navigate to **CDN Resource** > **Security** > **Secure Token**.</p>
  </Step>
  <Step title="Configure and generate tokens">
    <p>Enable and configure token settings, then click **Save changes**. Generate tokens on the backend for each user.</p>
  </Step>
</Steps>

## Create the CDN resource

<p>Set `origin` to a resolvable media hostname and `originProtocol` to `HTTPS`. An unresolved hostname returns HTTP 400 with the message `The domain name cannot be resolved. Please specify a valid domain name.` The [create&nbsp;endpoint](/api-reference/cdn/cdn-resources/create-cdn-resource) stores the hostname as the source of a new origin group.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `cname` | Yes | Domain that viewers request |
| `origin` | Yes | Resolvable origin hostname, without a scheme or a path |
| `originProtocol` | No | Optional in the API. Set to `HTTPS` for this resource; otherwise it defaults to `HTTP` |

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()  # Reads GCORE_API_KEY from env

    resource = client.cdn.cdn_resources.create(
        cname="video.site.com",
        origin="example.com",
        origin_protocol="HTTPS",
    )
    print(resource.id, resource.origin_protocol)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient() // Reads GCORE_API_KEY from env
        ctx := context.Background()

        resource, err := client.CDN.CDNResources.New(ctx, cdn.CDNResourceNewParams{
            Cname:          "video.site.com",
            Origin:         gcore.String("example.com"),
            OriginProtocol: cdn.CDNResourceNewParamsOriginProtocolHTTPS,
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(resource.ID, resource.OriginProtocol)
    }
    ```
  </Tab>

## Select calls for the delivery type

<p>The create call is the same for every format. Continue with the calls that match the content:</p>

- HLS live: set the HLS live cache, cache `.m3u8` playlists, and apply the LIVE STREAMING preset.
- MPEG-DASH live: set Always online and the 60-second CDN cache from the next section, then apply the LIVE STREAMING preset. The `.m3u8` rule and the LL-HLS query parameters apply to HLS.
- HLS VOD, MPEG-DASH VOD, HTTP-FLV VOD, and MP4: leave the live cache, the playlist rule, and the LIVE STREAMING preset unset, because no further updates are required after resource creation.
- HTTP-FLV Live: Support configures the cache during service activation.

## Set the HLS live cache

<p>A [resource&nbsp;update](/api-reference/cdn/cdn-resources/change-cdn-resource) sets Always online for `error` and `timeout` and a 60-second CDN cache. HLS live and MPEG-DASH live use these two fields. Sending one of these options does not remove the other.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `options.stale.value` | No | `error` and `timeout` when Always online is enabled |
| `options.edge_cache_settings.value` | No | `60s` for CDN-controlled caching |

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()

    resource = client.cdn.cdn_resources.update(
        1001,
        options={
            "stale": {"enabled": True, "value": ["error", "timeout"]},
            "edge_cache_settings": {"enabled": True, "value": "60s"},
        },
    )
    print(resource.options.stale.value, resource.options.edge_cache_settings.value)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        resource, err := client.CDN.CDNResources.Update(ctx, 1001, cdn.CDNResourceUpdateParams{
            Options: cdn.CDNResourceUpdateParamsOptions{
                Stale: cdn.CDNResourceUpdateParamsOptionsStale{
                    Enabled: true,
                    Value:   []string{"error", "timeout"},
                },
                EdgeCacheSettings: cdn.CDNResourceUpdateParamsOptionsEdgeCacheSettings{
                    Enabled: true,
                    Value:   gcore.String("60s"),
                },
            },
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(resource.Options.Stale.Value, resource.Options.EdgeCacheSettings.Value)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X PATCH "https://api.gcore.com/cdn/resources/1001" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "options": {
          "stale": {"enabled": true, "value": ["error", "timeout"]},
          "edge_cache_settings": {"enabled": true, "value": "60s"}
        }
      }'
    ```

    <p>The API returns:</p>

    ```json
    {
      "id": 1001,
      "options": {
        "stale": {"enabled": true, "value": ["error", "timeout"]},
        "edge_cache_settings": {"enabled": true, "value": "60s"}
      }
    }
    ```
  </Tab>
</Tabs>

<p>For Low-Latency HLS, add `options.query_params_whitelist` with `enabled` set to true and the values `_HLS_msn`, `_HLS_part`, and `_HLS_skip`. The baseline update above does not include that field.</p>

## Cache HLS playlists

<p>For HLS live, a rule with `ruleType` 0 matches playlist paths and caches them for 2 seconds. Browser cache is `0s`.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `rule` | Yes | `^/.+\.m3u8$` |
| `ruleType` | Yes | `0` for a regular expression |
| `options.edge_cache_settings.value` | No | `2s` on the playlist rule |
| `options.browser_cache_settings.value` | No | `0s` on the playlist rule |

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()

    rule = client.cdn.cdn_resources.rules.create(
        1001,
        name="HLS playlists",
        rule="^/.+\\.m3u8$",
        rule_type=0,
        options={
            "edge_cache_settings": {"enabled": True, "value": "2s"},
            "browser_cache_settings": {"enabled": True, "value": "0s"},
        },
    )
    print(rule.id, rule.options.edge_cache_settings.value)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        rule, err := client.CDN.CDNResources.Rules.New(ctx, 1001, cdn.CDNResourceRuleNewParams{
            Name:     "HLS playlists",
            Rule:     "^/.+\\.m3u8$",
            RuleType: 0,
            Options: cdn.CDNResourceRuleNewParamsOptions{
                EdgeCacheSettings: cdn.CDNResourceRuleNewParamsOptionsEdgeCacheSettings{
                    Enabled: true,
                    Value:   gcore.String("2s"),
                },
                BrowserCacheSettings: cdn.CDNResourceRuleNewParamsOptionsBrowserCacheSettings{
                    Enabled: true,
                    Value:   "0s",
                },
            },
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(rule.ID, rule.Options.EdgeCacheSettings.Value)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X POST "https://api.gcore.com/cdn/resources/1001/rules" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "HLS playlists",
        "rule": "^/.+\\.m3u8$",
        "ruleType": 0,
        "options": {
          "edge_cache_settings": {"enabled": true, "value": "2s"},
          "browser_cache_settings": {"enabled": true, "value": "0s"}
        }
      }'
    ```

      "options": {
        "edge_cache_settings": {"enabled": true, "value": "2s"},
        "browser_cache_settings": {"enabled": true, "value": "0s"}
      }

## Enable the LIVE STREAMING preset

<p>List presets, select the one named `LIVE STREAMING`, and apply that id to the resource. After the apply call, `preset_applied` is `true`. The list returned id `52` for that name. Use this call for live delivery. VOD leaves the preset unset.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    from gcore import Gcore

    client = Gcore()

    presets = client.cdn.presets.list()
    preset_id = next(item.id for item in presets if item.name == "LIVE STREAMING")
    applied = client.cdn.presets.applied.apply(preset_id, object_id=1001)
    print(applied.preset_id, applied.object_id)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/cdn"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        page, err := client.CDN.Presets.List(ctx, cdn.PresetListParams{})
        if err != nil {
            panic(err)
        }
        var presetID int64
        for _, item := range page.Results {
            if item.Name == "LIVE STREAMING" {
                presetID = item.ID
                break
            }
        }
        applied, err := client.CDN.Presets.Applied.Apply(ctx, presetID, cdn.PresetAppliedApplyParams{
            ObjectID: 1001,
        })
        if err != nil {
            panic(err)
        }
        fmt.Println(applied.PresetID, applied.ObjectID)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl "https://api.gcore.com/cdn/presets?limit=1000" \
      -H "Authorization: APIKey $GCORE_API_KEY"
    ```

    <p>The API returns:</p>

    ```json
    {
      "results": [
        {
          "id": 52,
          "name": "LIVE STREAMING"
        }
      ]
    }
    ```

    <p>Apply the id of the preset named `LIVE STREAMING`:</p>

    ```bash
    curl -X POST "https://api.gcore.com/cdn/presets/52/applied" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"object_id": 1001}'
    ```

    <p>The API returns:</p>

    ```json
    {
      "preset_id": 52,
      "object_id": 1001,
      "message": "Preset successfully applied"
    }
    ```
  </Tab>
</Tabs>

Gcore Video CDN delivers live streams and video-on-demand content globally without transcoding, using existing HLS, DASH, or FLV output.

## Video CDN or Gcore Video Streaming

<Tabs>
  <Tab title="Use video CDN if...">
    **Use [Video&nbsp;CDN](/cdn/video-cdn/video-cdn-overview) when:**

    - Existing HLS, DASH, or FLV streams are already available
    - Transcoding is handled independently, outside Gcore
    - Global delivery at scale is required (thousands to millions of viewers)
    - Advanced CDN features are needed:
      - Geo-blocking by country
      - Secure token authentication
      - Custom domains
      - Origin shielding
    - Reducing origin bandwidth costs is a priority

    **Supported formats:**
    - [HLS](/cdn/video-cdn/hls) (`.m3u8` playlists, `.ts` or `.m4s` segments)
    - **MPEG-DASH** (`.mpd` manifests)
    - **HTTP-FLV** (`.flv` streams)
    - **MP4** (progressive download, VOD only)

    **Example scenarios:**
    - A media server (Wowza, Nginx-RTMP, SRS) produces HLS output
    - Migrating from another CDN (Cloudflare, AWS, or Akamai)
    - Broadcasting rights require geo-restrictions
    - Offloading bandwidth from the origin is a goal
  </Tab>
  <Tab title="Use Video Streaming if...">
    **Use Gcore Video Streaming instead when:**

    - Transcoding is needed for raw RTMP/SRT input
    - Automatic quality ladder generation (ABR) is required
    - Streaming originates from encoders (OBS, vMix, hardware encoders)
    - DVR (pause/rewind) or recording features are needed
    - An all-in-one hosted solution is preferred

    Setup steps for Gcore Video Streaming are covered in [Video&nbsp;Streaming](/streaming).
  </Tab>
</Tabs>

## Quick setup (4 steps)

### Step 1: Request streaming activation

<Warning>
Required first step: video delivery via CDN requires legal approval from Gcore Support.
</Warning>

Contact [Gcore&nbsp;Support](mailto:support@gcore.com) or use the chat in the bottom-right corner and ask to enable video delivery for the CDN account. This is CDN-side approval for prepared HLS and DASH delivery.

Provide:

- **Account ID** (found in the profile dropdown or [Account&nbsp;overview](/account-settings/account/overview))
- **Domain name** and company name
- **Content type**: sports, education, entertainment, or news
- **Sample stream URL**: an example of the typical stream format
- **Viewer geography**: where the audience is located
- **Broadcasting license** or content compliance policy
- **Abuse or copyright contact email**

For sports, TV channels, events, or other third-party protected content, Support may request proof that the account holder or its clients have rights to distribute the content. Requests without the necessary licensing details, company identity, or abuse handling information may be declined or closed.

Processing time: Usually 1-2 business days

### Step 2: Activate paid CDN plan

Video streaming requires a paid CDN subscription:

1. Navigate to **CDN** in the [Gcore&nbsp;Customer&nbsp;Portal](https://portal.gcore.com)
2. On the free plan, upgrade to:
   - **Start** (1.5 TB included traffic)
   - **Pro** (5 TB included traffic)

Pricing is based on bandwidth delivered to viewers, detailed on the [pricing](/cdn/how-the-cdn-service-and-its-additional-options-are-billed) page.

### Step 3: Create CDN resource

Once streaming is activated by support, create the CDN resource:

1. Navigate to **CDN** > [CDN&nbsp;resources](https://portal.gcore.com/cdn/resources/list)
2. Click **Create CDN resource**
3. Enter the domain that will serve the video CDN — for instance, `video.yourdomain.com`. Use **Add CNAME** to add more domains if needed.
4. Under **Origin**, keep **Specify content origin** selected, then select the origin type:

<Tabs>
  <Tab title="URL">
    - **Origin source**: the media server domain or IP — for instance, `live.example.com`
    - The origin must be resolvable through DNS — internal-only or placeholder domains are rejected
  </Tab>
  <Tab title="S3 storage">
    - **Origin source**: the Gcore Storage bucket that holds the VOD files
  </Tab>
  <Tab title="FastEdge">
    - **Origin source**: the FastEdge app that generates the response
  </Tab>
</Tabs>

5. Click **Create**

The [static&nbsp;assets](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource) guide covers the same resource creation process used for video.

### Step 4: Configure caching rules

Optimize caching for video delivery:

<Tabs>
  <Tab title="For Live HLS Streaming">
    Basic cache configuration for live streams:

    ### Step 1: Enable "Always online" (Recommended)

    1. Navigate to **CDN Resource** > **Cache**
    2. Enable **"Always online"** and add these tags to the list of error types that trigger it:
       - **error** (serve stale cache if origin returns errors)
       - **timeout** (serve stale cache if origin times out)

    **Why enable Always online?**
    - Protects viewers from origin failures
    - If origin goes down, CDN serves cached content instead of error pages
    - Improves reliability and uptime

    <Warning>
    Important: Do not add "updating" to the error types list for live streaming. When excluded, the CDN can deliver video chunks more efficiently, reducing buffering and ensuring smoother playback. Only add "error" and "timeout".
    </Warning>

    ### Step 2: Set resource-level cache (for segments)

    1. Still in **CDN Resource** > **Cache**
    2. Set **CDN cache expiry time**: **60 seconds**
       - This caches all content (except manifests, see below) for 60 seconds
       - With DVR enabled, increase this to match the DVR window (30 minutes, for instance)

    ### Step 3: Create manifest caching rule

    1. Navigate to **CDN Resource** > **Rules**
    2. Click **Create rule** and select **Playlists template (.m3u8)** to pre-fill the pattern and cache settings for manifest files

    <Frame>![Create rule dropdown with the Playlists and Video segments templates](/images/docs/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming/create-a-cdn-resource-for-video-streaming-image2.png)</Frame>

    3. Review the pre-filled **Cache time** (2 seconds) and **Browser cache** (0 seconds) values, adjust if needed
    4. Click **Create rule**

    For MPEG-DASH manifests (`.mpd`) or a custom pattern, click **Create blank rule** instead and enter the pattern manually:
    - **Rule name**: `manifests`
    - **Pattern**: `^/.+\.(m3u8|mpd|ism)$` (regex for manifest files)
    - **Cache time**: **2 seconds**
    - **Browser cache**: **0 seconds** (no browser caching for manifests)

    **Why these values?**
    - **Segments (60s)**: Balances freshness with cache efficiency. Longer than segment duration for slow connections.
    - **Manifests (2s)**: Short enough that viewers always get the latest segment list
    - **DVR adjustment**: If DVR enabled, segment cache should match DVR window

    ### Optional: LL-HLS (Low-Latency) configuration

    If using LL-HLS (Low-Latency HLS):

    1. Navigate to **CDN Resource** > **Cache**
    2. Enable **Query parameters allowlist**
    3. Add these parameters: `_HLS_msn`, `_HLS_part`, `_HLS_skip`
       - These are required for LL-HLS to work correctly
       - All other query parameters will be ignored
  </Tab>
  <Tab title="For VOD (Video on Demand)">
    **Optimized cache configuration for VOD:**

    ### Step 1: Enable "Always online" (Recommended)

    1. Navigate to **CDN Resource** > **Cache**
    2. Enable **"Always online"** and add these tags to the list of error types that trigger it:
       - **error** (serve stale cache if origin returns errors)
       - **timeout** (serve stale cache if origin times out)

    **Why enable Always online?**
    - If origin goes down, viewers can still watch cached videos
    - Prevents "origin unavailable" errors from affecting users
    - Especially important for high-traffic VOD platforms

    <Warning>
    Important: Do not add "updating" to the error types list for live streaming. When excluded, the CDN can deliver video chunks more efficiently, reducing buffering and ensuring smoother playback. Only add "error" and "timeout".
    </Warning>

    ### Step 2: Set long-term cache for all content

    1. Still in **CDN Resource** > **Cache**
    2. Set **CDN cache expiry time**: 1 year (31536000 seconds)
       - This caches all successful responses (2xx, 3xx) for 1 year
       - VOD content doesn't change, so aggressive caching is safe
    3. Set **Custom cache time for 404 errors**: 1 second
       - Protects origin from repeated requests for non-existent files

    **Why one year?**
    - VOD files never change once uploaded
    - Maximum cache efficiency = minimum origin load
    - Can be purged manually if needed

    ### Step 3 (Optional): Large file optimization (for MP4)

    If delivering MP4 files for progressive download:

    1. Navigate to **CDN Resource** > **Content**
    2. Enable **Large files delivery optimization**
       - Enables HTTP range requests for seeking
       - Important: the origin must support Range requests
       - Note: Enabling this will invalidate existing cache

    Requirements:
    - Origin server supports HTTP Range Request (Content-Range headers)
    - If using origin group, files must have identical Content-Length and ETag across all origins
    - Do not enable GZIP compression when using large file optimization

    ### Step 4 (Optional): Query string handling

    1. Navigate to **CDN Resource** > **Cache**
    2. Enable **Ignore query string** if:
       - VOD URLs don't use query parameters for logic
       - Caching `video.mp4?ref=email` and `video.mp4?ref=social` as the same file is preferred
    3. Confirm with the customer first — analytics or tracking might depend on query parameters

    Common file extensions:
    - **Manifests**: `.m3u8`, `.mpd`
    - **Segments**: `.ts`, `.m4s`, `.m4v`, `.m4a`, `.m4i`
    - **Progressive**: `.mp4`, `.webm`
    - **Subtitles**: `.vtt`, `.webvtt`, `.ttml`
  </Tab>
  <Tab title="For Live MPEG-DASH CMAF Streaming">
    <Warning>
    Critical for low-latency: when using MPEG-DASH with an external transcoder (not Gcore Video Streaming), enable the **Chunked-Proxy module** for low-latency delivery by contacting [Gcore&nbsp;Support](mailto:support@gcore.com) or the account manager.

    Without Chunked-Proxy, the CDN uses standard "store and forward" delivery, resulting in 10-15 second latency instead of the 2-4 second low-latency performance.
    </Warning>

    ### Chunked-Proxy module

    Standard CDNs wait for files to completely download from origin before sending to viewers ("Store and Forward"). Gcore's **Chunked-Proxy module** streams data immediately:
    - Immediate distribution: CDN edge sends bytes to viewers *while* receiving from origin
    - Protocol optimization: uses Chunked Transfer Encoding (HTTP/1.1) and Framing (HTTP/2/3)
    - 2-4 second latency: achieves true low-latency for LL-DASH streams

    Low-latency delivery mechanics are covered in the [low-latency&nbsp;streaming](/streaming/live-streaming/how-low-latency-streaming-works) guide.

    ---

    ### Request Chunked-Proxy activation

    1. Contact [Gcore&nbsp;Support](mailto:support@gcore.com) or the account manager
    2. Request **Chunked-Proxy module activation** for the CDN resource
    3. Provide:
       - The CDN resource ID or domain
       - Confirmation of using LL-DASH with CMAF segments
       - Origin transcoder details (Wowza or Nginx-RTMP)

    After activation:
    - LL-DASH streams achieve 2-4 second latency
    - The CDN streams chunks immediately as they're received from origin

    <Info>
    When using **Gcore Video Streaming** (the Gcore transcoding service), Chunked-Proxy is already enabled by default. Activation is only needed for an external transcoder.
    </Info>

    ---

    ### Cache configuration

    After Chunked-Proxy activation by the support team, follow the cache configuration instructions from the **"For Live HLS Streaming"** tab above.

    Only difference: When creating the manifest caching rule (Step 3), use:
    - **Pattern**: `^/.+\.mpd$` (for DASH manifest files instead of `.m3u8`)

    Common DASH/CMAF file extensions:
    - **Manifests**: `.mpd`
    - **Segments**: `.m4s`, `.m4v`, `.m4a`, `.cmfv`, `.cmfa`
    - **Initialization**: `.mp4` (init segments)
  </Tab>
  <Tab title="For FLV Streaming">
    FLV streams use a single continuous connection. Cache settings for FLV streaming are fully custom — contact the support team for configuration.

    Configuration details are covered in the [FLV&nbsp;streaming](/cdn/video-cdn/flv-streaming) guide.
  </Tab>
</Tabs>

<Info>
For high-traffic streaming or specific performance requirements, contact [Gcore&nbsp;Support](mailto:support@gcore.com) to configure:
- **Cache sharding**: Distribute cache across multiple servers
- **Cache lock timing**: Optimize concurrent request handling
- **Custom TTL strategies**: Fine-tune cache behavior per file type
- **Origin connection limits**: Protect origin from traffic spikes
</Info>

### Step 5 (Live only): Enable LIVE STREAMING preset

<Info>
For live streams only — skip this step when delivering VOD.
</Info>

The LIVE STREAMING preset enables RAM-based caching for reduced latency:

1. Navigate to [CDN&nbsp;resources](https://portal.gcore.com/cdn/resources/list)
2. Click the **three dots** next to the video CDN resource
3. Select **Turn on LIVE STREAMING preset**

## Test the stream

### CDN URL

Update stream URLs from origin to CDN:

Before (origin):
```
http://live.example.com/playlist.m3u8
```

After (CDN):
```
http://video.yourdomain.com/playlist.m3u8
```

Or with auto-generated domain:
```
http://123456.gcdn.co/playlist.m3u8
```

### Test playback

Confirm playback in a player that supports HLS:

- Browser: [VLC&nbsp;Media&nbsp;Player](https://videolan.org)
- Online: [HLS.js&nbsp;demo&nbsp;player](https://hls-js.netlify.app/demo/)
- Mobile: Native Safari (iOS) or Chrome (Android)

Pasting the CDN URL into the player verifies playback.

## Optional: Advanced configuration

### Enable origin shielding

For high-traffic streams (100+ concurrent viewers), enable origin shielding:

1. Navigate to **CDN Resource** > **General** > **Origin shielding**
2. Toggle **Enable origin shielding**
3. Select shield location closest to the origin

Benefit: reduces origin requests by 80-95%, protecting the origin from traffic spikes.

Additional origin shielding options, including shield location selection, are available in [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding) settings.

### Add geo-restrictions

Restrict content by country — useful for broadcasting rights:

1. Navigate to **CDN Resource** > **Security** > **Country access policy**
2. Select:
   - **Allow only**: content available only in selected countries
   - **Block**: content blocked in selected countries
3. Select countries
4. Save changes

Example: "Allow only in Dominican Republic" for regional sports rights.

The full [Geo-restrictions](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#country-access-policy) reference covers additional match combinations.

### Add secure tokens

Protect content with time-limited authenticated URLs:

1. Navigate to **CDN Resource** > **Security** > **Secure Token**
2. Enable and configure token settings
3. Generate tokens on the backend for each user

Use cases: paid content, private videos, time-limited previews.

The full [Secure&nbsp;Tokens](/cdn/cdn-resource-options/security/use-a-secure-token/about-secure-token) reference covers token generation and expiration options.

## Troubleshooting

### Stream not playing

1. Check origin is accessible: test origin URL directly in browser
2. Verify DNS: confirm the CNAME points to the CDN (for a custom domain)
3. Check cache rules: verify `.m3u8` and `.ts` rules are configured
4. Review CDN logs: check for 4xx/5xx errors in [CDN&nbsp;statistics](/cdn/view-statistics-of-a-cdn-resource)

### High latency

1. Enable LIVE STREAMING preset: for live streams (see Step 5)
2. Reduce playlist cache: set `.m3u8` cache to 1-2 seconds
3. Enable origin shielding: reduces routing hops
4. Contact support: for advanced latency optimization

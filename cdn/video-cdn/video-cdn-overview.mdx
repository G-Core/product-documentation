Edge locations cache and distribute already-prepared live streams and VOD files so playback stays stable and origin load stays lower. Video CDN is that video-delivery use of standard Gcore CDN. Topics include supported formats, cache guidance, origin protection, security, and troubleshooting for HLS, DASH, MP4, and related workflows. Transcoding belongs in [Gcore&nbsp;Video&nbsp;Streaming](/streaming).

## Legal requirement

<Info>
Before delivering HLS, DASH, or other video streams via CDN, ask Gcore Support to enable video delivery for the CDN account. Approval verifies the use case, content rights, and anti-piracy requirements.
</Info>

Request activation from [Request&nbsp;streaming&nbsp;activation](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming#step-1-request-streaming-activation) in the setup guide. Contact Support and provide Account ID, domain name, company name, content type, sample stream URL, viewer geography, and a broadcasting license or content compliance policy. For sports, TV channels, events, or other third-party protected content, Support may ask for license or rights confirmation before enabling delivery.

If video delivery is not enabled yet, CDN requests for streaming file types can return `402`. Status-code guidance is in [Gcore&nbsp;error&nbsp;codes](/cdn/troubleshooting/gcore-error-status-codes#other-errors-402-504-508-556-557).

## Supported video formats

| Format | Live | VOD | Use case |
|--------|------|-----|----------|
| **HLS** (HTTP Live Streaming) | Yes | Yes | Wide device support, Apple-native |
| **MPEG-DASH** | Yes | Yes | Common standard for non-Apple devices |
| **HTTP-FLV** | Yes | Yes | Ultra-low latency (1–3 s), high concurrency |
| **MP4** | Limited | Yes | Direct downloads, progressive playback |

<Info>
HLS files (`.m3u8`, `.ts`, `.m4s`) are delivered by CDN as HTTP content. Gcore Video Streaming is not required when HLS files are already prepared and transcoding is not needed. Video CDN delivery must still be enabled for the CDN account by Gcore Support so the use case can be verified and the CDN protected from piracy and fraud.
</Info>

<Info>
MP4 is not a live streaming format for Video CDN, but VOD2Live-style playback is available with [Live&nbsp;imitation](/streaming/video-hosting/create-an-illusion-of-a-live-broadcast-with-uploaded-videos) in Gcore Video Streaming. Gcore transcodes the file and plays it on a fixed schedule, so viewers follow the live timeline and cannot fast-forward.
</Info>

## Low-latency streaming

Gcore Video CDN supports ultra-low latency live delivery:

**Low-Latency HLS (LL-HLS)**

- 2–4 second glass-to-glass latency
- Native support on iOS and modern browsers
- Uses CMAF segments with immediate streaming

**Low-Latency MPEG-DASH (LL-DASH)**

- 2–4 second glass-to-glass latency
- Broad device compatibility (Android, Smart TVs, web browsers)
- Requires Chunked-Proxy module activation

Both protocols use Chunked-Proxy to stream content as soon as it arrives from the origin, which cuts the typical store-and-forward delay from about 10–15 seconds down to 2–4 seconds. Configuration details are in [DASH&nbsp;and&nbsp;LL-DASH](/cdn/video-cdn/dash).

## Key features

### Global CDN delivery

- 210+ edge locations across six continents
- Automatic routing to the nearest edge server

### Optimized for video

- Sliding window caching for live streams (RAM-based)
- Range request support for efficient seeking
- Large file optimization for VOD delivery
- Origin shielding to reduce origin load by 80–99%

### Security and access control

- **Country access policy**: Restrict content by country
- **Secure token**: Time-limited authenticated URLs
- **Referrer access policy**: Limit unauthorized embedding
- **IP access policy**: Allowlist or blocklist specific IPs
- DDoS protection against volumetric attacks

### Advanced configuration

- Custom domains (CNAMEs)
- Custom cache rules per file type
- HTTP protocol support (v2 and v3 with QUIC)
- WebSocket support for interactive features
- Real-time statistics and monitoring

## Setup path

1. Select a streaming format: [HLS&nbsp;and&nbsp;LL-HLS](/cdn/video-cdn/hls), [DASH&nbsp;and&nbsp;LL-DASH](/cdn/video-cdn/dash), or [FLV&nbsp;streaming](/cdn/video-cdn/flv-streaming).
2. Contact [Gcore&nbsp;Support](mailto:support@gcore.com) to enable Video CDN delivery for the CDN account. This is CDN-side approval, not activation of Gcore Video Streaming. Provide domain and company name, content type, sample stream URL, expected viewer geography, and a broadcasting license or content compliance policy.
3. Create the resource with the [video&nbsp;CDN&nbsp;setup](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming) guide.
4. Set cache TTLs that match the workflow — playlists (`.m3u8`) at 1–2 seconds (live) or 5–60 seconds (VOD), and segments (`.ts`, `.m4s`) at 60 seconds (live) or 1–24 hours (VOD).
5. Test the stream with the CDN URL, then deploy to production.

Related configuration topics include [CDN&nbsp;resources](/cdn/getting-started/create-a-cdn-resource/overview), [Secure&nbsp;token](/cdn/cdn-resource-options/security/use-a-secure-token/about-secure-token), [Origin&nbsp;shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding), and [Reports](/cdn/view-statistics-of-a-cdn-resource).

## Video CDN vs Video Streaming

| | Video CDN (this section) | Video Streaming |
|---|--------------------------|----------------|
| Role | Caches and delivers already-prepared streams | Ingests raw input, transcodes, packages, and delivers |
| Transcoding | No — distribution only | Yes — automatic ABR from RTMP, SRT, WebRTC, or HLS pull |
| Formats | HLS, DASH, FLV, MP4, and other HTTP video | Packages into HLS and MPEG-DASH with a built-in player |
| Best when | Streams are already packaged; full CDN control is required | An all-in-one hosted pipeline with DVR or recording is required |

Select Video CDN when a media server already produces HLS/DASH/FLV, when migrating or adding multi-CDN, or when geo restrictions and custom access policies are required. Select [Video&nbsp;Streaming](/streaming) when raw encoder input, automatic ABR, DVR, or a hosted player pipeline is required.

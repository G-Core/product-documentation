Origin Shielding places one shield, also called a precache server, between the video origin and CDN edge servers. Viewers still receive video from a nearby edge, while an edge cache miss goes to the shield instead of the origin.

## Cache misses with and without a shield

Without Origin Shielding, every CDN edge that misses cache can request the same manifest, segment, or video file from the origin, so a live event or a VOD release turns those misses into many concurrent origin requests.

With Origin Shielding, edges pull missed objects through one shield location. The shield serves a cached copy or fetches the object from the origin once and shares it, so each object causes one origin request instead of one request per edge.

<Info>
The origin still serves the first request for uncached or expired content.
</Info>

## Situations that call for a shield

Enable Origin Shielding for a large live audience, a VOD release that may become hot, limited origin bandwidth, significant origin egress cost, or a low [cache&nbsp;hit&nbsp;ratio](/cdn/troubleshooting/cache-percentage-is-low-how-to-solve-the-issue) across multiple CDN edge locations.

### Live events

For live events with viewers in several regions, many edge locations can miss the same recently published segments at once. Those segments are new, so edge caches do not have them yet and the misses arrive together.

### VOD libraries

For a large VOD library, cold or evicted titles can miss on many edges at the same time. The files are no longer in those edge caches, so the misses cluster when viewers in different regions request the same title.

## Shield location and cache TTLs

Select a shield location close to the origin. For live streaming, use short but cacheable TTLs for manifests and longer TTLs for segments where the workflow allows it.

For VOD, keep files and segments cached long enough to serve repeated requests.

Set the shield location and these TTLs in [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding).

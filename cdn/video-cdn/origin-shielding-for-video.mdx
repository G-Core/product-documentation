Origin shielding adds a shield, also called a precache server, between the video origin and Gcore CDN edge servers. Viewers still receive video from nearby CDN edges, but edge cache misses reach the shield first, not the origin directly.

| Benefit | Why it matters |
|---------|----------------|
| Protects the origin | Repeated CDN edge misses are absorbed by the shield instead of hitting the origin from many locations. |
| Minimizes origin requests | The shield requests the origin only when the object is not already cached there. |
| Reduces egress costs | Less traffic is pulled from the origin, which matters when origin egress is costly. |
| Improves reliability | A less overloaded origin reduces the risk of slow segments, timeouts, and playback errors. |

## Origin shielding request flow

Without shielding, every CDN edge location that misses cache can request the same manifest, segment, or video file from the origin. During a live event or a popular VOD release, this can create a large number of concurrent origin requests.

With shielding, edge servers pull missed objects through one shield location. If the shield has the object, it serves the edge from cache. If not, it makes one origin request, caches the response, and shares it with other CDN edges.

```
Without shielding: Viewer -> CDN edge -> Origin
With shielding:    Viewer -> CDN edge -> Shield -> Origin
```

<Info>
Origin shielding does not replace origin capacity planning. The origin still serves the first request for uncached or expired content.
</Info>

## Use cases

### Sports broadcasting

A national TV broadcaster used origin shielding for live sports events with a very large concurrent audience. During match peaks, many viewers requested the same live playlists and segments at the same time from different regions.

Shielding helped concentrate repeated CDN edge misses through the shield server instead of sending them all to the broadcaster origin. This reduced bandwidth pressure on the origin and helped keep the live stream available during the highest-traffic moments of the event.

### VOD libraries

A large VOD service used origin shielding for a several PB-sized video library. Hot content was usually served from CDN edge cache, but cold or previously hot titles could be evicted from edge caches and then requested again from different regions. Shielding let one missed request warm the shield cache, so other CDN edges reused that copy instead of repeatedly pulling the same files from origin.

## Shielding recommendations

Enable origin shielding when a large live audience is expected, when VOD content may become hot, when origin bandwidth is limited, when origin egress costs are significant, or when a [low&nbsp;hit&nbsp;ratio](/cdn/troubleshooting/cache-percentage-is-low-how-to-solve-the-issue) appears across multiple CDN edge locations.

Select a shield location close to the origin server. For live streaming, use short but cacheable TTLs for manifests and longer TTLs for segments where the workflow allows it. For VOD, keep video files and segments cached long enough to serve repeated requests.

In the Customer Portal, Origin Shielding sits under CDN resource settings as **Enable Origin Shielding**. Full setup steps are in [Enable&nbsp;origin&nbsp;shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding).

Cache hit and miss behavior for video playback is covered in [video&nbsp;delivery&nbsp;speed](/cdn/video-cdn/improve-video-delivery-speed).

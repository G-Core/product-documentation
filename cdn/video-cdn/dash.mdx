MPEG-DASH (Dynamic Adaptive Streaming over HTTP) is an HTTP-based adaptive protocol for live and VOD delivery. A DASH stream uses an `.mpd` manifest and media segments, so Gcore CDN can cache and deliver it like other HTTP video formats.

Low-Latency MPEG-DASH (LL-DASH) is the low-latency mode for DASH live streaming. With CMAF segments and Gcore **Chunked-Proxy**, glass-to-glass latency can reach **2–4 seconds**, because the edge streams data as it arrives instead of waiting for complete segment downloads.

## DASH and LL-DASH fit

Video CDN for DASH fits when:

- DASH streams (`.mpd` manifests and media segments) are already packaged
- Transcoding and packaging run outside Gcore Video Streaming
- Broad device compatibility is required (Android, Smart TVs, web browsers, or custom players)
- CDN features including [Country&nbsp;access&nbsp;policy](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#country-access-policy), secure tokens, origin shielding, or custom domains are required

LL-DASH fits when 2–4 second latency is also required for live events (sports, auctions, gaming, or interactive broadcasts) and the transcoder produces MPEG-DASH with CMAF segments.

Use [Video&nbsp;Streaming](/streaming) instead when RTMP/SRT ingest, automatic ABR ladders, or a hosted transcoding pipeline is required.

## Latency model

### Store-and-forward delivery

Standard CDN delivery waits for a full segment from the origin (often 2–6 seconds) before sending it to viewers, which commonly yields **10–15 seconds** of latency.

### Chunked-Proxy delivery

Chunked-Proxy streams immediately:

1. The edge starts delivering bytes to viewers while still downloading from the origin.
2. Transfer uses HTTP Chunked Transfer Encoding (HTTP/1.1) or framing (HTTP v2 / v3).
3. Resulting glass-to-glass latency is typically **2–4 seconds**.

Engineering background: [latency&nbsp;blog](https://gcore.com/blog/optimizing-hls-dash-3sec) on HLS and DASH optimization.

## Chunked-Proxy behavior

### Without Chunked-Proxy

```
Origin → [CDN waits for full file] → CDN → Viewer
         2–6 second delay
Total latency: 10–15 seconds
```

### With Chunked-Proxy

```
Origin → [CDN streams immediately] → Viewer
Total latency: 2–4 seconds
```

Advantages:

- **Byte-level streaming**: Data flows origin → CDN → viewer concurrently
- **Protocol optimization**: HTTP/1.1 chunked transfer encoding and HTTP v2 / v3 framing
- **RAM-based caching**: **LIVE STREAMING** preset uses RAM instead of disk
- **Origin shielding compatible**: Lowers origin load while keeping low latency

### Configure the CDN resource

After activation, follow the cache steps in the [video&nbsp;streaming&nbsp;setup](/cdn/getting-started/create-a-cdn-resource/create-a-cdn-resource-for-video-streaming#step-4-configure-caching-rules) guide.

Key settings:

- **Manifests (`.mpd`)**: `2s` cache
- **Segments (`.m4s`)**: `60s` cache
- **Always online**: Enabled with **Error** and **Timeout** selected; leave **Updating** cleared
- **LIVE STREAMING preset**: Enabled for RAM caching

## Best practices

### Origin configuration

- **Segment duration**: 2–6 seconds (shorter lowers latency and raises overhead)
- **Chunked encoding**: Enable chunked transfer encoding on the origin
- **Availability window**: Keep 30–60 seconds of segments available

### CDN optimization

- **Origin shielding**: Recommended for 100+ concurrent viewers
- **Edge locations**: Content cached across 210+ global edge servers
- **Monitoring**: Use [Reports](/cdn/view-statistics-of-a-cdn-resource) to track performance

### Player compatibility

Players should support MPEG-DASH, CMAF segments, and a low-latency mode when available. Common choices include dash.js (low-latency mode), Shaka Player, ExoPlayer (Android), and AVPlayer (iOS/tvOS with DASH support).

## Troubleshooting

### High latency (over 10 seconds)

**Cause:** Chunked-Proxy is not activated or not working correctly.

**Solution:**

1. Confirm Support activated Chunked-Proxy.
2. Confirm the origin supports chunked encoding.
3. Confirm CMAF segments are used (not MPEG-TS).
4. Contact [Gcore&nbsp;Support](mailto:support@gcore.com) for diagnostics.

### Buffering or playback issues

**Cause:** Cache settings are too aggressive, or manifest updates are too slow.

**Solution:**

1. Reduce manifest cache to 1–2 seconds.
2. Keep segment cache at 60 seconds.
3. Enable **Always online** with **Error** and **Timeout** only (clear **Updating**).
4. Check origin availability and response times.

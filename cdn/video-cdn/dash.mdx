MPEG-DASH (Dynamic Adaptive Streaming over HTTP) is an HTTP-based adaptive protocol for live and video on demand (VOD) delivery. A DASH stream uses an `.mpd` manifest and media segments, so Gcore CDN can cache and deliver it like other HTTP video formats.

Low-Latency MPEG-DASH (LL-DASH) is the live mode that streams Common Media Application Format (CMAF) segments as they arrive. Gcore Chunked-Proxy is the edge module that forwards those bytes to viewers instead of waiting for a complete segment download.

## Suitable use cases

Use Video CDN for DASH when the origin already produces `.mpd` manifests and media segments, and transcoding stays outside Gcore Video Streaming.

- Broad device compatibility is required (Android, smart TVs, web browsers, or custom players)
- CDN features including [Country&nbsp;access&nbsp;policy](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#country-access-policy), secure tokens, Origin Shielding, or custom domains are required

Use LL-DASH for live events when the transcoder produces MPEG-DASH with CMAF segments and 2–4-second latency is required. Typical cases include sports, auctions, gaming, and interactive broadcasts.

Use [Video&nbsp;Streaming](/streaming) instead when Real-Time Messaging Protocol (RTMP) or Secure Reliable Transport (SRT) ingest, automatic adaptive bitrate (ABR) ladders, or a hosted transcoding pipeline is required.

## Setup requirements

Standard DASH and LL-DASH use different packaging, while both require a paid plan and video-delivery approval.

### Delivery formats

Standard DASH uses MPEG-DASH manifests and segments. LL-DASH additionally requires CMAF packaging.

| Format | Details |
|--------|---------|
| Standard DASH | MPEG-DASH (`.mpd` manifests and media segments, including `.m4s`) |
| LL-DASH | MPEG-DASH with CMAF segments (`.mpd`, `.m4s`) |

### Account and activation

A paid plan and video delivery approval apply to both modes. Chunked-Proxy applies only to LL-DASH.

| Requirement | Details |
|-------------|---------|
| Paid CDN plan | Any paid subscription |
| Video delivery approval | Enablement from Gcore Support |
| Chunked-Proxy | Required only for LL-DASH — contact [Gcore&nbsp;Support](mailto:support@gcore.com) |

<Warning>
Chunked-Proxy activation is mandatory for LL-DASH. Without it, DASH still delivers, but the edge uses store-and-forward instead of streaming bytes as they arrive.
</Warning>

    - Confirmation that LL-DASH with CMAF segments is in use
    - Origin transcoder details (Wowza, Nginx-RTMP, FFmpeg, or similar)

    <Info>
    With [Gcore&nbsp;Video&nbsp;Streaming](/streaming) and Gcore transcoding, Chunked-Proxy is already enabled by default. Activation is required only for an external transcoder.

## Supported file formats

DASH packages a manifest plus CMAF media objects. The CDN caches each object type independently.

| File type | Extension | Description |
|-----------|-----------|-------------|
| Manifests | `.mpd` | DASH Media Presentation Description |
| Video segments | `.m4s`, `.m4v` | CMAF video segments |
| Audio segments | `.m4a`, `.m4s` | CMAF audio segments |
| Initialization | `.mp4` | Initialization segments for fragmented MP4 (fMP4) streams |

## Latency model

Store-and-forward CDNs wait until a full segment arrives from the origin (often 2–6 s) before sending it to viewers. Chunked-Proxy starts delivering bytes while the origin transfer is still open, using HTTP/1.1 chunked transfer encoding, HTTP/2 DATA frames, or HTTP/3 over QUIC. That is the difference between typical 10–15-second latency and 2–4-second glass-to-glass latency — the total delay from video capture to viewer playback.

The table below compares viewer-delivery methods only. The engineering analysis in [Optimizing HLS and DASH for 3-second latency](https://gcore.com/blog/optimizing-hls-dash-3sec) explains how chunked transfer encoding and HTTP framing produce these latency ranges.

| Delivery method | Typical latency | Use case |
|-----------------|-----------------|----------|
| LL-DASH (Chunked-Proxy) | 2–4 seconds | Live sports, auctions, interactive events |
| Standard DASH (no Chunked-Proxy) | 10–15 seconds | News, conferences, less interactive content |
| HTTP Flash Video (HTTP-FLV) | 1–3 seconds | Ultra-low latency for specific use cases |

## Best practices

Origin, CDN, and player settings all affect whether Chunked-Proxy can hold the latency in the table above.

### Origin configuration

Shorter CMAF segments and chunked encoding on the origin give the edge a continuous byte stream to forward.

- Use 2–6-second segments (shorter duration lowers latency and raises overhead)
- Enable chunked transfer encoding on the origin
- Keep 30–60 s of segments available in the availability window

### CDN optimization

Origin Shielding reduces origin load, while reporting helps identify latency regressions. Gcore operates more than 210 edge locations, where content is cached in response to viewer requests.

- Enable Origin Shielding for 100 or more concurrent viewers
- Use [Reports](/cdn/view-statistics-of-a-cdn-resource) to track cache hit ratio and origin traffic

### Player compatibility

The player must support MPEG-DASH, CMAF segments, and a low-latency mode when one is available. Common choices are dash.js (low-latency mode), Shaka Player, and ExoPlayer on Android.

AVPlayer does not natively play MPEG-DASH. Apple’s AVFoundation stack uses HLS, so DASH on iOS or tvOS requires a third-party player that implements DASH. Use [HLS&nbsp;and&nbsp;LL-HLS](/cdn/video-cdn/hls) when native Apple playback is required.

## Troubleshooting

Check Chunked-Proxy, origin encoding, and cache time to live (TTL) values before assuming a player bug.

### High latency (over 10 seconds)

Latency in this range usually means the edge is still waiting for complete segments.

1. Confirm Support activated Chunked-Proxy.
2. Confirm the origin supports chunked encoding.
3. Confirm CMAF segments are used, not MPEG transport stream (MPEG-TS).
4. Contact [Gcore&nbsp;Support](mailto:support@gcore.com) for diagnostics.

### Buffering or playback issues

Aggressive cache or a slow origin can stall playlist updates even when Chunked-Proxy is on.

1. Reduce manifest cache to 1–2 s.
2. Keep segment cache at 60 s.
3. Enable **Always online** with **Error** and **Timeout** only (clear **Updating**).
4. Check origin availability and response times.

Contact [Gcore&nbsp;Support](mailto:support@gcore.com) or use chat in the Customer Portal for further help.

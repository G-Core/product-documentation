Multi-codec content delivery helps large video libraries reduce delivery traffic by serving a more efficient codec to compatible devices while keeping H.264 as a fallback. A player can request HEVC, AV1, VP9, or H.264 renditions based on the viewer browser, device, and playback format.

## Multi-codec live and VOD delivery

Gcore CDN is codec- and quality-agnostic. It distributes the video files and playlists that the origin provides, including prepared multi-codec HLS CMAF or MPEG-DASH streams. Libraries that already have multi-codec renditions can deliver them through Gcore CDN.

Libraries that are still mostly H.264 can create HEVC, AV1, and VP9 renditions with [multi-codec&nbsp;VOD](/streaming/video-hosting/multi-codec) in Gcore Video Streaming. That path fits enterprise VOD catalogs with high traffic.

## Business value

For large live broadcasts and large VOD libraries, codec choice is an ROI decision, not only a technical setting. When a major part of the audience can play HEVC, AV1, or VP9, delivered bitrate and CDN bandwidth consumption can drop.

Typical target use cases:

- Live sports broadcasts
- Live premium content
- Film and TV archives
- E-learning catalogs
- News and media archives
- Subscription or ad-supported VOD platforms
- Libraries with tens of thousands of hours of watched content

<Info>
Actual savings depend on source quality, codec mix, viewer devices, bitrate ladder, geography, and playback behavior. Gcore can help evaluate expected savings before a large library migration.
</Info>

## Codec comparison

| Codec | Typical bitrate reduction vs H.264 | Main benefit | Typical device support | Best fit |
|-------|--------------------------------|--------------|------------------------|----------|
| H.264 | Baseline | Maximum compatibility | All devices | Baseline playback and fallback |
| HEVC (H.265) | About 30–50% | Lower bitrate than H.264 at similar quality | Apple devices, many Smart TVs, newer mobile devices | Premium VOD and live-broadcast content |
| VP9 | About 25–45% | Efficient web playback | Mostly Android-based devices, VOD libraries | Browser-heavy audiences |
| AV1 | About 40–60% | Highest compression efficiency among modern web codecs | Newer devices and browsers, smart TVs and hardware decoders | Large catalogs where bandwidth savings justify premium processing |

## Device coverage and cost reduction

Modern codec support is broad enough for many video services to use multi-codec delivery as a cost-reduction strategy. Keep H.264 as a fallback and serve HEVC, AV1, or VP9 only to compatible devices.

## Recommended VOD workflow

1. Review the current VOD library: hours of content, monthly traffic, top countries, device mix, and current codec.
2. Define the codec set: usually H.264 fallback plus HEVC, AV1, VP9, or a subset.
3. Select output formats. HLS CMAF and MPEG-DASH are the main delivery paths for modern codecs.
4. Test playback on the most important devices and players.
5. Migrate the high-traffic part of the library first, then expand to the long tail if ROI is positive.

## Recommended live workflow

1. Prepare the live encoding and packaging workflow on the origin or streaming service.
2. Keep H.264 as the compatibility fallback for live playback.
3. Add HEVC and AV1 for device groups where playback is tested.
4. In HLS MPEG-TS use H.264. In HLS CMAF and MPEG-DASH use H.264, HEVC, and AV1.
5. Test the full live path before launch: encoder, packager, CDN cache behavior, player, latency, and fallback logic.
6. For important broadcasts, use [origin&nbsp;shielding](/cdn/video-cdn/origin-shielding-for-video) to reduce origin load during audience peaks.

<Note>
Advanced live multi-codec delivery depends on the ingest, packaging, player, and device path. Validate it with Gcore before using it for a production broadcast.
</Note>

## Delivery formats

| Delivery format | Container | Multi-codec support | Notes |
|-----------------|-----------|--------------------|-------|
| HLS MPEG-TS | MPEG-TS chunks | No | Supports H.264. Used for compatibility among all devices, especially legacy devices: mobile, desktop, Smart TV, STB, and similar. |
| HLS CMAF | Fragmented MP4 (fMP4) chunks | Yes | Recommended for Apple and modern HLS playback with H.264, HEVC, and AV1. Not recommended for VP9 delivery. |
| MPEG-DASH | fMP4 or WebM chunks | Yes | Recommended for Android, web, Smart TVs, and advanced player workflows. Use WebM chunks for VP9. |
| MP4 downloads | Single MP4 file | Depends on codec | Useful for direct file access to H.264, HEVC, or AV1 versions. |
| WebM files | Single WebM file | VP9 | Useful for direct VP9 file delivery when the workflow provides standalone WebM outputs. |

Playback format details are in [HLS&nbsp;and&nbsp;MP4](/streaming/video-hosting/hls-and-mp4).

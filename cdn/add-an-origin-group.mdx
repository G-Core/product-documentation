Origin groups define where the CDN fetches content from for a CDN resource. Origin groups support load balancing and failover across multiple origins.

## Origin group overview

One origin group can contain a single website, private bucket, or FastEdge HTTP application, or multiple origins.

With multiple active origins, the CDN distributes requests using a round-robin algorithm. Failover and retry behavior — including when to activate backup origins and which failure conditions trigger a retry — depend on origin roles and the **Use next upstream** option. See [Available options](#available-options) for details.

## Origin group configuration

Add one or more origins to the group. For URL and S3 origins, **Host header override** is optional; when left empty, the CDN uses the **Host header** value from the CDN resource settings.

### S3 storage

Select **Amazon** for Amazon S3 or **Other** for another S3-compatible storage service.

<Warning>
Without Origin Shielding, each cache miss on a CDN node sends a request directly to the S3 bucket. At scale, this can overload the storage cluster — enable [Origin&nbsp;Shielding](/cdn/cdn-resource-options/general/enable-and-configure-origin-shielding) to consolidate edge cache misses through a shared shield cache and reduce requests to the S3 origin.
</Warning>

#### Amazon S3 storage

Amazon S3 requires an access key ID and secret access key; the [AWS&nbsp;guide](https://docs.aws.amazon.com/powershell/latest/userguide/pstools-appendix-sign-up.html) explains where to find both values.

<Steps>
  <Step title="Select Amazon S3">
    Select **S3 storage**, then select **Amazon**.
  </Step>
  <Step title="Configure the bucket">
    Enter the storage details:

    1. Enter the **Access Key ID**.
    2. Enter the **Secret access key**.
    3. Select the **AWS region** where the bucket is hosted.
    4. Enter the **Bucket name**.
    5. (Optional) Enter the **Host header override**.

    <Frame>![Amazon S3 origin settings](/images/docs/cdn/add-an-origin-group/s3-storage.png)</Frame>
  </Step>
</Steps>

#### Other S3 storage

For Gcore Object Storage, select **Other**, copy the storage hostname from **Details**, and create the required credentials under [Access&nbsp;keys](/storage/manage-object-storage/manage-s3-access-keys).

<Steps>
  <Step title="Select another S3 service">
    Select **S3 storage**, then select **Other**.
  </Step>
  <Step title="Configure the bucket">
    Enter the storage details:

    1. Enter the storage server **Hostname**.
    2. Enter the **Access Key ID**.
    3. Enter the **Secret access key**.
    4. Enter the **Region (optional)** where the bucket is hosted.
    5. Enter the **Bucket name**.
    6. (Optional) Enter the **Host header override**.

    <Frame>![Other S3-compatible origin settings](/images/docs/cdn/add-an-origin-group/s3-storage-other.png)</Frame>
  </Step>
</Steps>

### URL origin

Use a URL origin for a website or IP address that does not require S3 authentication.

<Steps>
  <Step title="Select the origin type">
    Select **URL**.
  </Step>
  <Step title="Configure the origin">
    Enter the origin details:

    1. In **Origin source**, enter the IP address or domain name without `http://` or `https://`.
    2. (Optional) Enter the **Host header override**.
    3. (Optional) For ports other than 80 or 443, disable **Use default port** and enter the port.

    <Frame>![URL origin settings](/images/docs/cdn/add-an-origin-group/url.png)</Frame>
  </Step>
  <Step title="Add more origins">
    (Optional) Click **+ Add origin** and enter another source. The CDN distributes requests across active origins using a round-robin algorithm.
  </Step>
</Steps>

### FastEdge HTTP application

A FastEdge HTTP application can serve as a native CDN origin. Requests reach the application directly on the same edge node, which avoids duplicate response headers, preserves client GeoIP data, and reduces latency.

<Info>
Because the FastEdge application runs on the same edge node as the CDN, the upstream address in CDN logs and metrics can appear as that node's IP rather than a remote origin address. This applies only when the origin type is a FastEdge HTTP application, not when a FastEdge hook is attached to a regular CDN origin.
</Info>

<Steps>
  <Step title="Select the origin type">
    Select **FastEdge**.
  </Step>
  <Step title="Select the application">
    In the **FastEdge application** dropdown, select the HTTP application.

    <Frame>![FastEdge origin type with the application dropdown](/images/docs/cdn/add-an-origin-group/fastedge-origin-application.png)</Frame>
  </Step>
</Steps>

### Available options

#### Multiple-origin configuration

For groups with multiple origins, configure their availability, roles, and failover behavior:

- Enable or disable each origin.
- Assign active and backup origins.
- Enable or disable **Use next upstream**.

<Frame>![Set up multiple origins](/images/docs/cdn/add-an-origin-group/multiple-origins.png)</Frame>

#### Origin availability

Each origin has the **On** toggle enabled by default, so the CDN can pull content from it. Disable the toggle to remove the origin from this group's load balancing; requests stop reaching it within 15 minutes.

<Info>
At least one active origin must remain enabled.
</Info>

#### Active and backup origins

New origins receive the **Active** status by default and participate in round-robin load balancing. Select **Use origin as a backup** to remove an origin from regular balancing and use it when the active origins meet the applicable failover conditions.

#### Use next upstream

Enable **Use next upstream** only when every origin contains the exact same content. When enabled via the Customer Portal, the CDN retries the request on the next available origin after connection errors or timeouts. Additional retry conditions — such as specific HTTP response codes — can be configured through the [Create origin group API](https://docs.gcore.com/api-reference/cdn/origins/create-origin-group) using the `proxy_next_upstream` array. If no origin is available, the CDN serves the last origin's response.

The resulting request behavior depends on the origin roles and option state:

| Case | CDN request behavior |
| --- | --- |
| **Use next upstream** disabled; all origins active | The CDN returns the active origin's error response to the client without retrying |
| **Use next upstream** disabled; active and backup origins present | After a 5 s timeout or 5xx response from an active origin, the CDN tries the backup origins in list order. For a 4xx response, it returns the error to the client |
| **Use next upstream** enabled; no backup origins | After connection errors or timeouts, the CDN tries the remaining active origins in list order. If all active origins fail, the CDN serves the last origin's response |
| **Use next upstream** enabled; active and backup origins present | After connection errors or timeouts, the CDN tries the remaining active origins first, then backup origins, in list order |

## Origin group creation

Origin groups can be created directly from CDN resource settings or from the **Origin groups** page.

### From resource settings

<Steps>
  <Step title="Open the resource settings">
    In the [Gcore Customer Portal](https://portal.gcore.com/cdn/resources/list), navigate to **CDN**, find the resource, and click its **CNAME**.

    <Frame>![Resource name highlighted](/images/docs/cdn/add-an-origin-group/cdn-resources.png)</Frame>
  </Step>
  <Step title="Open the origin group form">
    In the **Pull content from** section, click **Add group**.

    <Frame>![New origin group option in resource settings](/images/docs/cdn/add-an-origin-group/add-group-resource-settings.png)</Frame>
  </Step>
  <Step title="Enter the origin group name">
    Enter a unique **Origin group name**.

    <Frame>![Choose a new origin group in resource settings](/images/docs/cdn/add-an-origin-group/origin-group-name.png)</Frame>
  </Step>
  <Step title="Configure the origin group">
    Select the origin type and configure it as described in Origin group configuration.
  </Step>
  <Step title="Save the origin group">
    Click **Add group**.
  </Step>
  <Step title="Save the CDN resource">
    Click **Save changes**.
  </Step>
</Steps>

### From the Origin groups page

Groups created on the **Origin groups** page must be attached to a CDN resource after creation. See [Origin group attachment](#origin-group-attachment).

<Steps>
  <Step title="Open the origin groups page">
    In the Customer Portal, navigate to **CDN** > **Origin groups**.

    <Frame>![Origin groups page](/images/docs/cdn/add-an-origin-group/origin-groups-page.png)</Frame>
  </Step>
  <Step title="Open the creation form">
    Click **Add origin group**.
  </Step>
  <Step title="Enter the origin group name">
    Enter a unique **Origin group name**.
  </Step>
  <Step title="Configure the origin group">
    Select the origin type and configure it as described in Origin group configuration.
  </Step>
  <Step title="Save the origin group">
    Click **Add group**.
  </Step>
</Steps>

## Origin group attachment

<Info>
Changing a resource's origin group does not update its Host header. Update the [Host&nbsp;header](/cdn/cdn-resource-options/http-headers/configure-and-check-the-host-header#how-to-manage-the-host-header) separately.
</Info>

Attach a group created from the **Origin groups** page to its CDN resource.

<Steps>
  <Step title="Open the resource settings">
    In the Customer Portal, navigate to **CDN**, find the resource, and click its **CNAME**.
  </Step>
  <Step title="Select the origin group">
    In the **Pull content from** section, select the group from the **Origin group** dropdown and click **Add group**.

    <Frame>![Origin group selection in resource settings](/images/docs/cdn/add-an-origin-group/add-group-resource-settings.png)</Frame>
  </Step>
  <Step title="Save the resource">
    Click **Save changes**.
  </Step>
</Steps>

<p>CNAME flattening is a Gcore Managed DNS feature that resolves CNAME chains at the zone apex to A or AAAA records, bypassing the RFC 1034 restriction that prevents CNAME records from coexisting with mandatory NS and SOA records.</p>

## Zone apex record restrictions

<p>[CNAME&nbsp;records](/dns/dns-records#cname-record) are increasingly used to integrate domains with CDNs and other services that route traffic through dynamically assigned IP addresses. Using an A record, which specifies the concrete IP address that resolves the domain, may not be suitable in cases where IP addresses change frequently based on the geolocation of requests.</p>

<p>According to the RFC 1034 specification, a CNAME record cannot coexist with other records. Therefore, it is impossible to specify a CNAME record for the root domain, also known as the "apex domain" (e.g., sample-test.com), because it has mandatory NS and SOA records.</p>

<p>While using a subdomain (e.g., cdn.sample-test.com) for CNAME record creation can be sufficient, some website owners may want to integrate their root domain. For this situation, Gcore Managed DNS provides the CNAME flattening feature.</p>

## CNAME flattening mechanism

<p>CNAME flattening is a mechanism that allows specification restrictions to be bypassed, enabling a CNAME to be specified for the root domain. It resolves the CNAME chain and uses the IP address of the final A or AAAA record. This synthetic record is then cached, respecting its TTL, and used to answer subsequent DNS queries for the apex domain on the Gcore DNS side.</p>

<p>The local cache layer can also reduce resolution time by serving subsequent queries from the cached flattened response.</p>

## Configuration of CNAME flattening

<p>Gcore Managed DNS provides CNAME flattening to customers on all plans by default.</p>

<Steps>
  <Step title="Navigate to the Records tab">
    In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **DNS** → **Managed DNS**, click the zone name, and open the **Records** tab.
  </Step>
  <Step title="Remove conflicting records">
    Delete the A record and any other record types at the zone apex that would conflict with the CNAME record. Click the delete icon next to each conflicting record and confirm the deletion.

    NS and SOA records are mandatory and must remain — CNAME flattening exists precisely to handle their coexistence with the CNAME.

    <Frame>![Delete an A record at the root domain](/images/docs/dns/dns-records/specify-cname-at-root/specify-cname-at-root-image1.png)</Frame>
  </Step>
  <Step title="Add a CNAME record">
    Click **Add record** and configure the new record:

    1. Set **Type** to **CNAME**.
    2. In the **Name** field, enter the root domain.
    3. In the **Content** field, enter the target domain.
    4. Click **Add**.

    <Frame>![Add a CNAME record to the apex zone](/images/docs/dns/dns-records/specify-cname-at-root/specify-cname-at-root-image2.png)</Frame>
  </Step>
</Steps>

<p>Gcore Managed DNS supports CNAME flattening only when the zone apex contains a single CNAME record. Use the [Gcore&nbsp;DNS&nbsp;Lookup](https://gcore.com/dev-tools/dns-lookup) tool to verify the resolved value of the apex domain.</p>

</MethodSection>
  <MethodSection id="api" label="REST API">

<p>CNAME flattening at the zone apex requires two sequential API calls: delete all conflicting RRsets at the apex, then create the CNAME record. The zone apex record name is the zone name itself — for example, `example.com` for the `example.com` zone.</p>

<Note>
All conflicting RRsets must be deleted before the CNAME is created. NS and SOA records are mandatory and must remain. Creating a CNAME while any other record type exists at the apex returns HTTP 409: `"cname can't coexists with other records"`.
</Note>

<Info>
An [API token](/account-settings/api-tokens) is required.
</Info>

<p>Open a terminal and export the required variables:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export ZONE_NAME="{YOUR_ZONE_NAME}"         # e.g. example.com
export CNAME_TARGET="{YOUR_CNAME_TARGET}"   # e.g. cdn.example.com
```

## Configure CNAME flattening

<Accordion title="Show all steps">

### Step 1. Delete conflicting records at the zone apex

<p>The zone apex record name equals the zone name. Delete each conflicting RRset type separately — for a zone that has only an A record at the apex, run the call below once with `rrsetType=A`.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `zoneName` | Yes | The zone name |
| `rrsetName` | Yes | Same as `zoneName` for the apex |
| `rrsetType` | Yes | Record type to delete, e.g. `A` |

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os
    from gcore import Gcore

    client = Gcore()

    client.dns.zones.rrsets.delete(
        "A",
        zone_name=os.environ["ZONE_NAME"],
        rrset_name=os.environ["ZONE_NAME"],
    )
    print("A record deleted")
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/dns"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        _, err := client.DNS.Zones.Rrsets.Delete(ctx, "A", dns.ZoneRrsetDeleteParams{
            ZoneName:  os.Getenv("ZONE_NAME"),
            RrsetName: os.Getenv("ZONE_NAME"),
        })
        if err != nil {
            panic(err)
        }
        fmt.Println("A record deleted")
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X DELETE "https://api.gcore.com/dns/v2/zones/$ZONE_NAME/$ZONE_NAME/A" \
      -H "Authorization: APIKey $GCORE_API_KEY"
    ```

    <p>The API returns HTTP 200 with an empty body on success.</p>
  </Tab>
</Tabs>

### Step 2. Create the CNAME record at the zone apex

<p>The record name must equal the zone name. The `content` field holds the target domain that the CNAME points to — typically a CDN delivery domain or another service endpoint.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `zoneName` | Yes | The zone name |
| `rrsetName` | Yes | Same as `zoneName` for the apex |
| `rrsetType` | Yes | `CNAME` |
| `ttl` | Yes | Time to live in seconds |
| `resource_records[].content` | Yes | Target domain, e.g. `cdn.example.com` |

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os
    from gcore import Gcore

    client = Gcore()

    rrset = client.dns.zones.rrsets.create(
        "CNAME",
        zone_name=os.environ["ZONE_NAME"],
        rrset_name=os.environ["ZONE_NAME"],
        ttl=300,
        resource_records=[{"content": [os.environ["CNAME_TARGET"]]}],
    )
    print(rrset.name, rrset.type, (rrset.resource_records or [{}])[0].content)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/dns"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        rrset, err := client.DNS.Zones.Rrsets.New(ctx, "CNAME", dns.ZoneRrsetNewParams{
            ZoneName:  os.Getenv("ZONE_NAME"),
            RrsetName: os.Getenv("ZONE_NAME"),
            Ttl:       gcore.Int(300),
            ResourceRecords: []dns.ZoneRrsetNewParamsResourceRecord{
                {Content: []any{os.Getenv("CNAME_TARGET")}},
            },
        })
        if err != nil {
            panic(err)
        }
        fmt.Printf("%s %s -> %v\n", rrset.Name, rrset.Type, rrset.ResourceRecords[0].Content)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X POST "https://api.gcore.com/dns/v2/zones/$ZONE_NAME/$ZONE_NAME/CNAME" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{\"ttl\": 300, \"resource_records\": [{\"content\": [\"$CNAME_TARGET\"]}]}"
    ```

    <p>The API returns:</p>

    ```json
    {
      "name": "example.com",
      "type": "CNAME",
      "ttl": 300,
      "resource_records": [
        {"id": 1001, "content": ["cdn.example.com"], "enabled": true, "meta": {}}
      ],
      "warning": "according to the rfc1034 3.6.2: if a CNAME RR is present at a node, no other data should be present...",
      "warnings": [{"key": "cname_on_apex", "message": "..."}]
    }
    ```

    <p>The `warning` field is expected — Gcore Managed DNS accepts the CNAME at the apex and handles flattening transparently. The record is created successfully.</p>
  </Tab>
</Tabs>

<p>Dynamic response selects which records from an RRset are returned for a DNS query. **Pickers** define how records are selected, while **metadata** provides the values compared per query — country, ASN, subnet, coordinates, or weight.</p>

<p>The Continent picker with `continents: Africa` metadata, for instance, returns that record only to clients in Africa.</p>

## Configure dynamic response

<Steps>
  <Step title="Create a record set">
  Create a DNS record set in [advanced&nbsp;mode](/dns/dns-records/manage-dns-records-advanced-interface-mode-with-balancing#1-go-to-records-settings) (steps 1–4).
  </Step>
  <Step title="Enable the Dynamic response toggle">
  Turn on **Dynamic response**.
  </Step>
  <Step title="Select pickers">
  Select a preset, or add pickers manually. Pickers run in the order shown, top to bottom — drag to change priority.

  <Frame>![Dynamic response configuration](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/pickers-10.png)</Frame>
  </Step>
  <Step title="Specify the record value">
  Enter the DNS record value that this metadata applies to.
  </Step>
  <Step title="Set metadata">
  Add the metadata required by the selected pickers and specify its value. Use **+** to add another metadata field to the same record.
  </Step>
  <Step title="Add more records (optional)">
  Click **Add record** to add more records and repeat steps 4 and 5.
  </Step>
  <Step title="Save the configuration">
  Click **Create**.
  </Step>
</Steps>

### Available pickers

<p>Select pickers to define routing logic. Presets are editable — select a preset and then adjust picker order or add pickers manually.</p>

<Accordion title="Picker types">
The following pickers are available:

 * **GeoDistance.** Geo proximity to the latlong (latitude and longitude) in the metadata determines the record in the response; the fallback metadata will be ignored.
 * **Weighted shuffle.** Weight metadata determines the probability of the record hitting the response.
 * **Default.** Fallback metadata determines the record in the response if no other pickers were selected.
 * **ASN.** The match with the ASN (autonomous system number) in the metadata determines the record in the response.
 * **Country.** The match with the country in the metadata determines the record in the response.
 * **Continent.** The match with the continent in the metadata determines the record in the response.
 * **Region.** The match with the region in the metadata determines the record in the response.
 * **IP.** The match with IP address or CIDR notation (in IPv4 and IPv6) determines the record in the response.
 * **Healthcheck.** The record in the response is selected based on availability determined with [Healthcheck](/dns/dns-failover/configure-and-use-dns-failover).

The **First N** option is also in the list of pickers. It controls the maximum number of records used per response and is added to each preset. The default value is 1.
</Accordion>

### Available metadata

<p>Each record can carry one or more metadata fields. Add the fields required by the selected pickers.</p>

<Accordion title="Metadata types">
Ten metadata types are available:

 * asn (autonomous system number)
 * continents
 * countries
 * regions
 * latlong (latitude and longitude)
 * fallback (only used in the response if no other metadata type is selected)
 * backup (only used in combination with health checks to provide failover capability; if the rest of the records are not "healthy," backup records will be used to form an answer; if at least one non-backup record is "healthy," the record with the backup metadata does not participate in the response)
 * notes (any comments — a city name, data center name, or cluster name)
 * weight
 * ip (IP address or CIDR notation, IPv4 and IPv6)
</Accordion>

## Examples of preset settings

<Tabs>
  <Tab title="Geo DNS">
    With the "Geo DNS" preset, metadata of different types can be added to each record.

    <Warning>
    The latlong and weight metadata are ignored if the corresponding pickers are not added from the list.
    </Warning>

    Gcore evaluates matching metadata in picker order: IP → ASN → country → continent → region. If no criterion matches, it uses a record with `fallback=true`; if no fallback exists, the response is formed from the remaining records according to **First N**. Unhealthy records are excluded first when Health Checks are configured.

    **Example**: The "Geo DNS" preset is selected with one record per response in the First N.

    <Frame>![Configure Geo DNS preset](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/geo-dns-20.png)</Frame>

    Two records are added with IP metadata:

      * For `10.0.0.0` record, subnet 192.168.1.0/24
      * For `10.0.0.1` record, subnet 192.0.2.0/24

    <Frame>![Configure metadata](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/geo-dns-30.png)</Frame>

    A client with an IP from subnet 192.168.1.0/24 receives the record `10.0.0.0`. A client from subnet 192.0.2.0/24 receives the record `10.0.0.1`.

  </Tab>
  <Tab title="Geo distance">
    With the "Geo distance" preset, the resolver analyzes the proximity of the request's geolocation to the latlong (latitude and longitude) specified in the record's metadata. Clients receive the record with the nearest coordinates.

    **Example**: The "Geo distance" preset is selected with one record per response in the First N.

    <Frame>![Configure Geo distance preset](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/geo-distance-40.png)</Frame>

    Two records are added with the following coordinates:

      * For the `10.0.0.0` record, latlong _51.52318152049715/-0.13458412218999416_ (central London)
      * For the `10.0.0.1` record, latlong _48.859741241898114/2.3415648470109653_ (central Paris)

    <Frame caption="The orange color shows where two zones are close together, while the red and yellow show distinct zones">![Configure metadata](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/geo-distance-50.png)</Frame>

    A client closer to 51.52318152049715/-0.13458412218999416 (central London) receives an A record with the value `10.0.0.0`. A client closer to _48.859741241898114/2.3415648470109653_ (central Paris) receives an A record with the value `10.0.0.1`.
  </Tab>
  <Tab title="Weighted shuffle">
    With the "Weighted shuffle" preset, the probability of a particular record appearing in the answer is controlled by specifying its weight.

    <Info>
    If the metadata field "weight" is left empty, a default value of 50, 33.3, or 25 is applied depending on the number of records. Each record without an explicit weight has equal probability.
    </Info>

    When the number of resource records exceeds First N, probability determines which records appear per response. A record's probability is its weight divided by the sum of the weights of all participating records:

    ```sh
    P1= W1 / Sumi(Wi)
    ```

    **Example**: The "Weighted shuffle" preset is enabled with max one record per response in the First N:

    <Frame>![Configure Weighted shuffle picker](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/weighted-shuffle-60.png)</Frame>

    Metadata is specified as follows:

      * _1.2.3.4_ with the "weight" 90, probability = 0.6
      * _4.5.6.7_ with the "weight" 10, probability = 0.06(6)
      * _7.8.9.0_ with the "weight" empty (i.e., set by default to 50), probability = 0.3(3)

    <Frame>![Configure records for weighted shuffle usage](/images/docs/dns/dns-records/configure-weight-balancing-and-geobalancing/weighted-shuffle-70.png)</Frame>

    Over the course of 300 answers, each record appears with the following frequency:

      * `~180` responses with the record `1.2.3.4` (weight 90)
      * `~20` responses with the record `4.5.6.7` (weight 10)
      * `~100` responses with the record `7.8.9.0` (weight 50)
  </Tab>
</Tabs>

</MethodSection>
  <MethodSection id="api" label="REST API">

<p>Dynamic response is configured on the RRset level. Each record in `resource_records` carries a `meta` object with routing criteria, and the `pickers` array defines the strategy the resolver uses to select a record per query. The `first_n` picker controls how many records appear in each response.</p>

<Info>
An [API&nbsp;token](/account-settings/api-tokens) is required.
</Info>

<p>Export these variables:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export ZONE_NAME="{YOUR_ZONE_NAME}"
export RECORD_NAME="{RECORD_FQDN}"
```

<p>`RECORD_NAME` is the fully qualified domain name (FQDN) of the record. For an apex record it equals `ZONE_NAME`; for a subdomain it is the full FQDN — `www.example.com`.</p>

## Weighted shuffle

<p>Weighted shuffle distributes queries across records based on their `weight` metadata value — higher weight means the record appears more often, proportional to its weight relative to the total. Use the `weighted_shuffle` picker together with `first_n` to limit the number of records per response.</p>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()

rrset = client.dns.zones.rrsets.create(
    "A",
    zone_name=os.environ["ZONE_NAME"],
    rrset_name=os.environ["RECORD_NAME"],
    resource_records=[
        {"content": ["1.2.3.4"], "meta": {"weight": 90}},
        {"content": ["4.5.6.7"], "meta": {"weight": 10}},
        {"content": ["7.8.9.0"], "meta": {"weight": 50}},
    ],
    pickers=[
        {"type": "weighted_shuffle"},
        {"type": "first_n", "limit": 1},
    ],
    ttl=300,
)
print(rrset.name, rrset.pickers)
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "context"
    "fmt"
    "os"

    gcore "github.com/G-Core/gcore-go"
    "github.com/G-Core/gcore-go/dns"
)

func main() {
    client := gcore.NewClient()
    ctx := context.Background()

    rrset, err := client.DNS.Zones.Rrsets.New(ctx, "A", dns.ZoneRrsetNewParams{
        ZoneName:  os.Getenv("ZONE_NAME"),
        RrsetName: os.Getenv("RECORD_NAME"),
        ResourceRecords: []dns.ZoneRrsetNewParamsResourceRecord{
            {Content: []any{"1.2.3.4"}, Meta: map[string]any{"weight": 90}},
            {Content: []any{"4.5.6.7"}, Meta: map[string]any{"weight": 10}},
            {Content: []any{"7.8.9.0"}, Meta: map[string]any{"weight": 50}},
        },
        Pickers: []dns.ZoneRrsetNewParamsPicker{
            {Type: "weighted_shuffle"},
            {Type: "first_n", Limit: gcore.Int(1)},
        },
        Ttl: gcore.Int(300),
    })
    if err != nil {
        panic(err)
    }
    fmt.Println(rrset.Name, rrset.Pickers)
}
```

## Geo DNS

<p>Geo DNS routes queries based on the client's geolocation. The resolver evaluates IP, ASN, country, continent, and region metadata in that order and uses the first criterion that produces a match. Add a record with `"fallback": true` to handle queries that match no other criteria. Use `first_n` to limit how many matching records appear in the response. Set `meta.countries` to two-letter ISO 3166-1 alpha-2 country codes.</p>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()

rrset = client.dns.zones.rrsets.create(
    "A",
    zone_name=os.environ["ZONE_NAME"],
    rrset_name=os.environ["RECORD_NAME"],
    resource_records=[
        {"content": ["10.0.0.1"], "meta": {"countries": ["de", "at"]}},
        {"content": ["10.0.0.2"], "meta": {"countries": ["fr", "be"]}},
        {"content": ["10.0.0.3"], "meta": {"fallback": True}},
    ],
    pickers=[
        {"type": "geodns"},
        {"type": "first_n", "limit": 1},
    ],
    ttl=300,
)
print(rrset.name, rrset.pickers)
```

## Geo distance

<p>Geo distance routes queries to the record whose coordinates are closest to the client's geolocation. Use the `geodistance` picker with `meta.latlong` set to a two-element array `[latitude, longitude]` in decimal degrees.</p>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()

rrset = client.dns.zones.rrsets.create(
    "A",
    zone_name=os.environ["ZONE_NAME"],
    rrset_name=os.environ["RECORD_NAME"],
    resource_records=[
        {"content": ["10.0.0.1"], "meta": {"latlong": [51.52, -0.13]}},
        {"content": ["10.0.0.2"], "meta": {"latlong": [48.86, 2.34]}},
    ],
    pickers=[
        {"type": "geodistance"},
        {"type": "first_n", "limit": 1},
    ],
    ttl=300,
)
print(rrset.name, rrset.pickers)
```

RTMP (port 1935) and RTMPS (port 443, TLS-encrypted) are the standard ingest protocols for live streaming encoders connecting to Gcore Streaming. Encoders push streams to Gcore ingest points using a server URL and stream key; Gcore transcodes the incoming stream for delivery.

## Main principles

RTMP is an ingest protocol — it receives streams from encoders and is not used for playback. RTMPS wraps RTMP in TLS, enabling encrypted transport through restrictive firewalls.

Configure the encoder with these settings before connecting:

- Video codec and bitrate: [input&nbsp;codecs](/streaming/live-streams-and-videos-protocols-and-codecs/input-parameters-and-codecs)
- Keyframe interval: `1sec`
- CPU usage preset: `veryfast`
- Profile: `baseline`
- Tune: `zerolatency`
- x264/x265 options: `rc-lookahead=0:bframes=0:scenecut=0`

<Info>
  RTMP only supports H.264 video + AAC audio. For other codecs (e.g. H.265/HEVC), use [SRT](/streaming/live-streaming/protocols/srt) ingest.
</Info>

Frame rate handling differs from codec selection: the encoder FPS is read once at session start and is not updated mid-stream.

<Info>
  Live transcoding reads the encoder FPS once at session start and does not update it mid-stream. If the source FPS degrades after connection, the encoder must reconnect with corrected settings.
</Info>

Both PUSH and PULL ingest modes are available for RTMP.

## PUSH streams

Use RTMP PUSH when the encoder can establish an outbound connection to Gcore Streaming. This is the best choice for:
- Software encoders — OBS, ffmpeg.
- Hardware encoders — Elemental, Haivision.
- Workflows that do not require an always-on origin server.

Configure the encoder with the exact ingest parameters: server URL, backup URL (if used), and stream key.

To use RTMPS, change the protocol name from `rtmp://` to `rtmps://`.

The ingest URL format is `rtmp://vp-push-ed1.gvideo.co/in/12345?aaabbbcccddd`, where:

- `rtmp://` or `rtmps://` — protocol
- `vp-push-ed1` — ingest server and geographic location (Europe in this example)
- `12345?aaabbbcccddd` — stream key

For encoders that do not support query strings, use the path-segment form: `rtmp://vp-push-ed1.gvideo.co/in/12345/aaabbbcccddd`.

The ffmpeg command below generates a test video (1280×720 @30fps) with a two-kHz audio tone and pushes it over RTMP:
```sh
ffmpeg -re -f lavfi -i testsrc2=size=1280x720:rate=30 \
       -f lavfi -i sine=f=2000:r=48000 \
       -c:v libx264 -preset veryfast -b:v 1M -g 30 \
       -c:a aac -b:a 128k -ar 48000 \
       -f flv "rtmp://vp-push-ed1.gvideo.co/in/12345?aaabbbcccddd"
```

<Info>
If the stream experiences transcoding or playback problems, changing the ingest server location may help. Contact support to update the ingest region — the [ingest&nbsp;region&nbsp;guide](/streaming/live-streaming/primary-backup) covers available locations.
</Info>


### Obtain the server URLs and stream key

There are two ways to obtain the server URLs and stream key: Customer Portal UI or API.

#### Via UI

1. In the **Gcore Customer Portal**, navigate to **Streaming** \> [Live&nbsp;Streaming](https://portal.gcore.com/streaming/streaming/list).

<Frame>
  <img src="https://assets.gcore.pro/docs/streaming-platform/live-streaming/create-a-live-stream/live-stream-list.png" alt="List of live streams" width="70%" />
</Frame>

2. Click the stream to open **Live stream settings**.

<Frame>
  <img src="https://assets.gcore.pro/docs/streaming-platform/live-streaming/create-a-live-stream/live-stream-settings.png" alt="Live stream settings" width="70%" />
</Frame>

3. Set **Ingest type** to **Push**.
4. In the **URLs for encoder** section, select **RTMP** or **RTMPS**.
5. Copy the **Server** URL and **Stream Key**.
6. Optionally, copy the **Backup Server** URL and **Backup Stream Key** for a redundant ingest path.

<Frame>
  <img src="https://assets.gcore.pro/docs/streaming-platform/live-streaming/create-a-live-stream/urls-for-encoder.png" alt="URLs for encoder section" width="70%" />
</Frame>


#### Via API

The Gcore API also returns the complete ingest URLs and stream key. The endpoint includes both primary and backup ingest point URLs.

Example of the API request:

```http
GET /streaming/streams/{stream_id}
```

Example of API response:

```json
{
  "push_url": "rtmp://vp-push-anx2.domain.com/in/123?08cd54f0",
  "backup_push_url": "rtmp://vp-push-ed1.domain.com/in/123b?08cd54f0",
  ...
}
```

The [create&nbsp;stream&nbsp;API](/api-reference/streaming/streams/create-live-stream) endpoint returns the complete URL and stream key fields.


## Ingest Limits

<Info>
Only one ingest protocol type can be used for a live stream at a time.
Pushing RTMP and another protocol (e.g., SRT) to the same stream at once will cause transcoding to fail.
</Info>

The ingester timeout is 3 sec (3000 ms). If no data arrives in that window, the connection is discarded as inactive and the encoder must reconnect.


## PULL streams

Gcore Streaming can PULL video data from the source.

Pull requirements:
- The source URL must be **publicly available** and **return data** for all requests.
- To allowlist Gcore network ranges, contact support for the current IP list.

### Setting up a PULL stream

There are two ways to set up a pull stream: via the Gcore Customer Portal or via the API.

#### Via UI

1. In the **Gcore Customer Portal**, navigate to **Streaming** \> [Live&nbsp;Streaming](https://portal.gcore.com/streaming/streaming/list).

<Frame>
  <img src="https://assets.gcore.pro/docs/streaming-platform/live-streaming/create-a-live-stream/live-stream-list.png" alt="List of live streams" width="70%" />
</Frame>

2. Click the stream to open **Live stream settings**.

<Frame>
  <img src="https://assets.gcore.pro/docs/streaming-platform/live-streaming/create-a-live-stream/live-stream-settings.png" alt="Live stream settings" width="70%" />
</Frame>

3. Set **Ingest type** to **Pull**.
4. In the **URL** field, enter the source stream URL.
5. Click **Save changes**.

#### Via API

The Gcore API also supports pull stream setup. The endpoint accepts the source stream URL.

Example of API request:

```http
PATCH /streaming/streams/{stream_id}
```

```json
{
  "stream": {
    "pull": true,
    "uri": "rtmp://example.com/path/to/stream",
    ...
  }
}
```

The [update&nbsp;stream&nbsp;API](/api-reference/streaming/streams/change-live-stream) endpoint accepts the pull URL in the request body.


## Primary, Backup, and Global Ingest Points

One primary ingest point with the default region is sufficient for most deployments.
For high-latency or unstable-connectivity scenarios, Gcore Streaming supports a backup ingest point and explicit ingest region selection.

The [backup&nbsp;ingest&nbsp;guide](/streaming/live-streaming/primary-backup) covers region selection and failover configuration.

## RTMP/S Troubleshooting

### Inappropriate codec for RTMP

**Cause:** RTMP only carries H.264 video and AAC audio. Other codecs — H.265/HEVC, AV1, MP3, Opus — are not supported in the native RTMP protocol. Enhanced RTMP is not yet available.

In the encoder, confirm that the video output codec is H.264 and the audio output codec is AAC.

### SSL issues

**Cause:** The encoder is configured with `rtmp://` but `rtmps://` is required, or an incorrect port is used.

Verify the protocol in the encoder settings. The [stream&nbsp;setup&nbsp;steps](/streaming/live-streaming/create-a-live-stream#step-3-configure-your-stream-for-push-pull-or-webrtc-to-hls) list the required RTMPS encoder values.

For port issues, add port 443 explicitly:

```
rtmps://vp-push-ed1.gvideo.co:443/in/
```

### No transcoding or image degradation with web cameras

**Cause:** H264+ codec extension uses an over-increased keyframe interval.

Check the outgoing stream parameters:

- Streams must be encoded using H.264 — custom codecs (H264+) are not supported.
- Smart codec modes must be disabled.

### Connection timed out

**Cause:** The server URL is incorrect, or the encoder does not support RTMPS.

Check the server URL in the encoder settings and verify the protocol is `rtmps://`.

If the encoder does not support RTMPS, switch to an encoder that does.

<p>RTMP (port 1935) and RTMPS (port 443, TLS-encrypted) are the standard ingest protocols for live streaming encoders connecting to Gcore Streaming. Encoders push streams to Gcore ingest points using a server URL and stream key; Gcore transcodes the incoming stream for delivery.</p>

## RTMP/S requirements

<p>Gcore RTMP ingest supports H.264 video with AAC audio. Other codecs — H.265/HEVC, AV1, MP3, Opus — require [SRT](/streaming/live-streaming/protocols/srt) ingest instead.</p>

<p>Required encoder settings:</p>

- Codec: H.264 video, AAC audio
- Keyframe interval: `1sec`

<Info>
  Live transcoding reads the encoder frame rate when the session starts. If the source FPS changes after the connection is established, the encoder must reconnect with the corrected settings.
</Info>

<p>RTMP supports two ingest modes: PUSH and PULL.</p>

## PUSH streams

<p>In PUSH mode, the encoder establishes the connection and sends the stream to a Gcore ingest point. This mode works with software encoders (OBS, ffmpeg) and hardware encoders (Elemental, Haivision).</p>

### Obtain the server URL and stream key

<p>Before configuring the encoder, retrieve the ingest URL and stream key from the Customer Portal.</p>

1. In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **Streaming** \> [Live&nbsp;Streaming](https://portal.gcore.com/streaming/streaming/list).

<Frame>
  ![List of live streams](/images/docs/streaming/live-streaming/protocols/rtmp/rtmp-live-stream-list.png)
</Frame>

2. Click the stream to open **Live stream settings**.

<Frame>
  ![Live stream settings with Ingest type options](/images/docs/streaming/live-streaming/protocols/rtmp/rtmp-live-stream-settings.png)
</Frame>

3. Set **Ingest type** to **Push**.
4. In the **URLs for encoder** section, select **RTMP** or **RTMPS**.
5. Copy the **Server** URL and **Stream Key**.
6. (Optional) Copy the **Backup Server** URL and **Backup Stream Key** for a redundant ingest path.

<Frame>
  ![URLs for encoder section with RTMP protocol selected](/images/docs/streaming/live-streaming/protocols/rtmp/rtmp-urls-for-encoder.png)
</Frame>

### Configure the encoder

<p>Enter the server URL and stream key from the previous step into the encoder. The ingest URL format is:</p>

```
rtmp://vp-push-ed1.gvideo.co/in/12345?aaabbbcccddd
```

<p>Where:</p>

- `rtmp://` or `rtmps://` — protocol (`rtmps://` uses TLS on port 443 for encrypted transport)
- `vp-push-ed1` — ingest server and geographic region (Europe)
- `12345?aaabbbcccddd` — stream key

<p>For encoders that do not support query strings, use the path-segment form:</p>

```
rtmp://vp-push-ed1.gvideo.co/in/12345/aaabbbcccddd
```

### Low-latency tuning

<p>These settings are recommended for low-latency streaming:</p>

- CPU usage preset: `veryfast`
- Profile: `baseline`
- Tune: `zerolatency`
- x264 options: `rc-lookahead=0:bframes=0:scenecut=0`

### Test with ffmpeg

<p>The ffmpeg command below generates a test video (1280×720 @30fps) with a two-kHz audio tone and pushes it over RTMP. At 30 fps, `-g 30` produces a one-second keyframe interval, matching the required `1sec` setting.</p>

```sh
ffmpeg -re -f lavfi -i testsrc2=size=1280x720:rate=30 \
       -f lavfi -i sine=f=2000:r=48000 \
       -c:v libx264 -preset veryfast -b:v 1M -g 30 \
       -c:a aac -b:a 128k -ar 48000 \
       -f flv "rtmp://vp-push-ed1.gvideo.co/in/12345?aaabbbcccddd"
```

### Backup and regional ingest

<p>By default, one primary ingest point handles all traffic. For redundancy or when network connectivity to the ingest point is unstable, Gcore supports a backup ingest URL and explicit region selection — the [backup&nbsp;ingest&nbsp;guide](/streaming/live-streaming/primary-backup) covers available options. Contact support to change the ingest region.</p>

## PULL streams

<p>In PULL mode, Gcore connects to a publicly available source URL and retrieves the stream.</p>

<p>Source requirements:</p>

- The source URL must be publicly accessible and respond to all requests from Gcore.
- To allowlist Gcore IP ranges on the source side, contact support for the current list.

### Configure the pull URL

1. In the Customer Portal, navigate to **Streaming** \> [Live&nbsp;Streaming](https://portal.gcore.com/streaming/streaming/list).

<Frame>
  ![List of live streams](/images/docs/streaming/live-streaming/protocols/rtmp/rtmp-live-stream-list.png)
</Frame>

2. Click the stream to open **Live stream settings**.

<Frame>
  ![Live stream settings with Ingest type options](/images/docs/streaming/live-streaming/protocols/rtmp/rtmp-live-stream-settings.png)
</Frame>

3. Set **Ingest type** to **Pull**.
4. In the **URL** field, enter the source stream URL.
5. Click **Save changes**.

## Ingest limits

<p>Only one ingest protocol can be active for a live stream at a time — pushing RTMP and SRT simultaneously to the same stream causes transcoding to fail.</p>

<p>The ingester timeout is 3 seconds. If no data arrives within that window, the connection is closed and the encoder must reconnect.</p>

## RTMP/S troubleshooting

### Incompatible codec

<p>Gcore RTMP ingest supports H.264 video and AAC audio only. Other codecs — H.265/HEVC, AV1, MP3, Opus — are not supported. Enhanced RTMP is not yet available.</p>

<p>In the encoder, verify that the video output codec is H.264 and the audio output codec is AAC.</p>

### SSL issues

<p>Possible causes include a mismatch between the protocol in the encoder (`rtmp://` vs `rtmps://`) or an incorrect port.</p>

<p>Verify the protocol in the encoder settings. The [stream&nbsp;setup&nbsp;steps](/streaming/live-streaming/create-a-live-stream#step-3-configure-your-stream-for-push-pull-or-webrtc-to-hls) list the required RTMPS encoder values.</p>

<p>If the port is the issue, specify port 443 explicitly:</p>

```
rtmps://vp-push-ed1.gvideo.co:443/in/
```

### No transcoding or image degradation with web cameras

<p>Possible cause: H264+ or Smart Codec mode is enabled on the camera.</p>

<p>Check the outgoing stream parameters:</p>

- Streams must be encoded using H.264 — custom codecs (H264+) are not supported.
- Smart codec modes must be disabled.

<Frame>
  ![Web camera codec settings showing H.264 encode mode and Smart Codec off](/images/docs/streaming/live-streaming/protocols/rtmp/rtmp-web-camera-codec-settings.png)
</Frame>

### Connection timed out

<p>Possible causes include an incorrect server URL, a firewall blocking port 1935 (RTMP) or 443 (RTMPS), or an encoder that does not support RTMPS.</p>

<p>Verify the server URL and protocol in the encoder settings. If the encoder does not support RTMPS, switch to one that does or use RTMP on port 1935.</p>

## Get push ingest credentials

<p>Returns the RTMP server URL and stream key for the specified stream. Use the returned `push_url` value directly as the server address in the encoder — it includes the stream key as a query string.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `stream_id` | Yes | Stream ID. |

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os
    from gcore import Gcore

    client = Gcore()
    stream = client.streaming.streams.get(int(os.environ["STREAM_ID"]))

    print("Server URL + stream key:", stream.push_url)
    print("Backup URL + stream key:", stream.backup_push_url)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

        stream, err := client.Streaming.Streams.Get(ctx, streamID)
        if err != nil {
            panic(err)
        }

        fmt.Println("Server URL + stream key:", stream.PushURL)
        fmt.Println("Backup URL + stream key:", stream.BackupPushURL)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -s "https://api.gcore.com/streaming/streams/$STREAM_ID" \
      -H "Authorization: APIKey $GCORE_API_KEY"
    ```

    <p>The API returns:</p>

    ```json
    {
      "id": 12345,
      "push_url": "rtmp://vp-push-ed2.gvideo.co/in/12345?ba6b6cffc3eece9258bae1fa666fc816",
      "backup_push_url": "rtmp://vp-push-anx1.gvideo.co/in/12345b?ba6b6cffc3eece9258bae1fa666fc816",
      "pull": false
    }
    ```

    <p>`push_url` is the primary RTMP ingest endpoint. `backup_push_url` provides a redundant ingest path. Both values include the stream key as a query string.</p>

## Configure pull ingest

<p>Switches a stream to pull mode and sets the source URL. Gcore connects to the specified URL and retrieves the stream. To configure failover, pass multiple source URLs separated by a space — Gcore cycles through them using round-robin if the active source stops sending data.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `stream_id` | Yes | Stream ID. |
| `pull` | Yes | Set to `true` to enable pull mode. |
| `uri` | Yes | Source URL. Separate multiple URLs with a space for round-robin failover. |

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os
    from gcore import Gcore

    client = Gcore()
    stream = client.streaming.streams.update(
        stream_id=int(os.environ["STREAM_ID"]),
        stream={
            "pull": True,
            "uri": os.environ["SOURCE_URL"],
        },
    )

    print("Pull mode:", stream.pull)
    print("Source URL:", stream.uri)
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/streaming"
    )

    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

        // Retrieve the current stream name — required by the SDK for updates
        stream, err := client.Streaming.Streams.Get(ctx, streamID)
        if err != nil {
            panic(err)
        }

        updated, err := client.Streaming.Streams.Update(ctx, streamID,
            streaming.StreamUpdateParams{
                Stream: streaming.StreamUpdateParamsStream{
                    Name: stream.Name,
                    Pull: gcore.Bool(true),
                    Uri:  gcore.String(os.Getenv("SOURCE_URL")),
                },
            },
        )
        if err != nil {
            panic(err)
        }

        fmt.Printf("Pull mode: %v\n", updated.Pull)
        fmt.Printf("Source URL: %s\n", updated.Uri)
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -s -X PATCH "https://api.gcore.com/streaming/streams/$STREAM_ID" \
      -H "Authorization: APIKey $GCORE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"stream": {"pull": true, "uri": "rtmp://source.example.com/live/stream"}}'
    ```

    <p>The API returns the updated stream object:</p>

    ```json
    {
      "id": 12345,
      "pull": true,
      "uri": "rtmp://source.example.com/live/stream"
    }
    ```

    <p>To configure failover between two source URLs:</p>

    ```bash
    -d '{"stream": {"pull": true, "uri": "rtmp://primary.example.com/live/stream rtmp://backup.example.com/live/stream"}}'
    ```
  </Tab>
</Tabs>

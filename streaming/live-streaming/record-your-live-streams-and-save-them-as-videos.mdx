## What is the record feature

<p>Record is a feature that allows you to record your live streams and store them in the Streaming storage. You can automatically record entire streams or manually record only desired fragments.</p>

<p>Recording and live transcoding are separate, independent workflows. Recording saves the incoming stream for later processing and export, while the live transcoder builds the live playback session from the source metadata read once when the encoder connects.</p>

## How to record a live stream

### How to record a live stream

<p>To record a live stream manually:</p>

<p>1\. Start a live stream in your encoder.</p>

<p>2\. Open the settings of the desired live stream.</p>

<p>3\. Press the **Start record** button.</p>


<Frame>![Start record button](/images/docs/streaming-platform/live-streaming/record-your-live-streams-and-save-them-as-videos/live-streaming-record.png)</Frame>



<p>After 5–10 seconds, the recording will start. You will see the timer and the **Stop record** button.</p>


<Frame>![recording](/images/docs/streaming-platform/live-streaming/record-your-live-streams-and-save-them-as-videos/9612975948817.png)</Frame>



<p>In cases of accidentally interrupting the live stream (bad internet connection, broken cable, etc.), recording will be continued when the live stream resumes. The recording will be saved as one video if the interruption is less than one minute. The recording will be divided into several videos if the interruptions are more than one minute.</p>

<p>4\. If you want to record not the whole live stream, but a certain fragment of it, press the **Stop record** button at the desired moment. The fragment will be saved. Please note: it must be 10 seconds or longer.</p>

<p>If you want to record the whole live stream, don't press the **Stop** button. The recording will stop automatically. Please note: recordings longer than 4 hours will be divided into fragments of 4 hours each—this is the optimal fragment size for video processing.</p>

<p>After stopping and processing, the recording will be saved in the Streaming Storage.</p>

## Where the records are kept

<p>After you record a stream, the recording is saved on the **Live Streaming** page. To view the recorded stream:</p>

<p>1\. Navigate to [Streaming](https://portal.gcore.com/streaming/streaming) > **Live Streaming**.</p>


<Frame>![Videos tab](/images/docs/streaming-platform/live-streaming/record-your-live-streams-and-save-them-as-videos/live-stream-storage.png)</Frame>


<p>2\. Click the stream name to open its settings.</p>

<p>3\. Navigate to the **Links for the export** section. Here you can copy the iFrame code to embed the recording on your website and download the recording of the quality you want.</p>


<Frame>![Export tab](/images/docs/streaming-platform/live-streaming/record-your-live-streams-and-save-them-as-videos/live-streams-export-iframe.png)</Frame>

## Record original stream

<p>Original recording saves the raw incoming stream (RTMP, SRT, or other protocol) without transcoding. The file preserves the original quality, framerate, codecs, and all source parameters exactly as sent by your encoder.</p>

<Warning>
Original recording is a premium feature. Contact your account manager or [Gcore support](mailto:support@gcore.com) to enable it for your account.
</Warning>

### Benefits

| Benefit | Description |
|---------|-------------|
| **Fast availability** | Original file is available for download approximately 30 seconds after the stream ends. No transcoding wait time. |
| **Original quality** | Preserves source bitrate, resolution, framerate, and codec settings without re-encoding. |
| **Quick turnaround** | Ideal for video editors who need raw footage immediately after broadcast. |

### How to enable

<p>Original recording is enabled by setting `record_type` to `origin` when creating or updating a stream via the API.</p>

### Storage limits

<Warning>
Original recordings are stored for **7 days only**. After 7 days, the original file is automatically deleted.

Transcoded renditions are not affected and remain available indefinitely.
</Warning>

## How recording interacts with live transcoding

<p>Because of this, a saved recording may still look correct even if the live stream session started with degraded source FPS or unstable source timestamps.</p>

<p>Recording also preserves technical changes that happen later inside the incoming live stream. If the source stream changes pixel format, color range, codec parameters, or similar properties during the broadcast, the recording may still be saved, but later VOD processing of that recording can fail because the recorded file now contains inconsistent source parameters.</p>

```text
Simplified MP4 timeline:

time ------------------------------------------------------------------------------>

| MP4 headers + metadata | stable video samples | parameter change | later samples |
| ftyp | moov            | mdat: yuv420p        | yuv420p->yuvj420p| mdat: changed |

                        OK for decoder/transcoder
                                              ^
                                              |
                         from this point, later video data may decode incorrectly,
                         show artifacts, fail validation, or stop transcoding
```

<p>In a simplified MP4 view, the file begins with container headers and stream description metadata, for example `ftyp` and `moov`, while the encoded video/audio payload is stored in `mdat`.</p>

<p>Inside `moov`, MP4 stores the track description and sample tables that tell downstream tools how to interpret the later samples. In practice this includes boxes such as `trak`, `mdia`, `stbl`, `stsd`, and timing/index tables like `stts`, `ctts`, `stss`, `stsc`, `stsz`, and `stco`/`co64`.</p>

<p>If the live source changes parameters in the middle of the recording, the later samples inside `mdat` may no longer match the stream description assumed at the beginning of the file, or may require a mid-file sample-description change that the workflow does not support. Starting from that change point, decoders and transcoders may see corrupted frames, reject the file, or fail during later processing.</p>

<Info>
If this has already happened in a saved recording, in many cases there may be no complete corrective action available afterward. If the recording is business-critical, contact the Support Team as soon as possible while source-side artifacts or temporary raw data may still be available for investigation. In some cases, our engineers may be able to recover part of the file or prepare a trimmed/restored version, but this is always best-effort work and cannot be guaranteed.
</Info>


<p>If your live playback is unexpectedly running at 10-12 fps while the recording looks smooth, this usually means the live transcoder read low source FPS metadata at the beginning of the live session. This FPS value is not re-read later, and Gcore does not upscale live frame rate dynamically during the session. After fixing the encoder settings, the customer must reconnect the live stream from the encoder side to start a new session with the correct source metadata.</p>

```text
LIVE ENCODER
  first part of stream: stable parameters
  example: yuv420p
            |
            +----------------------> LIVE TRANSCODER
            |                         uses live session rules
            |
            +----------------------> RECORDING WORKFLOW
                                      stores source as received

... later during the same broadcast ...

LIVE ENCODER
  source parameters change mid-stream
  example: yuv420p -> yuvj420p
            |
            +----------------------> LIVE TRANSCODER
            |                         may continue, degrade, or fail
            |                         depending on the type of change
            |
            +----------------------> RECORDING WORKFLOW
                                      stores the changed segment too

RECORDED FILE RESULT
  beginning: yuv420p
  ending:    yuvj420p
            |
            v
LATER VOD PROCESSING / EXPORT OF RECORDING
  sees mixed source parameters inside one file
  may fail, enter Error status, or require trimming
  of the broken segment before reprocessing
```

## Configure recording settings

<p>Set `auto_record` and `record_type` on an existing stream. When `auto_record` is `true`, recording starts automatically whenever the encoder connects. When `false`, recording must be started manually. `record_type` controls whether the raw ingest (`origin`) or the transcoded output (`transcoded`) is saved.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `auto_record` | No | `true` to record automatically when the stream goes live |
| `record_type` | No | `origin` — raw RTMP/SRT source; `transcoded` — processed output with overlays |

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

stream = client.streaming.streams.update(
    stream_id,
    stream={
        "auto_record": True,
        "record_type": "transcoded",
    },
)
print(f"Stream {stream.id}: auto_record={stream.auto_record}, record_type={stream.record_type}")
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "context"
    "fmt"
    "os"
    "strconv"

    gcore "github.com/G-Core/gcore-go"
    "github.com/G-Core/gcore-go/packages/param"
    "github.com/G-Core/gcore-go/streaming"
)

func main() {
    client := gcore.NewClient()
    ctx := context.Background()

    streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

    // GET the current stream to read its name — required field for Update
    existing, err := client.Streaming.Streams.Get(ctx, streamID)
    if err != nil {
        panic(err)
    }

    stream, err := client.Streaming.Streams.Update(ctx, streamID, streaming.StreamUpdateParams{
        Stream: streaming.StreamUpdateParamsStream{
            Name:       existing.Name,
            AutoRecord: param.NewOpt(true),
            RecordType: "transcoded",
        },
    })
    if err != nil {
        panic(err)
    }
    fmt.Printf("Stream %d: auto_record=%v, record_type=%v\n",
        stream.ID, stream.AutoRecord, stream.RecordType)
}
```
  </Tab>
  <Tab title="curl">
```bash
curl -X PATCH "https://api.gcore.com/streaming/streams/$STREAM_ID" \
     -H "Authorization: APIKey $GCORE_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "auto_record": true,
       "record_type": "transcoded"
     }'
```

<p>The API returns the full updated stream object. The relevant fields:</p>

```json
{
  "id": 4518917,
  "auto_record": true,
  "record_type": "transcoded",
  "recording": false,
  "recording_duration": null
}
```

## Start recording manually

<p>Start recording a specific stream on demand. The stream must be live (actively receiving an ingest signal) when this call is made — recording initializes within 3–7 seconds. After recording starts, `recording` switches to `true` on the stream object and `recording_duration` counts up in seconds.</p>

<Info>
The Go SDK returns an error for this endpoint due to a bug with empty 204 responses. Use the raw HTTP helper shown below until the SDK is fixed.
</Info>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

client.streaming.streams.start_recording(stream_id)
print(f"Recording started for stream {stream_id}")
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "fmt"
    "io"
    "net/http"
    "os"
    "strconv"
)

// startRecording uses raw HTTP because the Go SDK does not handle
// the 204 No Content response from this endpoint correctly.
func startRecording(streamID int64) error {
    apiKey := os.Getenv("GCORE_API_KEY")
    url := fmt.Sprintf("https://api.gcore.com/streaming/streams/%d/start_recording", streamID)
    req, _ := http.NewRequest("PUT", url, nil)
    req.Header.Set("Authorization", "APIKey "+apiKey)
    req.Header.Set("Content-Type", "application/json")
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return err
    }
    defer resp.Body.Close()
    io.ReadAll(resp.Body)
    if resp.StatusCode != 204 && resp.StatusCode != 200 {
        return fmt.Errorf("unexpected status: %d", resp.StatusCode)
    }
    return nil
}

func main() {
    streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

    if err := startRecording(streamID); err != nil {
        panic(err)
    }
    fmt.Printf("Recording started for stream %d\n", streamID)
}
```
  </Tab>
  <Tab title="curl">
```bash
curl -X PUT "https://api.gcore.com/streaming/streams/$STREAM_ID/start_recording" \
     -H "Authorization: APIKey $GCORE_API_KEY" \
     -H "Content-Type: application/json"
```

<p>Returns `204 No Content` when recording starts successfully. If the stream is not live, the recording task is queued and will begin when the stream goes live.</p>

## Stop recording

<p>Stop an active recording. The stream does not have to be taken offline — only recording stops. The saved video entity is returned and becomes available in Streaming Storage.</p>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

video = client.streaming.streams.stop_recording(stream_id)
print(f"Recording saved as video {video.id}: {video.name}")
```

## Retrieve recordings for a stream

<p>After a recording stops, it is saved as a video entity in Streaming Storage. Use the `stream_id` filter to list all recordings made from a specific stream, then read the video fields to get playback and embed URLs.</p>

| Field | Description |
|-------|-------------|
| `id` | Video ID |
| `name` | Auto-generated name including stream name and timestamp |
| `status` | `viewable` — processing complete and ready for playback; `pending` — still processing |
| `hls_url` | HLS playback URL (.m3u8) |
| `hls_cmaf_url` | CMAF HLS URL for low-latency players |
| `custom_iframe_url` | Embed iframe URL for the built-in player (auto-generated by default) |
| `origin_url` | Raw source file URL — populated only when `record_type` is `origin` |

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

recordings = list(client.streaming.videos.list(stream_id=stream_id))
for video in recordings:
    print(f"Video {video.id}: {video.name}")
    print(f"  status:     {video.status}")
    print(f"  hls_url:            {video.hls_url}")
    print(f"  custom_iframe_url:  {video.custom_iframe_url}")
    print(f"  origin_url:         {video.origin_url}")
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "context"
    "fmt"
    "os"
    "strconv"

    gcore "github.com/G-Core/gcore-go"
    "github.com/G-Core/gcore-go/packages/param"
    "github.com/G-Core/gcore-go/streaming"
)

func main() {
    client := gcore.NewClient()
    ctx := context.Background()

    streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

    page, err := client.Streaming.Videos.List(ctx, streaming.VideoListParams{
        StreamID: param.NewOpt(streamID),
    })
    if err != nil {
        panic(err)
    }
    for _, video := range page.Items {
        fmt.Printf("Video %d: %s\n", video.ID, video.Name)
        fmt.Printf("  status:     %v\n", video.Status)
        fmt.Printf("  hls_url:           %v\n", video.HlsURL)
        fmt.Printf("  custom_iframe_url: %v\n", video.CustomIframeURL)
        fmt.Printf("  origin_url:        %v\n", video.OriginURL)
    }
}
```

<p>Record saves live streams as videos in Video Hosting. Recording can start automatically when a stream goes live, or be triggered manually to capture only a specific time window within the broadcast.</p>

## Record a live stream manually

<p>To record a live stream:</p>

<p>1\. Start a live stream from an encoder.</p>

<p>2\. Open the settings of the desired live stream.</p>

<p>3\. Click **Start record**.</p>


<Frame>![Start record button](/images/docs/streaming/live-streaming/record-your-live-streams-and-save-them-as-videos/live-streaming-record.png)</Frame>



<p>After 5–10 seconds, recording starts. The timer and **Stop record** button appear.</p>


<Frame>![recording](/images/docs/streaming/live-streaming/record-your-live-streams-and-save-them-as-videos/9612975948817.png)</Frame>



<p>If the stream disconnects due to a network issue or hardware failure, recording resumes automatically when the stream reconnects. Interruptions shorter than one minute produce a single video. Interruptions longer than one minute split the recording into separate videos.</p>

<p>4\. To record only a specific fragment rather than the full stream, click **Stop record** at the desired moment.</p>

<Note>The minimum recording length is 10 seconds.</Note>

<p>To record the entire stream, do not click **Stop record**. Recording stops automatically when the stream ends.</p>

<Note>Recordings longer than 4 hours are split into 4-hour fragments for video processing.</Note>

<p>After stopping and processing, the recording appears in Video Hosting.</p>

## Recordings location

<p>After recording stops, the video is saved in Video Hosting. To access recordings:</p>

<p>1\. Navigate to [Streaming](https://portal.gcore.com/streaming) > **Video Hosting**.</p>

<Frame>![Video Hosting page showing recorded stream entries](/images/docs/streaming/live-streaming/record-your-live-streams-and-save-them-as-videos/live-stream-storage.png)</Frame>

<p>2\. Click the recording name to open its settings.</p>

<p>3\. Navigate to the **Links for the export** section. Copy the iFrame code to embed the recording on a website, or use the download links to save the video file.</p>

<Frame>![Links for the export section in Video Hosting video settings](/images/docs/streaming/live-streaming/record-your-live-streams-and-save-them-as-videos/live-streams-export-iframe.png)</Frame>

## Record original stream

<p>Original recording saves the raw source stream (RTMP, SRT, or other protocol) without transcoding, preserving the original quality, codecs, and framerate exactly as sent by the encoder. Original recordings are available for download approximately 30 seconds after the stream ends — without waiting for transcoding.</p>

<Warning>
Original recording is a premium feature. Contact an account manager or [Gcore support](mailto:support@gcore.com) to enable it. Configuration is done via the REST API tab using the `record_type: origin` parameter.
</Warning>

<p>Original recordings have a different retention policy from transcoded recordings.</p>

<Warning>
Original recordings are stored for **7 days only**. After 7 days, the original file is automatically deleted.

Transcoded renditions are not affected and remain available indefinitely.
</Warning>

## Troubleshoot differences between live playback and recordings

<p>Recording and live transcoding operate as separate, independent processes. Recording saves the incoming stream as received; the live transcoder builds the playback session from source metadata read once when the encoder first connects.</p>

### Recording fails during later VOD processing

<p>If the source stream changes pixel format, color range, codec parameters, or similar properties during the broadcast, the recording saves the changed segment too. The resulting file contains inconsistent source parameters, and later VOD processing may fail.</p>

<p>The cause is a structural property of the MP4 container: the file begins with metadata (`ftyp`, `moov`) that describes how to interpret all later samples. If source parameters change mid-stream, the later samples in `mdat` no longer match that initial description. The container format does not support mid-file sample-description changes, so decoders and transcoders reject the tail of the file or fail during export.</p>

```text
Simplified MP4 timeline:

time ------------------------------------------------------------------------------>

| MP4 headers + metadata | stable video samples | parameter change | later samples |
| ftyp | moov            | mdat: yuv420p        | yuv420p->yuvj420p| mdat: changed |

                        OK for decoder/transcoder
                                              ^
                                              |
                         from this point, later video data may decode incorrectly,
                         show artifacts, fail validation, or stop transcoding
```

```text
LIVE ENCODER
  first part of stream: stable parameters
  example: yuv420p
            |
            +----------------------> LIVE TRANSCODER
            |                         uses live session rules
            |
            +----------------------> RECORDING WORKFLOW
                                      stores source as received

... later during the same broadcast ...

LIVE ENCODER
  source parameters change mid-stream
  example: yuv420p -> yuvj420p
            |
            +----------------------> LIVE TRANSCODER
            |                         may continue, degrade, or fail
            |                         depending on the type of change
            |
            +----------------------> RECORDING WORKFLOW
                                      stores the changed segment too

RECORDED FILE RESULT
  beginning: yuv420p
  ending:    yuvj420p
            |
            v
LATER VOD PROCESSING / EXPORT OF RECORDING
  sees mixed source parameters inside one file
  may fail, enter Error status, or require trimming
  of the broken segment before reprocessing
```

<Info>
If a recording fails VOD processing due to mid-stream parameter changes, contact [Gcore support](mailto:support@gcore.com) for assistance.
</Info>

### Recording appears smooth but live playback has low FPS

<p>If live playback runs unexpectedly at 10–12 fps while the recording appears smooth, the live transcoder read low source FPS metadata at the start of the session. This FPS value is not re-read later, and Gcore does not upscale live frame rate dynamically during the session. After fixing the encoder settings, the stream must be reconnected from the encoder side to start a new session with the correct source metadata.</p>

## Configure recording settings

<p>Set `auto_record` and `record_type` on an existing stream. When `auto_record` is `true`, recording starts automatically whenever the encoder connects. When `false`, recording must be started manually. `record_type` controls whether the raw ingest (`origin`) or the transcoded output (`transcoded`) is saved.</p>

| Parameter | Required | Description |
|-----------|----------|-------------|
| `auto_record` | No | `true` to record automatically when the stream goes live |
| `record_type` | No | `transcoded` (default) — saves the processed output with applied overlays and encoding; `origin` — saves the raw RTMP/SRT source without transcoding |

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

stream = client.streaming.streams.update(
    stream_id,
    stream={
        "auto_record": True,
        "record_type": "transcoded",
    },
)
print(f"Stream {stream.id}: auto_record={stream.auto_record}, record_type={stream.record_type}")
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "context"
    "fmt"
    "os"
    "strconv"

    gcore "github.com/G-Core/gcore-go"
    "github.com/G-Core/gcore-go/packages/param"
    "github.com/G-Core/gcore-go/streaming"
)

func main() {
    client := gcore.NewClient()
    ctx := context.Background()

    streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

    // GET the current stream to read its name — required field for Update
    existing, err := client.Streaming.Streams.Get(ctx, streamID)
    if err != nil {
        panic(err)
    }

    stream, err := client.Streaming.Streams.Update(ctx, streamID, streaming.StreamUpdateParams{
        Stream: streaming.StreamUpdateParamsStream{
            Name:       existing.Name,
            AutoRecord: param.NewOpt(true),
            RecordType: "transcoded",
        },
    })
    if err != nil {
        panic(err)
    }
    fmt.Printf("Stream %d: auto_record=%v, record_type=%v\n",
        stream.ID, stream.AutoRecord, stream.RecordType)
}
```
  </Tab>
  <Tab title="curl">
```bash
curl -X PATCH "https://api.gcore.com/streaming/streams/$STREAM_ID" \
     -H "Authorization: APIKey $GCORE_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "auto_record": true,
       "record_type": "transcoded"
     }'
```

<p>The API returns the full updated stream object. The relevant fields:</p>

```json
{
  "id": 4518917,
  "auto_record": true,
  "record_type": "transcoded",
  "recording": false,
  "recording_duration": null
}
```

## Start recording manually

<p>Start recording a specific stream on demand. The stream must be actively receiving an ingest signal — if the stream is offline, the API returns `204` but recording does not start. After recording starts, `recording` switches to `true` on the stream object and `recording_duration` counts up in seconds.</p>

<Info>
The Go SDK returns an error for this endpoint due to a bug with empty 204 responses. Use the raw HTTP helper shown below until the SDK is fixed.
</Info>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

client.streaming.streams.start_recording(stream_id)
print(f"Recording started for stream {stream_id}")
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "fmt"
    "io"
    "net/http"
    "os"
    "strconv"
)

// startRecording uses raw HTTP because the Go SDK does not handle
// the 204 No Content response from this endpoint correctly.
func startRecording(streamID int64) error {
    apiKey := os.Getenv("GCORE_API_KEY")
    url := fmt.Sprintf("https://api.gcore.com/streaming/streams/%d/start_recording", streamID)
    req, _ := http.NewRequest("PUT", url, nil)
    req.Header.Set("Authorization", "APIKey "+apiKey)
    req.Header.Set("Content-Type", "application/json")
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return err
    }
    defer resp.Body.Close()
    io.ReadAll(resp.Body)
    if resp.StatusCode != 204 && resp.StatusCode != 200 {
        return fmt.Errorf("unexpected status: %d", resp.StatusCode)
    }
    return nil
}

func main() {
    streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

    if err := startRecording(streamID); err != nil {
        panic(err)
    }
    fmt.Printf("Recording started for stream %d\n", streamID)
}
```
  </Tab>
  <Tab title="curl">
```bash
curl -X PUT "https://api.gcore.com/streaming/streams/$STREAM_ID/start_recording" \
     -H "Authorization: APIKey $GCORE_API_KEY" \
     -H "Content-Type: application/json"
```

<p>Returns `204 No Content` whether the stream is live or offline. Recording only starts if the stream is actively receiving an ingest signal at the time of the call.</p>
  </Tab>

## Stop recording

<p>Stop an active recording. The stream does not have to be taken offline — only recording stops. The saved video appears in Video Hosting and is returned by the API.</p>

## Retrieve recordings for a stream

<p>After a recording stops, the video appears in Video Hosting. Use the `stream_id` filter to list all recordings made from a specific stream. The response includes playback URLs (`hls_url`, `hls_cmaf_url`), an embed URL (`iframe_url`), and `status` — either `ready` (available for playback) or `pending` (still processing). For `origin` recordings, `origin_url` contains the raw source file URL.</p>

<Tabs>
  <Tab title="Python SDK">
```python
import os
from gcore import Gcore

client = Gcore()
stream_id = int(os.environ["STREAM_ID"])

recordings = list(client.streaming.videos.list(stream_id=stream_id))
for video in recordings:
    print(f"Video {video.id}: {video.name}")
    print(f"  status:       {video.status}")
    print(f"  hls_url:      {video.hls_url}")
    print(f"  hls_cmaf_url: {video.hls_cmaf_url}")
    print(f"  iframe_url:   {video.iframe_url}")
    print(f"  origin_url:   {video.origin_url}")
```
  </Tab>
  <Tab title="Go SDK">
```go
package main

import (
    "context"
    "fmt"
    "os"
    "strconv"

    gcore "github.com/G-Core/gcore-go"
    "github.com/G-Core/gcore-go/packages/param"
    "github.com/G-Core/gcore-go/streaming"
)

func main() {
    client := gcore.NewClient()
    ctx := context.Background()

    streamID, _ := strconv.ParseInt(os.Getenv("STREAM_ID"), 10, 64)

    page, err := client.Streaming.Videos.List(ctx, streaming.VideoListParams{
        StreamID: param.NewOpt(streamID),
    })
    if err != nil {
        panic(err)
    }
    for _, video := range page.Items {
        fmt.Printf("Video %d: %s\n", video.ID, video.Name)
        fmt.Printf("  status:       %v\n", video.Status)
        fmt.Printf("  hls_url:      %v\n", video.HlsURL)
        fmt.Printf("  hls_cmaf_url: %v\n", video.HlsCmafURL)
        fmt.Printf("  iframe_url:   %v\n", video.IframeURL)
        fmt.Printf("  origin_url:   %v\n", video.OriginURL)
    }
}
```

## CDN delivery in Video Streaming

[Video Streaming](https://gcore.com/streaming-platform) distributes video content through the Gcore CDN network. The CDN is fully integrated into Video Streaming — no additional configuration is required to start delivering content globally.

Edge servers pull videos from storage or live streams from the media server and deliver them to end users across 210+ locations worldwide.

## Integrated CDN delivery

When Video Streaming is activated, CDN delivery is automatically enabled and configured. Content is immediately distributed through Gcore's global CDN infrastructure with:

- **Automatic caching** at edge locations closest to viewers
- **Adaptive bitrate delivery** for optimal playback quality
- **Built-in player** with CDN-optimized streaming
- **Global coverage** across 210+ edge locations

**No additional CDN setup is required** – streaming and CDN work together out of the box.

## Billing for integrated CDN

Video Streaming with integrated CDN is billed on a **per-minute basis** based on the selected tariff plan. Billing is calculated in seconds and converted to minutes.

**Billing calculation:** Billing is based on the total minutes of content delivered to viewers.

<Info>
If viewers watch a total of 10,000 minutes of content in a month, billing is 10,000 minutes at the plan's per-minute rate.
</Info>

<Warning>
If a player downloads a video segment to buffer, it is considered delivered and billed. For example, if a player buffers 30 seconds before playback starts, those 30 seconds count toward billing regardless of whether the viewer watches the content or closes the player.
</Warning>

## Default CDN subdomain

Content is distributed to viewers from a CDN resource subdomain. When a Video Streaming account is created, a default CDN subdomain is automatically assigned in the format:

```sh
clientID.gvideo.io
```

The _clientID_ is the numeric account identifier visible in the profile dropdown (click the user icon in the top-right corner of the portal). For example, if the client ID is _12345_, the default subdomain is _12345.gvideo.io_.

**Important:** This default CDN resource is invisible in the dedicated CDN resource list and is managed automatically by Video Streaming. No configuration or management of this resource is required.

This subdomain is included in the playback URLs for all videos and live streams:
- **Live stream:** `https://12345.gvideo.io/cmaf/12345_00000/master.m3u8`
- **Video (VOD):** `https://12345.gvideo.io/videos/12345_ABcdefg123HiJ`

## Delivery approaches

The default integrated CDN covers most use cases without any setup. If the use case requires custom domains, geo-blocking, or other advanced features, Gcore offers two additional delivery approaches. The table below compares all three options:

| Feature | Video Streaming | Hybrid (Transcoding + Custom CDN) | Video CDN only |
|---------|-------------------------------|-----------------------------------|----------------|
| **Availability** | Immediate (automatically enabled) | Manual activation required | Manual activation required |
| **Pricing model** | Per-minute (all-inclusive) | Per-minute (transcoding) + Per-GB (CDN bandwidth) | Per-GB (bandwidth only) |
| **Transcoding** | Included | Included | Not included (pre-encoded stream required) |
| **Custom domains** | Not available | Supported | Supported |
| **Geo-blocking** | Not available | Country access policies | Country access policies |
| **Referrer validation** | Not available | Domain restrictions | Domain restrictions |
| **IP allowlists/blocklists** | Not available | IP access policies | IP access policies |
| **Secure tokens** | Not available | Configurable | Configurable |
| **Advanced caching rules** | Default settings | Full control | Full control |
| **Separate security policies** | One policy for all | Multiple resources | Multiple resources |

<Tabs>
  <Tab title="Video Streaming (Transcoding)">
    **What it does:**
    - Accepts raw video input (RTMP, SRT, WebRTC, or pulls HLS)
    - Transcodes the stream into multiple quality levels (ABR ladder up to 1080p)
    - Packages into HLS and MPEG-DASH formats
    - Delivers via Gcore CDN with built-in player
    - **Billed per-minute** of content streamed

    **Choose this if:**
    - The input is a raw stream (RTMP, SRT, WebRTC) that needs transcoding
    - Adaptive bitrate (ABR) encoding should be handled by Gcore
    - Multiple quality levels are needed automatically
    - Reducing delivery load on origin servers is a priority
    - DVR or recording features are required
    - Simple per-minute billing is preferred
    - Advanced CDN features (geo-blocking, custom domains) are not needed

    **Example use cases:**
    - Streaming from OBS, vMix, or hardware encoders
    - Pulling an HLS stream and adding ABR quality options
    - Broadcasting live events with automatic quality adaptation
  </Tab>
  <Tab title="Hybrid (Transcoding + Custom CDN)">
    **What it does:**
    - **Same transcoding** as Video Streaming (Transcoding) option
    - Accepts raw video input (RTMP, SRT, WebRTC, or pulls HLS)
    - Transcodes into multiple quality levels (ABR ladder up to 1080p)
    - **Plus:** Delivers via custom CDN resource with advanced features
    - **Billed per-minute** for transcoding + **per-GB** for CDN bandwidth

    **Choose this if:**
    - Transcoding AND advanced CDN features are both needed
    - Custom domain names are required (e.g., `video.yourdomain.com`)
    - Geo-blocking or referrer validation is needed
    - Secure tokens for access control are required
    - Separate security policies for different content are needed
    - Additional CDN costs for advanced features are acceptable

    **Example use cases:**
    - Streaming with geo-restrictions for broadcasting rights compliance
    - Protected content requiring secure tokens and custom domains
    - Multi-region delivery with different security policies per region
    - Enterprise deployments requiring advanced access control

    **How to set up:**
    See the [Custom CDN resource](/streaming/interaction-with-cdn/custom-cdn-resource) guide for detailed setup instructions.
  </Tab>
  <Tab title="Video CDN only">
    **What it does:**
    - Delivers already-prepared HLS or MPEG-DASH streams
    - No transcoding — distribution at scale only
    - Caches and delivers streams from 210+ edge locations worldwide
    - **Billed per-GB** of bandwidth consumed

    **Activation:** Video CDN delivery requires approval by Gcore Support before use. Contact [support@gcore.com](mailto:support@gcore.com) to request activation for the CDN account.

    **Choose this if:**
    - An HLS or MPEG-DASH stream is already prepared
    - Transcoding is already handled on the origin side
    - Only global CDN distribution is needed
    - Maximum control over encoding settings is required
    - Advanced CDN features such as geo-blocking or custom domains are needed
    - Per-GB billing is preferred

    **Example use cases:**
    - A media server already produces HLS output
    - Geo-restrictions or custom access policies are required
    - Offloading bandwidth from an origin server
    - Migrating from another CDN provider

    **How to set up:**
    See the [Video CDN](/cdn/video-cdn/video-cdn-overview) guide for detailed setup instructions.
  </Tab>
</Tabs>

<Info>
- **Start simple:** Use Video Streaming (Transcoding) for most use cases.
- **Need advanced features with transcoding:** Use the Hybrid approach.
- **Already have HLS/DASH streams:** Use Video CDN only (requires Support activation).
</Info>

## Next steps

- **Start streaming:** Use the integrated CDN — no additional setup needed.

- **Need access control for paid or private content?** See [Video secure token](/streaming/interaction-with-cdn/video-secure-token).

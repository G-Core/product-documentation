Gcore JS Video Player (`@gcorevideo/player`) is a lightweight, customizable video player built on top of hls.js, dash.js, and the native `<video />` element. It supports LIVE and VOD playback with HLS, LL-HLS, MPEG-DASH, LL-DASH, and MP4, and works with any source URL, including non-Gcore sources. Functionality is extended through plugins, with full SDK access to methods, events, and error handling.

The [GitHub&nbsp;repository](https://github.com/G-Core/gcore-videoplayer-js/) contains the full SDK reference.
</Info>

## Basic functions

### Set video source

The player is configured at initialization through a set of built-in options: switch sources, enable autoplay, loop content, mute on start, and show a preview image before playback begins.

Any source URL works — not only Gcore-hosted streams. The player supports HLS (.m3u8) and MPEG-DASH (.mpd), both Live and VOD, and automatically determines the source type.

A single source or multiple sources can be defined in the configuration. The player tries them in order, uses the first compatible one, and displays an error stub if none can be played.


**Simple way to start HLS playback:**

LIVE, player detects type of video automatically ([live&nbsp;example](https://player.gvideo.co/streams/2675_19146)):
```js
const player = new Player({
  autoPlay: true,
  mute: true,
  sources: ["https://demo.gvideo.io/cmaf/2675_19146/master.m3u8"],
})
```

VOD, player detects type of video automatically ([VOD&nbsp;example](https://player.gvideo.co/videos/2675_w6nGXEimHz4Z6t1j)):
```js
const player = new Player({
  autoPlay: true,
  mute: true,
  sources: ["https://demo-public.gvideo.io/videos/2675_w6nGXEimHz4Z6t1j/master.m3u8"],
})
```

**Advanced way to start playback with multiple sources:**

To serve multiple environments, configure DASH as the primary transport with HLS as a fallback. If DASH is unsupported or fails, the player falls back to HLS. A poster image (from the \Poster\ plugin \poster.url\ setting) is shown before playback starts.

LIVE ([live&nbsp;example](https://player.gvideo.co/streams/2675_19146)):
```js
const player = new Player({
  autoPlay: true,
  mute: true,
  playbackType: "live",
  priorityTransport: 'dash', // [dash|hls], "dash" is default value
  sources: [
    {
      source: "https://demo-public.gvideo.io/cmaf/2675_19146/index.mpd",
      mimeType: 'application/dash+xml',
    },
    {
      source: "https://demo-public.gvideo.io/cmaf/2675_19146/master.m3u8", 
      mimeType: 'application/x-mpegURL',
    }
  ],
  poster: { url: 'https://static.gvideo.co/videoplatform/posters/broadcast/21606/e0a5243fdd2ae36061b8cadfa5089fc8.jpeg' },
})
```

VOD ([VOD&nbsp;example](https://player.gvideo.co/videos/2675_w6nGXEimHz4Z6t1j)):
```js
const player = new Player({
  autoPlay: true,
  mute: true,
  playbackType: "vod",
  priorityTransport: 'dash', // [dash|hls], "dash" is default value
  sources: [
    {
      source: "https://demo-public.gvideo.io/videos/2675_w6nGXEimHz4Z6t1j/master.mpd",
      mimeType: 'application/dash+xml',
    },
    {
      source: "https://demo-public.gvideo.io/videos/2675_w6nGXEimHz4Z6t1j/master.m3u8", 
      mimeType: 'application/x-mpegURL',
    }
  ],
  poster: { url: 'https://static.gvideo.co/videoplatform/posters/video/11452407/eb4fba797fc1f41309e5b0b552319208.jpeg' },
})
```


### Enable autoplay

To enable autoplay, set `autoPlay: true`. Don't forget to combine it with `mute: true` to comply with most browser policies.
```js
const player = new Player({
  autoPlay: true,
  sources: ["https://demo-public.gvideo.io/videos/2675_mvsPGvDVx0Hzbog/master.m3u8"],
})
```


### Loop playback

Use the `loop: true` config option to repeat the video continuously.
```js
const player = new Player({
  loop: true,
  playbackType: 'vod',
  sources: ["https://demo-public.gvideo.io/videos/2675_mvsPGvDVx0Hzbog/master.m3u8"],
})
```


### Mute on start

Set `mute: true` to start playback without audio. This helps meet autoplay restrictions.
```js
const player = new Player({
  mute: true,
  sources: ["https://demo-public.gvideo.io/videos/2675_mvsPGvDVx0Hzbog/master.m3u8"],
})
```


### Set thumbnail

Use the `Poster` plugin and define an image using the `poster.url` setting. This image appears before playback starts and is helpful for branding, showing a preview, or providing visual context.
```js
poster: {
  url: "https://static.gvideo.co/videoplatform/posters/video/11452143/6423b07877c27c372b205aa99fd13f42.jpeg",
  showForNoOp: true
}
```


## Customize the player

Custom styles and hidden interface elements adjust the player appearance and behavior.


### Custom skin

Since the player’s UI is plugin-based, most interface elements expose class names that can be targeted directly. For complete control over layout and styling, define styles in a scoped or external stylesheet. 

| Theme eleme        | Description                               |
|--------------------|-------------------------------------------|
| Background color   | Background of bottom play panel           |
| Foreground color   | Color of icons, play button, and timeline |
| Text color         | Color of text                             |
| Hover color        | Color of buttons under mouse pointer      |

Default stylesheet:
```html
<link rel="stylesheet" href="https://player.gvideo.co/v2/assets/latest/index.css" />
```


### Hide UI components

The player interface is modular. Visual elements are enabled by activating corresponding plugins. The `Media controls` plugin handles the core of the UI — if it's not selected, most visible components won’t appear. Each UI-related plugin can be toggled dynamically at runtime. Some plugins also act as containers and unlock access to additional components.

```js
player.on('ready', () => {
  const mc = player.getPlugin('MediaControl')
  if (mc) {
    mc.disable()
  }
})
```

For a completely custom UI, disable the default controls via plugin settings and implement the interface on top of the [core&nbsp;playback&nbsp;API](https://github.com/G-Core/gcore-videoplayer-js/blob/main/packages/player/docs/api/player.md).


## Install and configure

### Install via npm or yarn

The Gcore Player SDK works with React, Vue, Svelte, plain JS, or CMS platforms like WordPress and Tilda — no framework dependency.

<Steps>
  <Step title="Install the SDK">
    Install the player package:

    ```
    npm install @gcorevideo/player
    ```

    or with yarn:

    ```
    yarn add @gcorevideo/player
    ```
  </Step>

  <Step title="Import and configure the player">
    Import the player styles and core modules, register the plugins, then initialize the player against the container element:

    ```js
    import '@gcorevideo/player/dist/index.css'
    import { Player, MediaControl, SourceController } from '@gcorevideo/player'

    Player.registerPlugin(MediaControl)
    Player.registerPlugin(SourceController)

    const player = new Player({
      autoPlay: true,
      mute: true,
      sources: [{
        source: 'https://example.com/your-video.m3u8',
        type: 'application/x-mpegURL'
      }]
    })

    player.attachTo(document.getElementById('container'))
    ```
  </Step>

  <Step title="Add the container element">
    Define the container in HTML or the component template:

    ```html
    <div id="container" style="width: 640px; height: 360px;"></div>
    ```

    Set the container width and height explicitly. The player attaches only if the container has visible dimensions.
  </Step>
</Steps>


### Vanilla JS

As an alternative, import the native .js file directly into HTML pages without installation.

Add module:
```html
<script src="https://player.gvideo.co/v2/assets/latest/index.js"></script>
```

Or import only the modules and plugins needed:
```html
<script type="module">
  import {
    Player,
    ...
  } from 'https://player.gvideo.co/v2/assets/latest/index.js'
  ...
</script>
```

The [README](https://github.com/G-Core/gcore-videoplayer-js/blob/main/packages/player/README.md) on GitHub documents usage and the latest version. 


### Get the latest version

The Gcore Player supports both a fixed version and auto-updating to the latest release.

*Latest build (auto-update):*

```js
<script src="https://player.gvideo.co/v2/assets/latest/index.js"></script>
```

Use this option to stay updated with the newest features and bug fixes without manual version changes.

*Exact version (fixed, no surprises):*

```js
<script src="https://player.gvideo.co/v2/assets/{version}/index.js"></script>
```

Replace `{version}` with a specific release tag, e.g. `1.7.24`. Available versions are listed on [npmjs.com](https://www.npmjs.com/package/@gcorevideo/player?activeTab=versions).

Use this for production environments, certification, or long QA cycles where updates must be tested before rollout.

Recommendation:
	- Use exact versions in production for stability.
	- Use latest during development for automatic access to improvements.

## SDK overview

Gcore Video Player is configured through a single object called `PlayerConfig`. This object defines the player’s behavior, including video sources, playback type, preferred streaming protocol, autoplay and mute settings, poster image, and enabled plugins.


### Methods overview

Once the player is initialized, instance methods control playback. Most features are exposed via simple methods without accessing the internal architecture directly.

| Category              | Method              | Description                                                                 |
|-----------------------|---------------------|-----------------------------------------------------------------------------|
| **Playback control**  | `player.play()`     | Start playback                                                              |
|                       | `player.pause()`    | Pause playback                                                              |
|                       | `player.stop()`     | Stop playback and clear the current stream                                  |
| **Mute & volume**     | `player.mute()`     | Mute audio                                                                  |
|                       | `player.unmute()`   | Unmute audio                                                                |
|                       | `player.setVolume(0.5)` | Set volume (0.0 – 1.0)                                                    |
|                       | `player.isMuted()`  | Check if player is muted                                                    |
|                       | `player.getVolume()`| Get current volume value                                                     |
| **Seek & timing**     | `player.getCurrentTime()` | Get current playback position (in seconds)                              |
|                       | `player.getDuration()`   | Get total media duration (in seconds)                                     |
|                       | `player.seek(120)`       | Jump to a specific time (e.g. 120 seconds = 2 min)                        |
| **Cleanup**           | `player.destroy()`  | Release resources and disconnect player before removing DOM container       |

The [Player&nbsp;class&nbsp;reference](https://github.com/G-Core/gcore-videoplayer-js/blob/main/packages/player/docs/api/player.player.md#methods) on GitHub lists all available methods.


### Events overview

The player emits events throughout the playback lifecycle to track user interaction, trigger UI updates, or synchronize video playback with other app actions.

One of the most common events is play, which triggers when playback begins — either automatically or after user interaction:
```js
player.on("play", () => {
  // Called when playback starts
})
```

| Category        | Event           | Description                                                                 |
|-----------------|-----------------|-----------------------------------------------------------------------------|
| **Playback**    | `pause`         | Triggered when playback is paused                                           |
| **Seek & time** | `seek`          | Fired when the current time changes (programmatically or by user action)    |
| **Audio**       | `volumeupdate`  | Fired when volume or mute state changes                                     |
| **Errors**      | `error`         | Fired when playback fails or media cannot be loaded                         |

The [PlayerEvent&nbsp;reference](https://github.com/G-Core/gcore-videoplayer-js/blob/main/packages/player/docs/api/player.md) on GitHub lists all events and their parameters.


### Errors overview

Gcore Video Player emits a standardized error event whenever playback fails. This event returns a `PlaybackError` object containing details: error code, message, severity, and source:

```js
player.on("error", (error) => {
  console.warn("Playback error:", error.message)
})
```

The most common playback errors include:
  - Invalid or unreachable video URLs
  - Missing or corrupted media metadata
  - Unrecognized formats or codec issues

Most non-fatal errors can be handled by showing fallback UI, retrying playback, or switching to a backup stream. The SourceController plugin automates fallback logic and recovery scenarios.
The [PlaybackError&nbsp;reference](https://github.com/G-Core/gcore-videoplayer-js/blob/main/packages/player/docs/api/player.playbackerror.md) on GitHub documents all error codes and fields.


### Debug overview

If the video does not start, buffers indefinitely, or behaves unexpectedly, enable logs to investigate.

**Enable debug output:**

The `@gcorevideo/utils` package provides two utilities for log output: `Logger` controls which categories are captured; `LogTracer` writes them to the browser console. Enable all categories with `Logger.enable("*")`:

```js
import { Logger, LogTracer } from "@gcorevideo/utils"
Logger.enable("*")                         // enable all log categories
const tracer = new LogTracer("my-player") // named tracer for console output
```

The console output includes player lifecycle events, source selection, buffering status, and error details — useful for diagnosing unsupported formats or network failures.

**Integrate with observability tools:**

Gcore Player integrates with remote logging platforms like Sentry. Structured metadata (browser, device, resolution, and error details) can be forwarded to identify user-side issues at scale. The Nuxt example repository demonstrates [Sentry&nbsp;integration](https://github.com/dmitritz/gcore-videoplayer-js-nuxt/blob/29f9c6bb226970886962f99a9d475f57169bceba/app.vue#L56) and [server-side&nbsp;logging](https://github.com/dmitritz/gcore-videoplayer-js-nuxt/blob/29f9c6bb226970886962f99a9d475f57169bceba/app.vue#L38C22-L38C34).


## Limits

### Views Statistics

This player does not collect or send usage statistics from end user devices. Viewing statistics are available from CDN data via the [CDN&nbsp;statistics&nbsp;API](/api-reference/streaming/statistics/get-unique-viewers-via-cdn).

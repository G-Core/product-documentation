title: Fix the camera or microphone if they do not work
sidebarTitle: Camera and microphone
ai-navigation: Troubleshoot crossed-out camera and microphone by allowing site and OS permissions, then testing extensions and the network.
---

Crossed-out camera or microphone icons in a Real-Time Video call mean the site or the operating system blocked the devices, or a stored permission or extension is denying access. The origin that must be allowed is `meet.gcore.com`.

Allow the site in the browser first. If the icons stay crossed out, reset that site permission, test extensions, allow the browser in the OS, then confirm that the browser version is supported. If the devices work in the browser but other participants do not receive media, the network is blocking WebRTC. An enabled icon with silence in the room is a different problem — the OS is sending the wrong input device, and that check is in the Windows tab.

## Reset site permissions

If the address-bar toggles were changed but the icons stay crossed out, the browser is still applying a stored permission for `meet.gcore.com`. Reset that origin only, then reload the page.

<Tabs>
  <Tab title="Chrome">
    In the padlock menu, click **Reset permissions**, then reload the page. Chrome asks for camera and microphone access again.
  </Tab>
  <Tab title="Edge">
    In the padlock menu, click **Reset permissions**, then reload the page. Edge asks for camera and microphone access again.
  </Tab>
  <Tab title="Firefox">
    In **Settings** → **Privacy & Security** → **Permissions**, open **Camera** and **Microphone**, remove `meet.gcore.com` from the lists, then reload the page.
  </Tab>
  <Tab title="Opera">
    In the padlock menu, click **Reset permissions**, then reload the page. Opera asks for camera and microphone access again.
  </Tab>
  <Tab title="Safari">
    In Safari **Settings**, open **Camera** and **Microphone**, remove or unblock `meet.gcore.com`, then reload the page and click **Allow**.
  </Tab>
</Tabs>

## Check extensions

A third-party extension can deny camera or microphone access on `meet.gcore.com`. Open the Real-Time Video page in a private or incognito window, where most extensions are off.

A private window also uses a separate permission store, so a working call there is not proof that an extension is the cause. If the devices work in the private window, return to the regular window, disable extensions that manage camera, microphone, ads, or privacy one at a time, and reload the call. The extension that restores the devices is the one to leave off during Real-Time Video sessions.

## Check operating-system permissions

The operating system can block the browser even when the site permission is on. Open the tab for the OS in use.

<Tabs>
  <Tab title="Windows">
    Windows 11 can deny camera or microphone access to the browser. Open **Settings** → **Privacy & security**, then select **Camera** or **Microphone**. Turn camera access or **Microphone access** on, then allow the browser in the app list.

    <Frame>
      ![Windows 11 Microphone access and per-app microphone permissions](/images/docs/streaming/faq/real-time-video-issues/fix-the-camera-or-microphone-if-they-do-not-work/13081924169617.png)
    </Frame>

    If the icon is already enabled but the room hears nothing, the default input is wrong. Open **Settings** → **System** → **Sound**. Under **Input**, select the device that should capture the call.

    <Frame>
      ![Windows 11 Sound settings with Input devices](/images/docs/streaming/faq/real-time-video-issues/fix-the-camera-or-microphone-if-they-do-not-work/13081899519505.png)
    </Frame>
  </Tab>
  <Tab title="macOS">
    On current macOS, camera and microphone access is under **System Settings** → **Privacy & Security**. On earlier macOS, the same pane is **System Preferences** → **Security & Privacy**.

    1. Open **System Settings** (or **System Preferences**) and select **Privacy & Security** (or **Security & Privacy**).

    <Frame>
      ![macOS System Preferences with Security and Privacy selected](/images/docs/streaming/faq/real-time-video-issues/fix-the-camera-or-microphone-if-they-do-not-work/13081820659857.png)
    </Frame>

    2. Select **Camera** or **Microphone**, then select the checkbox next to the browser.

    <Frame>
      ![macOS Privacy pane with Camera, Microphone, and browser checkboxes](/images/docs/streaming/faq/real-time-video-issues/fix-the-camera-or-microphone-if-they-do-not-work/13081892456593.png)
    </Frame>

    Restart the browser after changing these settings — the new permission applies only after a reload.
  </Tab>
  <Tab title="Android">
    Android can deny camera or microphone access to Chrome even when the site permission is on.

    Open **Settings** → **Apps** → **Chrome** → **Permissions**. Set **Camera** and **Microphone** to **Allow**, then return to the Real-Time Video page and reload it.
  </Tab>
  <Tab title="iOS">
    iOS can deny camera or microphone access to Safari even when the page prompt was accepted.

    Open **Settings** → **Privacy & Security**, then **Camera** and **Microphone**, and allow Safari. Site-level Safari controls are under **Settings** → **Safari** (or **Settings** → **Apps** → **Safari**). Camera and Microphone must not be set to **Deny**. Reload the Real-Time Video page.
  </Tab>
</Tabs>

## Check the network

This step applies only after the camera and microphone are available in the browser — the local preview works, the icons are not crossed out, and the OS permission is on.

Corporate networks and strict firewalls can still block WebRTC media, so other participants do not receive audio or video. Switching browsers does not bypass a network that drops those connections. Join the call from another network, or ask the network administrator to allow WebRTC traffic for `meet.gcore.com`.

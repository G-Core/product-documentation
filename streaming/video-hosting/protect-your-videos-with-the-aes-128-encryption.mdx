<p>AES-128 encrypts HLS video chunks. A keyserver controls access to the decryption key, so playback can be limited to authorized viewers.</p>

## VoD playback

<p>VoDs are delivered over the [HLS&nbsp;protocol](/streaming/video-hosting/hls-and-mp4). Each video is split into playlists of encrypted chunks. The playlist <code>EXT-X-KEY</code> tag names the keyserver URL for the decryption key.</p>

<p>Playback follows this sequence:</p>

1. The player loads the HLS playlist and requests the decryption key from the keyserver URL in the <code>EXT-X-KEY</code> tag.
2. The keyserver checks the viewer. The check can use cookies, a session parameter, or another signal defined on the keyserver.
3. If the check fails, the keyserver does not return a key.
4. If the check passes, the keyserver requests the key from the CDN encryption endpoint and returns it to the player.
5. The player decrypts the chunks.

## Enable AES-128

<p>Gcore support enables AES-128 for the account and configures the keyserver URL. Email [support@gcore.com](mailto:support@gcore.com) or use chat in the [Gcore Customer Portal](https://portal.gcore.com), and include that URL. A typical URL is client-keyserver.com.</p>

<p>Videos then follow the account encryption setting. Playlists (m3u8) include an <code>EXT-X-KEY</code> tag:</p>

```sh
#EXT-X-KEY:METHOD=AES-128,URI="https://client-keyserver.com/videos/clientId_videoslug/encryption"
```

## Keyserver configuration

<p>After AES-128 is enabled for the account, the keyserver validates the viewer and requests the decryption key from the CDN encryption endpoint:</p>

```sh
GET https://{CDN_HOST}/videos/{clientId_slug}/encryption
```

<p><code>clientId_slug</code> joins the Gcore account ID and the video slug, as in <code>1000503_cC4PEC0AWy1qu03R</code>.</p>

<p>The response is the decryption key. Pass that 16-byte binary value to the player unchanged. Return the original bytes, not a hexadecimal rendering of them.</p>

<p>Return the key with these HTTP headers:</p>

* Content-transfer-encoding: binary
* Content-type: application/octet-stream

<Note>
AES-128 can be combined with a [country&nbsp;access&nbsp;policy](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#country-access-policy) or a [referrer&nbsp;access&nbsp;policy](/cdn/cdn-resource-options/security/control-access-to-the-content-with-country-referrer-ip-and-user-agents-policies#referrer-access-policy).
</Note>

<p>When AES-128 encryption is enabled for the account by Gcore support, the Streaming API exposes a per-video <code>encryption</code> field. Set it to <code>aes128</code> to encrypt a specific video regardless of the account-level default, or set it to <code>inherit</code> to follow the account setting. Configure the keyserver to call the CDN encryption endpoint to retrieve decryption keys.</p>

<Info>
An [API&nbsp;token](/account-settings/api-tokens) is required.
</Info>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export VIDEO_ID="{YOUR_VIDEO_ID}"
```

## Check video encryption status

<p>The <code>encryption</code> field in the video object shows the current encryption setting for that video.</p>

| Value | Behavior |
|-------|----------|
| `inherit` | Uses the account-level encryption setting configured by Gcore support |
| `aes128` | Delivers this video with AES-128 encryption regardless of the account setting |

    import os

    video_id = int(os.environ["VIDEO_ID"])

## Enable AES-128 on a video

<p>Set <code>encryption</code> to <code>aes128</code> to force encrypted delivery for a specific video.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import os
    from gcore import Gcore

    client = Gcore()
    video_id = int(os.environ["VIDEO_ID"])
    video = client.streaming.videos.get(video_id)
    updated = client.streaming.videos.update(
        video_id,
        name=video.name,
        extra_body={"encryption": "aes128"},
    )
    print(f"Encryption: {updated.encryption}")  # aes128
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "encoding/json"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/option"
        "github.com/G-Core/gcore-go/streaming"
    )

    // Use option.WithJSONSet to set the field at the request level.
    func main() {
        client := gcore.NewClient()
        ctx := context.Background()

        videoID, _ := strconv.ParseInt(os.Getenv("VIDEO_ID"), 10, 64)
        video, err := client.Streaming.Videos.Get(ctx, videoID)
        if err != nil {
            panic(err)
        }

        updated, err := client.Streaming.Videos.Update(
            ctx,
            videoID,
            streaming.VideoUpdateParams{
                CreateVideo: streaming.CreateVideoParam{
                    Name: video.Name,
                },
            },
            option.WithJSONSet("encryption", "aes128"),
        )
        if err != nil {
            panic(err)
        }

        var rawUpdated map[string]json.RawMessage
        json.Unmarshal([]byte(updated.RawJSON()), &rawUpdated)
        var enc string
        json.Unmarshal(rawUpdated["encryption"], &enc)
        fmt.Printf("Encryption: %s\n", enc) // aes128
    }
    ```
  </Tab>
  <Tab title="curl">
    ```bash
    curl -X PATCH "https://api.gcore.com/streaming/videos/$VIDEO_ID" \
         -H "Authorization: APIKey $GCORE_API_KEY" \
         -H "Content-Type: application/json" \
         -d '{"encryption": "aes128"}'
    ```

    <p>The API returns the updated video object with <code>"encryption": "aes128"</code>.</p>
  </Tab>
</Tabs>

## Retrieve the decryption key (keyserver integration)

<p>When AES-128 is enabled, Gcore adds an <code>EXT-X-KEY</code> tag to the HLS playlist pointing to the keyserver URL. The keyserver receives the player's request, verifies the viewer, then calls the Gcore CDN encryption endpoint to retrieve the decryption key and forward it to the player.</p>

<p>The endpoint the keyserver calls to retrieve the key:</p>

```bash
GET https://{CDN_HOST}/videos/{clientId_slug}/encryption
```

<p><code>clientId_slug</code> joins the Gcore account ID and the video slug, as in <code>1000503_cC4PEC0AWy1qu03R</code>. The account ID and slug are available in the video object returned by <code>GET /streaming/videos/{video_id}</code>.</p>

<p>Gcore returns the decryption key as a 16-byte binary value. Pass it to the player using these HTTP headers:</p>

```
Content-Transfer-Encoding: binary
Content-Type: application/octet-stream
```

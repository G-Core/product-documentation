Order a virtual server or a dedicated server through the [Gcore&nbsp;Hosting&nbsp;Portal](https://hosting.gcore.com/billmgr). Each action is an HTTP POST to `https://hosting.gcore.com/billmgr`. The `func` parameter selects the action.

<Info>
Sign in with your existing Hosting Portal account. [Contact&nbsp;support](/hosting/contact-our-technical-support) and send your company details and the source IP address. What to send is on the [reseller&nbsp;page](/hosting/become-reseller-and-resell-our-services).

Support adds that IP address to the allow list and adds your account to the reseller group. Send the calls below from that address.
</Info>

## Authenticate

`authinfo` is your Hosting Portal username and password, separated by a colon. `out=json` selects a JSON response. Send both on every call. The password stays in the POST body. The first call is the tariff list below.

## Read a failed call

An HTTP error means the call did not return a billing document. A call can also return HTTP 200 and still fail. Then the failure text is in `doc.error.msg`, and `doc.list` is absent. Read `doc.error` before you use the list.

## Tariffs available to order

Request the virtual server catalog:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.pricelist" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json"
```

Request the dedicated server catalog:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.dedic.order.pricelist" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json"
```

The response lists the tariffs you can order. Each item has the tariff id in `pricelist`, the name in `title`, the location, and the price for one, three, six, and 12 months. The location is the `datacenter` object on the tariff (`id` and `value`). On the account used to read this catalog, a separate data center list is not available. `{TODO: verify - the same catalog shape for an account in the reseller group}`

Text values sit in `$`. `period` is a number of months. This object is one tariff returned by `v2.vds.order.pricelist` on the Gcore Hosting Portal:

```json

  "pricelist": { "$": "172456" },
  "title": { "$": "KVM-HIGHCPU-SSD-1-SY4" },
  "datacenter": {
    "id": { "$": "13" },
    "value": { "$": "Australia, Sydney" }
  },
  "prices": {
    "price": [
      {
        "period": { "$": "1" },
        "cost": { "$": "14.99" },
        "currency": { "$": "EUR" }
      }
    ]
  }
}
```

## Order a virtual server

Take `pricelist` and `datacenter.id` from the catalog. This call opens the order form and does not place the order:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.param" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json" \
  --data-urlencode "pricelist=172456" \
  --data-urlencode "datacenter=13" \
  --data-urlencode "period=1"
```

The form returns `domain` (the server name), `ostempl` (the operating system), and `order_period` (`1`, `3`, `6`, or `12`). Read `ostempl` from this response. Ubuntu 22.04 is `VM6_ISPsystem_Ubuntu-22.04`. The form also returns `addon_*` fields for that tariff. `{TODO: verify - which addon fields the order requires}`

Submit the same function with `sok=ok` and `skipbasket=on`. In BILLmanager, `skipbasket=on` charges the order from the account balance instead of leaving it in the cart. `{TODO: verify - GHost partners pay with skipbasket=on}`

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.param" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json" \
  --data-urlencode "pricelist=PRICELIST" \
  --data-urlencode "datacenter=DATACENTER" \
  --data-urlencode "period=1" \
  --data-urlencode "order_period=1" \
  --data-urlencode "domain=server1.example.com" \
  --data-urlencode "ostempl=OS_TEMPLATE" \
  --data-urlencode "skipbasket=on" \
  --data-urlencode "sok=ok"
```

`pricelist`, `datacenter`, `order_period`, `domain`, and `ostempl` come from the catalog and the form. A request without `sok=ok` changes nothing. `{TODO: verify - the response body after sok=ok. This submit was not sent}`

## Order a dedicated server

The dedicated server form uses the same parameters. The catalog call is `v2.dedic.order.pricelist`. The order call is `v2.dedic.order.param`. The form for tariff `152029` in datacenter `13` opened with `domain`, `ostempl`, and `order_period`. `{TODO: verify - the response body after sok=ok on v2.dedic.order.param.
```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.dedic.order.param" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json" \
  --data-urlencode "pricelist=PRICELIST" \
  --data-urlencode "datacenter=DATACENTER" \
  --data-urlencode "period=1" \
  --data-urlencode "order_period=1" \
  --data-urlencode "domain=server1.example.com" \
  --data-urlencode "ostempl=OS_TEMPLATE" \
  --data-urlencode "skipbasket=on" \
  --data-urlencode "sok=ok"
```

## Pay for the order

Add funds to your account balance before the first order. Renewals are charged from that balance. The order calls above send `skipbasket=on` so the new order is charged from that balance too.

## Read the service

After the order, list your virtual servers:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=vds" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json"
```

List dedicated servers with `func=dedic`. Read `id` and `item_status` on the new service. In BILLmanager, `1` means ordered, `2` means active, and `5` means processing. Wait until `item_status` is `2`.

```json
{
  "id": { "$": "SERVICE_ID" },
  "item_status": { "$": "2" }
}
```

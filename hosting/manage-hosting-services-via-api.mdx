A partner orders a virtual server or a dedicated server through the [Gcore&nbsp;Hosting&nbsp;Portal](https://hosting.gcore.com/billmgr). Each action is an HTTP POST to `https://hosting.gcore.com/billmgr`. The `func` parameter selects the action.

<Info>
Each call signs in with the existing Hosting Portal account. Company details and the source IP address are collected on the [reseller&nbsp;page](/hosting/become-reseller-and-resell-our-services).

Support adds that IP address to the allow list and adds the account to the reseller group. A call from any other address gets no response.
</Info>

## Authenticate

`authinfo` is the Hosting Portal username and password, separated by a colon. `out=json` selects a JSON response. Send both on every call. The password stays in the POST body.

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.pricelist" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json"
```

## Read a failed call

A failed call still returns HTTP 200. The failure text is in `doc.error.msg`. A successful list has `doc.list` and no `doc.error`. Read `doc.error` before using the list.

## Tariffs available to order

The virtual server catalog:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.pricelist" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json"
```

The dedicated server catalog:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.dedic.order.pricelist" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json"
```

The response lists the tariffs the account can order. Each item has the tariff id in `pricelist`, the name in `title`, the location, and the price for one, three, six, and 12 months. The location is the `datacenter` object on the tariff (`id` and `value`). A client account has no separate data center list.

Text values sit in `$`. `period` is a number of months. This object is one tariff returned by `v2.vds.order.pricelist` on the Gcore Hosting Portal:

```json
{
  "pricelist": { "$": "172456" },
  "title": { "$": "KVM-HIGHCPU-SSD-1-SY4" },
  "datacenter": {
    "id": { "$": "13" },
    "value": { "$": "Australia, Sydney" }
  },
  "prices": {
    "price": [
      {
        "period": { "$": "1" },
        "cost": { "$": "14.99" },
        "currency": { "$": "EUR" }
      }
    ]
  }
}
```

## Order a virtual server

Take `pricelist` and `datacenter.id` from the catalog. This call opens the order form and does not place the order:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.param" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json" \
  --data-urlencode "pricelist=172456" \
  --data-urlencode "datacenter=13" \
  --data-urlencode "period=1"
```

The form returns `domain` (the server name), `ostempl` (the operating system), and `order_period` (`1`, `3`, `6`, or `12`). Read `ostempl` from this response. Ubuntu 22.04 is `VM6_ISPsystem_Ubuntu-22.04`. The form also returns `addon_*` fields for that tariff. `{TODO: verify - which addon fields the order requires}`

The same function with `sok=ok` submits the order. The charge comes from the account balance:

```bash
curl -s -X POST "https://hosting.gcore.com/billmgr" \
  --data-urlencode "func=v2.vds.order.param" \
  --data-urlencode "authinfo=USER:PASSWORD" \
  --data-urlencode "out=json" \
  --data-urlencode "pricelist=PRICELIST" \
  --data-urlencode "datacenter=DATACENTER" \
  --data-urlencode "period=1" \
  --data-urlencode "order_period=1" \
  --data-urlencode "domain=server1.example.com" \
  --data-urlencode "ostempl=OS_TEMPLATE" \
  --data-urlencode "sok=ok"
```

`pricelist`, `datacenter`, `order_period`, `domain`, and `ostempl` come from the catalog and the form. A request without `sok=ok` changes nothing. `{TODO: verify - the response body after sok=ok. This submit was not sent}`

## Pay for the order

The partner adds funds to the account balance before the first order. A submitted order and a renewal are charged from that balance.

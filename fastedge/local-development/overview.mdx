FastEdge applications can be scaffolded, built, and tested entirely outside the Customer Portal, before anything reaches the edge. Three tools cover different parts of that workflow: an AI plugin that automates the full cycle through natural language, an editor extension with a visual debugger, and a headless test framework built for CI.

## Tool comparison

Each tool targets a different point in the development cycle, and the choice depends on how much of the workflow needs to run through an editor versus a script:

| Tool | Best for | Requires |
|------|----------|----------|
| AI-assisted development | Scaffolding, building, and deploying through natural-language requests in Claude Code or Codex | Docker, an API token |
| FastEdge extension | Interactive debugging with a request builder inside VS Code | VS Code, the language toolchain |
| Test framework | Headless test suites in CI, or the same debugger without an editor | Node.js |

[AI-assisted&nbsp;development](/fastedge/local-development/ai-assisted-development) covers the [gcore-fastedge](https://github.com/G-Core/FastEdge-plugin) plugin and its bundled [MCP&nbsp;server](https://github.com/G-Core/FastEdge-mcp-server), including setup for Claude Code, Codex, and other MCP clients.

The [FastEdge&nbsp;extension](/fastedge/local-development/vscode-extension) builds and debugs applications through a bundled visual debugger without leaving VS Code.

The [Test&nbsp;framework](/fastedge/local-development/test-framework) article covers the fastedge-test package for headless CI suites and the same browser debugger the VS Code extension bundles.

Source code and issues for gcore-fastedge and FastEdge-mcp-server are on the same GitHub organization as [FastEdge-vscode](https://github.com/G-Core/FastEdge-vscode) and [FastEdge-test](https://github.com/G-Core/FastEdge-test).

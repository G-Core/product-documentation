Gcore MCP Server runs from `uv` and reads its settings from environment variables. Client configuration is in [Connect&nbsp;Claude&nbsp;Code](/developer-tools/mcp-server/connect-claude-code-to-gcore-mcp-server) and [Connect&nbsp;Cursor&nbsp;IDE](/developer-tools/mcp-server/connect-cursor-to-gcore-mcp-server).

**Install uv**

Gcore MCP Server runs via `uvx`, which is part of the `uv` package manager.

<Tabs>
<Tab title="macOS/Linux">

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

</Tab>
<Tab title="Windows">

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

After installation, restart the terminal to update PATH.

</Tab>
</Tabs>

Verify the installation:

```bash
uv --version
```

**Create a Gcore API token**

Create an [API&nbsp;token](/account-settings/api-tokens) with permissions matching the products to be used. Required roles per product are in [API&nbsp;token&nbsp;permissions](/developer-tools/mcp-server/gcore-mcp-server-overview#api-token-permissions).

<Warning>
The API token is displayed once and cannot be retrieved later. Store it securely and do not commit it to version control.
</Warning>

## Install the server

<Tabs>
<Tab title="Temporary (uvx)">

`uvx` runs the server in a temporary environment without installing it permanently. The AI client handles this automatically using the `uvx` command in its configuration. No manual step is needed.

To verify the server starts correctly, run it directly:

```bash
uvx --from "gcore-mcp-server@git+https://github.com/G-Core/gcore-mcp-server.git" gcore-mcp-server
```

Pin a specific version by appending the tag:

```bash
uvx --from "gcore-mcp-server@git+https://github.com/G-Core/gcore-mcp-server.git@v0.1.1" gcore-mcp-server
```

<Info>
If the AI client shows "Failed to connect to MCP server", verify that `uv` is installed (`uv --version`) and test the `uvx` command directly from the terminal. A missing comma or bracket in the config file also prevents loading.
</Info>

</Tab>
<Tab title="Persistent (uv tool)">

Install as a global command available system-wide:

```bash
uv tool install "gcore-mcp-server@git+https://github.com/G-Core/gcore-mcp-server.git"
```

If `gcore-mcp-server` is not found after installation, run `uv tool update-shell` or add the `uv` tool bin directory to `PATH`.

Use `gcore-mcp-server` as the command in the AI client configuration instead of the `uvx` command.

</Tab>
</Tabs>

## Environment variables

The server starts in dynamic mode when `GCORE_TOOLS` and `GCORE_MCP_MODE` are unset. Pattern syntax is in [Tool&nbsp;filtering](/developer-tools/mcp-server/filter-tools-with-gcore-tools).

| Variable | Required | Effect |
|----------|----------|--------|
| `GCORE_API_KEY` | For API calls | API token. Unset, the server still lists tools and every call fails. |
| `GCORE_MCP_MODE` | No | `dynamic` or `direct`. Unset, together with an empty `GCORE_TOOLS`, selects dynamic mode. |
| `GCORE_TOOLS` | No | SDK path patterns. Unset, the six dynamic tools reach all 817 operations. A value that matches nothing exits with status 2. Set without `GCORE_MCP_MODE`, it selects direct mode. |
| `GCORE_DENY_TOOLS` | No | Patterns to hide from search and from direct mode. |
| `GCORE_READ_ONLY` | No | `true` allows read operations only. |
| `GCORE_CODE_EXECUTION` | No | `false` removes `execute_code`. The default tool list includes it. |
| `GCORE_TRANSPORT` | No | `stdio` or `http`. `sse` exits with status 2. |
| `GCORE_PORT` | No | Port for `GCORE_TRANSPORT=http`. |
| `GCORE_CLOUD_PROJECT_ID` | No | Optional project pin. |
| `GCORE_CLOUD_REGION_ID` | No | Optional region pin. |

<Info>
Requests that return "401 Unauthorized" indicate an invalid or expired API token. Verify the token in the [Gcore Customer Portal](/account-settings/api-tokens) and check that it has permissions for the requested product.
</Info>

## Project and region

`cloud.instances.list` with `project_id` and `region_id` omitted returns `_scope.project` for the account default project. The response note says every active region was searched, and each item includes `region_id`. The schema for `project_id` says the default project is used except for destructive operations. The schema for `region_id` says list operations search every region and other operations need a region.

`GCORE_CLOUD_PROJECT_ID` and `GCORE_CLOUD_REGION_ID` are optional. Add them to the client `env` block only to pin calls:

```json
"GCORE_CLOUD_PROJECT_ID": "PROJECT_ID",
"GCORE_CLOUD_REGION_ID": "REGION_ID"
```

Find the IDs by asking the client to list projects and regions, or from the URL at **Cloud** > **Projects** in the [Gcore Customer Portal](https://portal.gcore.com).

## Read-only mode and approval

`GCORE_READ_ONLY=true` rejects writes. In direct mode the write and destructive tools are absent. In dynamic mode the client receives `search_tools`, `get_tool_schema`, `call_read_tool`, and `execute_code`. A write passed to `call_read_tool` returns an error that the server is in read-only mode.

`GCORE_TRANSPORT=http` starts read-only and logs that `GCORE_READ_ONLY=false` is required to allow changes. The session URL is `http://127.0.0.1:<port>/mcp`. `GET /sse` returns 404.

With the default confirmation behavior, `dns.zones.delete` returns `CONFIRMATION REQUIRED` and the text "This call was NOT executed." Repeating the call is what sends it. `cloud.instances.create` and `dns.zones.create` do not set `requires_confirmation`.

<Info>
Requests that return "429 Too Many Requests" are rate limited. Retry after the Retry-After interval when the response includes that header.
</Info>

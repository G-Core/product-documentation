MIG partitions a supported NVIDIA GPU into isolated GPU instances that can be assigned to individual workloads. In Everywhere AI, configure the MIG profiles on the cluster, apply a profile to GPU nodes, and create corresponding MIG flavors for workloads.

<Steps>

<Step title="Configure MIG in config.yaml">

Add an `apps.gpuOperator.mig` section to `config.yaml`. The section controls the MIG strategy and the mig-parted configuration pushed to the GPU Operator.

<Tabs>

<Tab title="Default">

```yaml
apps:
  gpuOperator:
    mig:
      strategy: "single"
      config:
        default: "all-disabled"
        create: false
        name: ""
        data: {}
```

</Tab>

<Tab title="Custom mixed profile">

```yaml
apps:
  gpuOperator:
    mig:
      strategy: "mixed"
      config:
        default: "all-disabled"
        create: true
        name: custom-mig-config
        data:
          config.yaml: |-
            version: v1
            mig-configs:
              all-disabled:
                - devices: all
                  mig-enabled: false
              custom-mig:
                - devices: [0, 1, 2, 3, 4, 5, 6]
                  mig-enabled: false
                - devices: [7]
                  mig-enabled: true
                  mig-devices:
                    "1g.10gb": 7
```

</Tab>

</Tabs>

**Parameter reference:**

| Parameter | Description |
|-----------|-------------|
| `mig.strategy` | Controls how the device plugin exposes MIG resources to Kubernetes. `single` — all MIG instances on a node are exposed under unified resource names (all GPUs must use the same geometry). `mixed` — each GPU's instances are exposed individually, allowing different geometries per GPU on the same node. |
| `mig.config.create` | `true` — create a ConfigMap from `mig.config.data`. `false` — use the GPU Operator's built-in default profiles. |
| `mig.config.name` | Name of the mig-parted ConfigMap. Leave empty to use the operator default. |
| `mig.config.default` | Profile applied to nodes that have no `nvidia.com/mig.config` label. Use `all-disabled` to leave GPUs whole until explicitly labeled. |
| `mig.config.data` | mig-parted configuration content. Each named entry under `mig-configs` is a profile that can be referenced by a node label. |

After editing `config.yaml`, apply the change:

```bash
box-installer --config config.yaml release update
```

This opens a pull request in Gitea with the rendered configuration diff. Merge the PR (or use `--auto-merge`) and wait for Argo CD to converge.

</Step>

<Step title="Label nodes with a MIG profile">

The MIG Manager watches the `nvidia.com/mig.config` node label and applies the corresponding profile from the ConfigMap. After the GPU Operator reconfigures, label each GPU node to partition:

```bash
kubectl label node <node-name> nvidia.com/mig.config=custom-mig --overwrite
```

To verify the profile was applied and MIG instances are visible to Kubernetes:

```bash
kubectl describe node <node-name> | grep -E "mig.config.state|nvidia.com/mig-"
```

When successful, the output includes `nvidia.com/mig.config.state: success` and the MIG capacity entries — `nvidia.com/mig-1g.10gb: 7` for the example profile above. If `mig.config.state` shows `pending` or `failed`, the MIG Manager has not yet completed or encountered an error — check the `gpu-operator` namespace pod logs.

To leave a node unpartitioned (whole GPU):

```bash
kubectl label node <node-name> nvidia.com/mig.config=all-disabled --overwrite
```

Nodes without the label receive the profile specified in `mig.config.default`.

</Step>

<Step title="Create MIG flavors">

With MIG instances now available on the node, create a flavor that exposes them to workloads.

Navigate to **Capacity** > **Flavors**, click **Create Flavor**, and enable **GPU accelerator**. Configure the GPU settings:

- **GPU Mode**: **MIG Fractured**
- **GPU Type**: the GPU model installed on the partitioned node
- **GPU Count**: the number of MIG instances allocated to each workload

<img src="./img/create-flavor-gpu-modes.png" alt="Create Flavor form with GPU accelerator enabled, showing Full GPU, MIG Fractured, and HAMi Fractured mode options" />

Enter the flavor **Name**, select **Product affiliation** if the flavor should be limited to specific products, set **vCPU Count** and **RAM Size**, then click **Create**. The flavor becomes available when creating inference instances, Jupyter notebooks, and Slurm worker sets.

</Step>

</Steps>

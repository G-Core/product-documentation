Flavors are predefined resource profiles that specify CPU, memory, and GPU allocations for workloads. Standardized flavors simplify deployment decisions and enable consistent capacity planning.

Navigate to **Capacity** > **Flavors** to manage flavor configurations.

![Flavors page showing list of available flavors with filters and Create Flavor button](/images/docs/everywhere-ai/admin/capacity/manage-flavors/flavors-management-list.png)

Each flavor displays: **Name**, **GPU Type**, **GPU Count**, **vCPU Count**, **GPU RAM Size**, and **RAM Size**. Use the search box to find flavors by name, or apply filters for GPU type, GPU count, vCPU count, GPU RAM, and RAM ranges.

## Create a flavor

Flavors should follow a naming convention that communicates resource allocation. Examples: `inference-16vcpu-232gib-1xl40s-48gb` (16 vCPU, 232 GiB RAM, 1x L40S GPU), `1vcpu-1024mb-0gpu` (1 vCPU, 1 GiB RAM, no GPU).

1. Click **Create Flavor**.
2. Enter a **Name**. Names must use lowercase letters, digits, and hyphens, start and end with a letter or digit, and not exceed 63 characters.
3. Optionally select **Product affiliation** to restrict the flavor to specific products. Leave empty to make it available for all products.
4. Set **vCPU Count** and **RAM Size (GiB)**.
5. To add GPU resources, enable **GPU accelerator** and configure:
   - **GPU Mode**: select how the GPU is exposed to the workload.
     - **Full GPU** — the workload gets the entire physical GPU.
     - **MIG Fractured** — hardware-partitioned GPU slice (requires MIG to be configured on the cluster). MIG setup is in [MIG&nbsp;partitioning](/everywhere-ai/admin/capacity/configure-gpu-mig).
     - **HAMi Fractured** — software-virtualized GPU share (requires `featureGates.hami.enabled: true` in `config.yaml`).
   - **GPU Type**: select the GPU model.
   - **GPU Count**: set the number of GPU units (or MIG slices) assigned to the workload.
6. Click **Create**.

## Delete a flavor

Click the delete icon next to any flavor to remove it from the catalog.


<Warning>
Deletion fails if active workloads use the flavor. Before deleting, navigate to **Resources** > **Instances**, filter by the flavor name, and verify no instances appear. Migrate or terminate existing workloads before attempting deletion.
</Warning>

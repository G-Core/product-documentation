Navigate to **Resources** > **Nodes** to view all physical servers grouped by region. Use this page to monitor cluster nodes, control workload placement, and prepare nodes for maintenance or hardware service.

![Nodes page showing list of nodes grouped by region with filters, search, and bulk selection controls](/images/docs/everywhere-ai/admin/resource-management/manage-nodes/resource-management-nodes-list.png)

Each node entry shows hostname, status (Active or Maintenance), node group assignment, GPU allocation, and running instance count.

## Group actions

Select one or more nodes using checkboxes, then click **Group actions** to apply batch operations. Checking a region header selects all nodes in that region.

![Group actions dropdown showing maintenance and drain options](/images/docs/everywhere-ai/admin/resource-management/manage-nodes/resource-management-nodes-group-actions.png)

| Action | Effect | Use case |
|--------|--------|----------|
| Set to maintenance | Prevents new workloads from being scheduled | Preparing nodes for updates or hardware service |
| Exit maintenance | Returns nodes to normal operation | Restoring capacity after maintenance |
| Drain | Evacuates all workloads to other nodes | Clearing nodes before shutdown or hardware replacement |

Draining a node does not automatically place it into maintenance mode. Set maintenance first to prevent new workloads from being scheduled during evacuation.

## Node details

Click a node to open **Node Overview**. **Node summary** shows the GPU model, CPU, RAM, and local storage, with the running instances listed below. The panel provides controls for individual node maintenance and workload relocation.

![Node Overview panel with GPU, CPU, RAM, local storage, and the running instances list](/images/docs/everywhere-ai/admin/resource-management/manage-nodes/resource-management-node-details.png)

Each running instance can be relocated individually using the **Deschedule** action. The panel also provides **Set to maintenance** and **Drain** buttons for individual node operations.


<Warning>
Drain operations fail if the cluster does not have enough available CPU, memory, or GPU capacity to host the evacuated workloads.
</Warning>


## Maintenance workflow

Maintenance mode prevents new workload placement, while drain relocates workloads that are already running.

To take a node offline for hardware service:

1. Click the target node to open details.
2. Click **Set to maintenance** to prevent new placements.
3. Click **Drain** to evacuate existing workloads.
4. Perform hardware service.
5. Click **Exit maintenance** to restore normal operation.

Cluster health metrics appear on the [Dashboard](/everywhere-ai/admin/dashboard/dashboard). Node groups are managed in [Manage&nbsp;node&nbsp;groups](/everywhere-ai/admin/resource-management/manage-node-groups). Individual instances are relocated on the [Instances](/everywhere-ai/admin/resource-management/manage-instances) page.

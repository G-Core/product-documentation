---
title: "Enable Virtual Machines"
description: "Enable Virtual Machine support on an Everywhere AI cluster. StorageClass setup, hypervisor nodes, gateway config, and"
---

Virtual Instances require additional cluster infrastructure for compute, storage, and networking. VM support is disabled by default; prepare the required infrastructure first, then enable it in `config.yaml`.

<Steps>

<Step title="Annotate StorageClasses">

Every StorageClass that will be used for VM volumes — including the scratch space class — must carry these annotations:

```yaml
annotations:
  storage.gcore.com/access-modes: ReadWriteOnce,ReadOnlyMany,ReadWriteMany
  storage.gcore.com/volume-modes: filesystem,disk
  storage.gcore.com/scope: global
```

The `scratchSpaceStorageClass` field in the feature gate config references the class used by CDI for temporary storage during image imports. It must also carry these annotations.

</Step>

<Step title="Add hypervisor nodes">

Virtual Machines run only on bare-metal nodes with the KubeVirt label and taint. Add at least one such node to the cluster:

```yaml
nodeSelector:
  node-role.kubernetes.io/kubevirt: ""
taints:
  - key: node-role.kubernetes.io/kubevirt
    effect: NoSchedule
```

Infrastructure components (virt-controller, virt-api, cdi-controller) run on `worker-infra` nodes and do not require bare-metal hardware.

</Step>

<Step title="Configure gateway nodes">

VM networking requires gateway nodes with access to the external (public) network. Two configurations are supported:

**Option one — Dedicated gateway nodes**

Add dedicated gateway nodes and label them:

```
node-role.kubernetes.io/ovn-gw: ""
```

**Option two — Hypervisors as gateways**

If all hypervisor nodes have a second interface connected to the external subnet, label each hypervisor with:

```
node-role.kubernetes.io/ovn-gw: ""
```

In both options, the public interface on gateway nodes must have port-security disabled.

</Step>

<Step title="Enable in config.yaml">

Add the full `virtualMachines` block under `featureGates` in `config.yaml`:

```yaml
featureGates:
  virtualMachines:
    enabled: true
    scratchSpaceStorageClass: "<storage-class-name>"
    network:
      pubNetInterfaceName: "<interface-name>"
      pubNetNodes: "<gw-node-1>,<gw-node-2>"
      cidrBlock: "<public-cidr>"
      gateway: "<gateway-ip>"
      excludeIps:
        - "<first-reserved-range-start>..<first-reserved-range-end>"
        - "<second-reserved-range-start>..<second-reserved-range-end>"
    defaultProjectName: "kubevirt-images"
    pullSecretName: "kubevirt-images-registry"
```

| Field | Description |
|-------|-------------|
| `scratchSpaceStorageClass` | StorageClass for CDI scratch volumes during image imports. Must carry the StorageClass annotations described in the prerequisites. |
| `network.pubNetInterfaceName` | Physical interface name on gateway nodes connected to the public network — `enp4s0` is a common value. |
| `network.pubNetNodes` | Comma-separated list of gateway node hostnames. |
| `network.cidrBlock` | Public IP range to allocate to VMs. |
| `network.gateway` | Default gateway for the public network. |
| `network.excludeIps` | IP ranges within `cidrBlock` that must not be assigned to VMs. Specify ranges reserved for infrastructure or other uses. |
| `defaultProjectName` | Registry project containing Gcore OS images. Default: `kubevirt-images`. |
| `pullSecretName` | Secret name for authenticating to the image registry. Default: `kubevirt-images-registry`. |

Apply the change:

```bash
box-installer --config config.yaml release update
```

This opens a pull request in Gitea with the configuration diff. Merge the PR (or use `--auto-merge`) and wait for Argo CD to converge. Once deployed, the **Virtual Instances** section becomes available to users in Everywhere AI.

</Step>

</Steps>

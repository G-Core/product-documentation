---
title: "Manage releases"
description: "Use box-installer release commands to deliver Everywhere AI updates, apply configuration changes, and track installed versions without"
---

After the initial installation, use `release` commands to deliver updates or apply configuration changes without repeating the full installation sequence. A release update opens a pull request in Gitea with the rendered changes; after the PR is merged, `release finalize` records the new state.

## Update

Deliver a new installer release or apply configuration changes to the cluster:

```bash
box-installer --config config.yaml release update
```

`release update` computes the diff between the current cluster state and the new installer or config, then opens a PR in Gitea. If the PR is clean (no conflicts), it can be merged automatically:

```bash
box-installer --config config.yaml release update --auto-merge
```

To merge the PR and wait for Argo CD to apply the changes and become healthy in a single command:

```bash
box-installer --config config.yaml release update --wait
```

## Finalize

After the PR is merged manually in Gitea, record the new release state in the cluster:

```bash
box-installer --config config.yaml release finalize
```

To wait until Argo CD reports all applications healthy before recording:

```bash
box-installer --config config.yaml release finalize --wait
```

`release finalize` writes the desired version and the resolved health state to the cluster CRD. Without `--wait`, it records whatever Argo CD reports at the moment of the call. Pass `--wait` to confirm convergence before marking the release complete.

## Show

Print the release state last recorded in the cluster:

```bash
box-installer --config config.yaml release show
```

The output includes the current version, any in-flight update attempt, per-region view, and Argo CD health.


<Info>
`release show` is not a live view. It reflects what the installer last recorded during `install finalize`, `release update`, or `release finalize`.
</Info>

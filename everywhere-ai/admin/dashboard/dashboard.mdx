The Dashboard displays real-time health metrics for the Everywhere AI cluster.

Use this page to monitor resource utilization across regions and identify capacity issues before they affect users.

![Dashboard overview showing Nodes, GPU, RAM, and vCPU panels with cluster-wide metrics](/images/docs/everywhere-ai/admin/dashboard/dashboard/dashboard-overview-3.png)

## Filter by region

The page header includes a global region filter. Select **All regions** to view aggregated data from all regions, or choose a specific region to focus on local metrics. Each panel also has its own region selector for independent filtering.

![Region filter dropdown showing All regions and the list of available regions](/images/docs/everywhere-ai/admin/dashboard/dashboard/dashboard-region-filter-3.png)

## Nodes panel

The Nodes panel displays server availability and status. **Total Nodes** shows the cluster size, while the status breakdown separates **Allocated** nodes (running workloads), **Maintenance** nodes (not accepting new workloads), **Unhealthy** nodes (requiring attention), and **Free** nodes (ready for new deployments).

Click **Node details by location** to expand the regional breakdown table, which helps identify imbalances where some regions have excess capacity while others are fully utilized.

## GPU, Total RAM, and Total vCPU panels

The **GPU** panel shows total GPU utilization as a percentage of compute capacity in use, plus a per-GPU breakdown showing allocated count and utilization for each GPU model present in the cluster.

The **Total RAM** panel shows memory allocation in GiB (allocated / total) with utilization percentage. The **Total vCPU** panel displays virtual CPU allocation. Both panels visualize allocated vs free capacity for capacity planning.

![GPU, RAM, and vCPU panels showing utilization and allocation metrics](/images/docs/everywhere-ai/admin/dashboard/dashboard/dashboard-gpu-ram-vcpu-3.png)

## Registries and Users panels

The **Registries** panel displays container registry storage: total capacity in GiB, number of configured registries, and allocated vs free space. Monitor this to prevent projects from running out of registry storage.

The **Users** panel shows adoption metrics: active projects, total user accounts, and configured user groups. These counts help with capacity planning and license tracking.

![Registries and Users panels showing storage allocation and user adoption metrics](/images/docs/everywhere-ai/admin/dashboard/dashboard/dashboard-registries-users-3.png)

## Daily monitoring workflow

Start by reviewing global metrics for GPU, vCPU, and RAM utilization to assess overall health. Check node status for unhealthy or maintenance nodes — these need attention before they affect users. If any metrics show concerning values, switch to regional view to isolate the affected data center.


<Warning>
Pay attention to per-GPU-family utilization. Imbalances cause placement failures even when aggregate capacity appears healthy. Free nodes may lack the specific GPU types that workloads require — GPU placement is strict and workloads cannot use nodes without the requested accelerator hardware.
</Warning>


When issues are identified, navigate to [Nodes](/everywhere-ai/admin/resource-management/manage-nodes) to take corrective action.

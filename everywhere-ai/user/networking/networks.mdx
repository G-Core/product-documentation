title: "Networks"

A network provides private connectivity for Virtual Instances within a region. Instances attach to subnets rather than directly to the network — each subnet defines its own IP range, gateway, and DNS configuration. A network must contain at least one subnet before an instance can connect to it. The subnet can be created immediately or added later.

Open **Compute Instances** > **Networking** > **Networks**.

![Networks list showing two entries with region and creation date](/images/docs/everywhere-ai/user/networking/networks/networks-list.png)

## Create a network and subnet

<Steps>

<Step title="Name and region">

Click **Create Network**, enter a name, and select a region — the network is available only in that region, so instances must be in the same region to connect. Enable **Static Routes** if custom routing rules are needed. Click **Create & Proceed**.

![Create Network dialog with Network name, Region selector, and Static Routes toggle](/images/docs/everywhere-ai/user/networking/networks/create-network-step1.png)

</Step>

<Step title="Subnet settings">

1. Enter the **Subnetwork Name**.
2. Specify the **CIDR IPv4** range. Instances receive an address from this block — each instance connects to a specific subnet, not to the network as a whole.
3. **Enable DHCP** controls whether instances receive their IP address, gateway, and DNS servers automatically on boot. Leave it on unless static assignment is required.
4. **Gateway IP**: **Automatic** reserves the first usable address in the block as the gateway (`10.0.0.1` for `10.0.0.0/24`). Select **Specific** to use a different address — it must fall within the CIDR.
5. **Custom DNS** replaces the default nameservers (`8.8.8.8` / `8.8.4.4`). The servers are delivered to instances via DHCP, so they won't be received automatically if DHCP is disabled.
6. Click **Create subnetwork**, or **Skip for now** to add a subnet later.

![Create Subnetwork form showing CIDR, DHCP toggle, Gateway IP, and Custom DNS fields](/images/docs/everywhere-ai/user/networking/networks/create-subnetwork-form.png)

</Step>

</Steps>

Each network is connected to an external gateway with SNAT enabled by default, so instances get outbound internet access. Instances in different networks cannot reach each other privately — when connectivity between instance groups is needed, use subnets within the same network rather than separate networks.

## Manage subnets and routing

Open a network to view its subnets. To add another subnet, click **Create subnetwork** — the form uses the same fields as above. To change **Enable DHCP** or **Custom DNS**, click **...** next to the subnet and select **Edit**. The name, **CIDR IPv4**, and **Gateway IP** cannot be changed after creation.

![Network details page showing subnet list and Create subnetwork button](/images/docs/everywhere-ai/user/networking/networks/network-details.png)

Static routes operate at the network level and take precedence over the default route for matching destinations. To configure them, select the **Static Routes** tab, enable the toggle, and add entries — each entry specifies a **Destination** CIDR and a **Nexthop** address. Click **Save changes**.

## Delete network resources

Networks must have all subnets removed before deletion. Delete each subnet using its menu icon (three dots) → **Delete**, then delete the network the same way.

![Network details page showing subnet menu with Edit and Delete options](/images/docs/everywhere-ai/user/networking/networks/network-subnet-delete.png)

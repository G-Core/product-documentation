title: "Security Groups"
description: "Create and manage security group firewall rules for Virtual Instances in Everywhere AI."
---

Each network interface on a Virtual Instance carries the security groups assigned to it. Traffic is filtered by their rules — inbound packets are blocked unless a rule permits them, and within each group outbound packets are unrestricted until that group defines an outbound rule; once a group has an outbound rule, only traffic matching a rule in that group is allowed. Assigning multiple groups to one interface combines all their rules, so adding a group can only open more traffic, never block it.

Manage security groups under **Compute Instances** > **Networking** > **Security Groups**.

![Security Groups list showing one default security group for each region](/images/docs/everywhere-ai/user/networking/security-groups/security-groups-list.png)

## Default security group

When a new interface gets no security group, Everywhere AI assigns the region's default group automatically. That default allows inbound SSH (port 22) and ICMP from any IPv4 address, and all outbound traffic — enough to let the instance initiate outbound connections. Inbound rules do not prevent communication between instances in the same security group.

![Default security group showing ICMP and SSH inbound rules and ALL outbound](/images/docs/everywhere-ai/user/networking/security-groups/security-group-default-rules.png)

The default group can be modified to open or close specific ports. To reset it back to the original three rules, click **Restore default rules** — a confirmation dialog warns that all current rules will be replaced. The default group cannot be deleted.

## Create a security group

A new group starts empty — all inbound blocked, all outbound open. Click **Create Security Group**, select a region, optionally add [rules](#rules), enter a name, and confirm. Until inbound rules are defined, this group permits no inbound traffic.

## Rules

Click **Add rule** in the inbound or outbound section, then select a rule type from the dropdown.

![Add Rule dialog with Type, Protocol, Port, Ethernet type, Remote IP Prefix, and Remote Security Group fields](/images/docs/everywhere-ai/user/networking/security-groups/security-group-add-rule.png)

The preset types (SSH, HTTP, HTTPS, MySQL, DNS, and others) fill in protocol and port automatically. **Custom** covers any service without a preset — select the protocol (TCP, UDP, ICMP, or ALL), enter the port, and set the Ethernet type (IPv4 or IPv6; defaults to IPv4). For ICMP or ALL, leave the port blank.

The remote side of a rule — the source for inbound, the destination for outbound — is defined by a CIDR in **Remote IP Prefix**, a reference to another security group in **Remote Security Group**, or both. When both fields are set, the rule permits traffic that satisfies either condition. A CIDR of `0.0.0.0/0` matches any IPv4 address; a narrower block like `10.0.0.0/8` limits the rule to a specific range. A security group reference targets instances by group membership rather than IP address, which is useful when addresses are not fixed.


<Warning>
A rule with `0.0.0.0/0` matches any IPv4 address as the remote source or destination, depending on the rule direction. For inbound rules, use a specific CIDR when the service does not need to be publicly accessible.
</Warning>


Within a group, outbound traffic is unrestricted until that group defines an outbound rule — after that, only traffic matching an explicit rule in that group is allowed. Port 25 (SMTP) is an infrastructure-level exception: it is blocked for all outbound traffic regardless of rules; contact support to unblock it.

## Manage security groups

Rules take effect immediately when added, edited, or removed. The default group cannot be deleted; all other groups can be removed through the menu icon (three dots) next to them in the list.

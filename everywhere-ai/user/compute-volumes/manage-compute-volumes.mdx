---
title: "Compute Volumes"
description: "Create, attach, detach, resize, and delete compute volumes for a virtual instance in the same region."
---

Stopping an instance does not delete the data on its volumes. After a volume is detached or the instance is deleted, the volume remains available and can be attached again in the same region. A **Boot Volume** holds the OS and cannot be resized, detached, or deleted while its instance is running.

Open **Compute Volumes** under **Compute Instances**.

Search by volume name or filter by **Region**, **Storage class**, or **Access**. The status shows the volume state: an **Available** volume can be attached, an **Attached** volume shows the instance it is connected to, and **Pending** means that creation or an update is still in progress.

## Create

Open **Compute Volumes** and click **Create Volume**.

The region chosen here is permanent, so the storage classes and instances below are only those in that region.

Under **Choose Volume type**, an empty disk is a **Data Volume**, while the OS disk is a **Boot Volume** from a public image or from **Custom Image**. A custom image needs a direct HTTP(S) URL to a bootable image.

Size is a whole number of GiB, from 1 GiB to 16384 GiB, and it can only grow. A boot image raises that floor to the minimum shown for the image.

Each storage class card shows the access mode. **Single-node read/write** means the disk is not shared. Under **Boot Volume**, a class without disk-volume support stays disabled.

Leave **Attach to an Instance** empty unless an instance in that region should take the disk now. Click **Create**. The volume stays **Pending** while it is created. With no instance selected, it then becomes **Available**. If it is attached during creation, it becomes **Attached**.


<Warning>
The storage class cannot be changed after the volume is created.
</Warning>


## Attach

On an **Available** volume, click **Attach to Instance**, select an instance in the same region, and click **Attach**. The row then names that instance, and the status changes to **Attached**.

The instance can also take the disk from its **Volumes** tab, where [Manage&nbsp;Virtual&nbsp;Instances](/everywhere-ai/user/virtual-instances/manage-virtual-instances) covers **Add Volume**: a new empty disk, or a volume that is already detached.

During instance creation, **Add Boot Volume** creates the OS disk, while **Data Volume** and **Existing Volume** in that dialog stay disabled, so a data volume is attached after the instance exists.

## Detach

Open **...** on the volume row and select **Detach**.

The data stays on the disk, but a running guest can still be writing to it, so stop the instance first or confirm that nothing is writing to the disk. Once it is safe to detach, type `Detach` and click **Detach**. The volume then returns to **Available**.


<Warning>
Detaching a volume from a running instance can cause data loss.
</Warning>


## Resize

Open **...** on the volume row and select **Resize**.

The dialog shows the current size, and the new value must be at least 1 GiB larger. A data volume can be resized while it is still attached, but the guest does not see the extra space until its filesystem is extended. The command depends on the filesystem.


<Warning>
Volume capacity can only be increased.
</Warning>


## Delete

Open **...** on the volume row and select **Delete**.

An attached data volume is detached first, so a running instance can lose data.


<Warning>
Deletion permanently removes the volume and its data.
</Warning>

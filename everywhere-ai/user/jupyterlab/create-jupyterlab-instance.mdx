JupyterLab is a web-based interactive development environment for working with Jupyter notebooks, code, and data. Everywhere AI provides managed JupyterLab instances with configurable CPU and GPU resources.

JupyterLab is designed for interactive work: exploring datasets, prototyping models, and running experiments. For production model serving, use Inference Instances; for batch training jobs, use Slurm clusters.

## Create an instance


<Warning>
The instance name and region cannot be changed after creation. The volume must be in the same region as the instance.
</Warning>


![JupyterLab Instances page with Create JupyterLab Instance button](/images/docs/everywhere-ai/user/jupyterlab/create-jupyterlab-instance/jupyterlab-empty-state.png)

1. Navigate to **Training** > **JupyterLab** and click **Create JupyterLab Instance**.
2. In **Placement**, select the region.
3. In **Flavor**, select the hardware type — **CPU-optimized** for data exploration and lightweight workloads, **GPU-optimized** for model training and deep learning — then select a flavor from the dropdown. Some flavors may be temporarily unavailable due to capacity constraints.
4. In **Volume**, select an existing volume from the **Volume name** dropdown or click **+ Create volume** to create one inline. Volumes from other regions are grayed out — select the region first to filter the list. Volume options are on [Volumes](/everywhere-ai/user/volumes/manage-volumes).
5. In **Name**, enter a unique identifier. The name becomes part of the connection endpoint.
6. Click **Create**.

![Create JupyterLab Instance form with Placement, Flavor, Volume, and Name sections](/images/docs/everywhere-ai/user/jupyterlab/create-jupyterlab-instance/jupyterlab-create-form.png)

The instance moves through the following states:

| Status | Description |
|--------|-------------|
| Deploying | Instance is being provisioned |
| Ready | Instance is running and accessible |
| Unknown | Instance state cannot be determined |

## Access the instance

The instances list shows all JupyterLab instances with their status. Hover over the info icon in the endpoint column to copy the endpoint URL.

![Instance list with endpoint tooltip showing the URL and Copy button](/images/docs/everywhere-ai/user/jupyterlab/create-jupyterlab-instance/jupyterlab-endpoint-tooltip.png)

Open the URL in a browser to start working in JupyterLab.

## Instance management

### Settings

The flavor and volume of a running instance can be modified on the **Settings** tab. Changing these settings triggers an instance restart — running notebooks are interrupted during the restart.

1. Open the instance details.
2. Click the **Settings** tab.
3. Change the **Hardware**, **Flavor**, or **Volume** as needed.
4. Click **Save changes**.

![Settings tab with Hardware, Flavor, and Volume options](/images/docs/everywhere-ai/user/jupyterlab/create-jupyterlab-instance/jupyterlab-settings-tab.png)

### Delete an instance

Deleting an instance removes the JupyterLab environment but does not affect the attached volume. Data stored on the volume remains available for use with other instances.

1. Open the instance details.
2. Click the **Delete** tab.
3. Click **Delete JupyterLab Instance**.

![Delete tab with Delete JupyterLab Instance button](/images/docs/everywhere-ai/user/jupyterlab/create-jupyterlab-instance/jupyterlab-delete-tab.png)


<Warning>
Deleting an instance stops all running notebooks. Data stored on the attached volume is preserved if the volume is not deleted separately.
</Warning>


## Persistent storage

The attached volume is mounted at `/home/jovyan/work` inside JupyterLab. Files stored in this directory persist across instance restarts and remain available even after the instance is deleted, as long as the volume is not removed.

Files outside `/home/jovyan/work` are not persisted — the home directory and temporary files reset when the instance restarts.

title: "Pull secrets"
description: "Configure pull secrets to authenticate container image pulls from external private registries in Everywhere AI."
---

Pull secrets store authentication credentials for pulling images from external private registries. They provide an alternative when migrating images to a [project registry](/everywhere-ai/user/registries/manage-registries) is not practical.

For most use cases, [project registries](/everywhere-ai/user/registries/manage-registries) are the recommended approach — they provide integrated authentication, full control over access permissions, and no dependency on external services. Pull secrets are needed in specific situations:

- **Legacy images**: Images already stored in an external registry where migration is not feasible due to CI/CD pipeline dependencies or organizational constraints.
- **Third-party images**: Private images from vendors or partners that cannot be copied to a project registry due to licensing or distribution agreements.
- **Transitional period**: Temporary access to external registries while migrating to project registries.

Each pull secret contains three elements: a registry endpoint, login credentials, and a password or token. Credentials are stored encrypted. Once the secret is selected in the instance configuration, its credentials are used automatically when pulling the image.

Pull secrets are project-scoped. A secret created in one project is not visible or usable in other projects.

![Pull Secrets page](/images/docs/everywhere-ai/user/pull-secrets/manage-pull-secrets/pull-secrets-list.png)

## Create a pull secret

Navigate to **Images** > **Pull secrets**, then click **Create Secret**.

Configure the fields in the dialog:

- **Name**: A descriptive identifier that appears in dropdowns when configuring instances. Use names that indicate the registry and purpose (`vendor-models`, `legacy-ml-images`).
- **Registry**: The registry endpoint URL. This must match the prefix of image paths that will use this secret. An incorrect format causes authentication to fail silently during deployment.
- **Login**: Username, token name, or service account identifier depending on the registry.
- **Password**: Password or access token. For token-based authentication, ensure the token has not expired and has sufficient permissions.

Click **Create**. The secret appears in the list immediately.

![Create Secret dialog with Name, Registry, Login, and Password fields](/images/docs/everywhere-ai/user/pull-secrets/manage-pull-secrets/pull-secrets-create-form.png)

### Registry endpoint formats

| Registry | Endpoint |
|----------|----------|
| Docker Hub | `index.docker.io` |
| GitLab Container Registry | `registry.gitlab.com` |
| GitHub Container Registry | `ghcr.io` |
| Self-hosted registries | Use the exact hostname (`registry.example.com`) |

## Credential verification

Before using a pull secret in production deployments, test the credentials locally:

```bash
docker login <registry-endpoint>
```

A successful login confirms the credentials are valid and the endpoint format is correct.

If the login fails, the pull secret will also fail during deployment. Common causes:

- **Expired tokens**: Regenerate the token and update the pull secret.
- **Insufficient permissions**: Verify the account has read access to the specific repository.
- **Wrong endpoint format**: The endpoint must match exactly what the registry expects.
- **Revoked access**: The user account or token may have been deactivated.

## Instance configuration

When creating an inference instance with an image from an external private registry:

1. In the **Image & Port** section, select **Public** for **Registry type**.
2. Enter the full image path in format `<registry>/<namespace>/<image>:<tag>`.
3. Toggle **Add authorization** to reveal the pull secret dropdown.
4. Select the pull secret that matches the registry endpoint.
5. Complete the remaining instance configuration and create the instance.


<Info>
**Public** refers to all external registries (both public and private). **Private** refers to [project registries](/everywhere-ai/user/registries/manage-registries) hosted within the project.
</Info>


## Editing

To update credentials when a token expires or access changes:

1. Click the menu icon next to the secret.
2. Select **Edit**.
3. Update the **Registry**, **Login**, or **Password** fields.
4. Click **Save**.


<Info>
The secret name cannot be changed after creation. To rename a secret, delete it and create a new one.
</Info>


## Deletion

1. Click the menu icon next to the secret.
2. Select **Delete**.
3. Confirm the deletion.


<Warning>
Deleting a pull secret immediately makes it unavailable for new image pulls. If an instance that depends on it restarts or scales, it cannot pull the image and fails to start. Verify no active deployments use the secret before deletion.
</Warning>


## Limitations

**Project scope.** Pull secrets cannot be shared across projects. Each project requiring access to the same external registry needs its own pull secret.

**Immutable name.** The secret name is fixed at creation. Changing a name requires deleting the existing secret and creating a new one, then updating any instances that reference it.

**External registry dependency.** Authentication depends entirely on the external registry. If the registry becomes unreachable, credentials expire, or access is revoked, image pulls fail without detailed error messages.

A Hugging Face model that is not in the [Application&nbsp;Catalog](/everywhere-ai/user/application-catalog/application-catalog) still needs a place for its weights before it can be served. Put the weights on a volume, write them there from JupyterLab, and serve them with a vLLM container that mounts the same volume.

Because JupyterLab and the inference instance mount this same volume, both have to run in its region. Delete the JupyterLab instance before the inference instance mounts the volume, because **Existing Volume** only lists a detached volume, and the weights stay on the volume.

## Deploy the model

<Steps>

<Step title="Create a volume for the weights">

Open **Volumes** > **Volumes** and click **Create Volume**. Select the region where the model will run, keep **Source Type** as **Persistent Storage** so the weights stay on the volume, and select a **Storage Class** from the list for that region. Set **Capacity** large enough for the weights, name the volume, and click **Create**.

![Create Volume dialog with region, persistent storage, storage class, capacity, and name](/images/docs/everywhere-ai/user/custom-inference/deploy-custom-model/create-volume.png)

</Step>

<Step title="Download the weights in JupyterLab">

A CPU flavor can run the download, so open **Training** > **JupyterLab**, click **Create JupyterLab Instance**, select the same region, select **CPU-optimized** under **Hardware**, then select a flavor and this volume. Name the instance and click **Create**.

![Create JupyterLab Instance form with region, flavor, volume, and name](/images/docs/everywhere-ai/user/custom-inference/deploy-custom-model/create-jupyterlab.png)

When the status is **Ready**, the endpoint is on the list and on **Overview**. JupyterLab asks for an access token. [JupyterLab](/everywhere-ai/user/jupyterlab/create-jupyterlab-instance) covers copying that token and opening the notebook.

JupyterLab mounts the volume at `/home/jovyan/work`. Save the weights to `/home/jovyan/work/<model-dir>`.

Later, the inference instance mounts the same volume at `/models`, so the model is available there as `/models/<model-dir>`.

In the notebook, install the Hugging Face library and download the weights into that directory.

```bash
pip install huggingface_hub
```

```python
from huggingface_hub import snapshot_download

snapshot_download(
    repo_id="<repo-id>",
    local_dir="/home/jovyan/work/<model-dir>",
    token="<hf-token>",
)
```

`<repo-id>` is the Hugging Face repository, and `<hf-token>` is a read token for that account. For a gated repository, access has to be approved on the model page before the download succeeds.

When the download finishes, delete the JupyterLab instance from its **Delete** tab. The volume keeps the files.


<Warning>
Until that instance is deleted, the volume stays attached and does not appear under **Existing Volume** on the inference form.
</Warning>


</Step>

<Step title="Serve the volume with vLLM">

The inference instance runs the container that reads the weights from `/models`. On **Inference** > **Inference Instances**, open a **Deployment**. On an empty list, click **Create Deployment**. If instances already exist, click **Create inference instance**, then select **Deployment**.

![Create inference instance form with Deployment selected](/images/docs/everywhere-ai/user/custom-inference/deploy-custom-model/create-inference.png)

Name the instance, leave **Public Registry** selected, and set **Image** to `vllm/vllm-openai:latest`. That image serves an OpenAI-compatible API. Turn on **Set startup command** and set **Executable command** to the following command to serve the model from `/models/<model-dir>`:

```bash
vllm serve --model /models/<model-dir> --host 0.0.0.0 --port 8000 --served-model-name <model-name>
```

`<model-name>` is the value clients send as `model`. The **Container port** field is set to 80 by default; set it to `8000` so it matches `--port`.

![Container image, startup command, and container port on the inference form](/images/docs/everywhere-ai/user/custom-inference/deploy-custom-model/model-image-settings.png)

In **Flavor**, select a GPU flavor capable of running the model. The GPU count and the GPU model are part of that flavor name. Select the same region before **Add Volume**, because the button stays disabled until a region is selected. Select **Existing Volume** and the volume, set **Mount path** to `/models`, and click **Create inference instance**.

</Step>

<Step title="Call the endpoint">

The instance is ready when **Deployment status** is **Active** and, with the default of one replica, the replica line shows **1/1**. The **Endpoint** link on **Overview** is then the base URL. If the replicas do not become ready, open the **Logs** tab.

With no key selected on **API key authentication**, send the request without an Authorization header. After a key from [API&nbsp;keys](/everywhere-ai/user/api-keys/manage-api-keys) is selected there, send that key in the header. Remove the Authorization header below if no API key is associated with the instance.

For a chat model, send a chat completion. `model` is the `<model-name>` from the startup command.

```bash
curl -X POST https://<endpoint-url>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <API_KEY>" \
  -d '{
    "model": "<model-name>",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

</Step>

</Steps>

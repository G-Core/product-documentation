---
title: "Create a Slurm cluster"
description: "Create a Slurm cluster in Everywhere AI, configure login and worker nodes, partitions, storage, optional sidecar containers, and connect"
---

Everywhere AI provides managed Slurm clusters for multi-node training, long-running compute jobs, and parallel workloads. Use Slurm when a workload requires multiple nodes or complex scheduling; for real-time inference, [Inference&nbsp;Instances](/everywhere-ai/user/inference-instances/manage-inference-instances) are a better fit.

A cluster separates access from compute: the **login node** is the SSH entry point for job submission, while **worker nodes** execute the scheduled work through partitions. Login and worker nodes share a persistent volume, so datasets and job outputs remain accessible across the cluster regardless of which nodes a job runs on. Worker nodes can mix CPU and GPU hardware, letting the same cluster serve workloads with different compute requirements.

Multiple clusters can exist in the same project and region. Each cluster is identified by its name, which must be unique within the project.

## Create a cluster

Navigate to the **Training** section and open **Slurm**, then click **Create Cluster**.

![Region and login nodes, with a maximum of five login nodes](/images/docs/everywhere-ai/user/slurm/create-slurm-cluster/slurm-create-form.png)

<Steps>

<Step title="Select a region">

Select the region where the cluster will run. The region cannot be changed after creation.

</Step>

<Step title="Configure access and compute capacity">

Login nodes are the SSH entry point for the cluster. Select their flavor and a node count of at most five, then add at least one key under **Root-user SSH keys**. Supported formats: RSA, ED25519, ECDSA.

Worker node sets define the compute capacity available for jobs. Nodes within a set share the same hardware — to mix CPU and GPU resources or use different hardware configurations in the same cluster, create a separate set for each. For each set, configure the name, hardware type, flavor, and node count. The set name becomes the node hostname prefix. A cluster supports up to 16 worker node sets.

![Worker Node Sets configuration in the create form](/images/docs/everywhere-ai/user/slurm/create-slurm-cluster/slurm-create-worker-node-sets.png)

</Step>

<Step title="Configure job scheduling">

The worker node sets configured above are available to jobs through partitions. The `default` partition includes all of them, so no additional scheduling configuration is needed for a simple cluster.

Create additional partitions when workloads need access to different worker sets or different scheduling rules. Click **+ Add Partition** to configure one.

![Partition form including default memory per GPU](/images/docs/everywhere-ai/user/slurm/create-slurm-cluster/slurm-partition-form.png)

Select the worker node sets the partition can use, then configure the scheduling rules that apply to jobs submitted to it:

- **Max Job Time** — maximum runtime a job can request. Accepts `MM[:SS]`, `HH:MM:SS`, `DD-HH[:MM[:SS]]`, or `UNLIMITED`. Jobs that exceed the limit are terminated.
- **Priority** — scheduling order relative to other partitions. Higher values are scheduled first; the default is 100.
- **Preempt Mode** — whether running jobs can be interrupted for higher-priority ones. Disabled by default.
- **Max Nodes per Job** — caps how many nodes a single job can claim. Leave empty for no limit.
- **Default memory(RAM) per GPU** — RAM allocated per GPU when a job does not request a memory amount. Leave empty for no value.
- **State** — controls whether the partition accepts new submissions:

| State | Behavior |
|-------|----------|
| **Up** | Accepts new job submissions. |
| **Drain** | Lets running jobs finish, but blocks new submissions. |
| **Down** | Stops all scheduling immediately; running jobs are not terminated. |
| **Inactive** | Disables the partition entirely. |

</Step>

<Step title="Configure storage">

The cluster requires a default volume shared by all login and worker nodes. The first volume is mounted at root, holds the shared home directories, and cannot be detached after the cluster is created. Data stored on the nodes themselves is not preserved when the cluster is deleted.

The default volume can be created together with the cluster or attached from an existing one. Click **Add Volume** to open the configuration.

To create new storage, select **Data Volume**, enter a name and size (minimum 25 GiB), and select a storage class. **Single-node read/write** describes the disk. The cluster mount is separate from that label: the first volume is mounted at root, and the login and worker nodes share the home directories on it.

![Add Default Volume form with storage classes marked single-node read/write](/images/docs/everywhere-ai/user/slurm/create-slurm-cluster/slurm-add-volume-new.png)

If the volume already exists, select **Existing Volume**. Only volumes with **Available** status can be attached. Volumes can be prepared in advance from the [Volumes](/everywhere-ai/user/volumes/manage-volumes) section.

</Step>

<Step title="Add a sidecar container">

Additional containers run alongside the Slurm nodes and are not required to create the cluster. Up to 16 can be added during creation or later. A container needs a name and an image. Select where it runs: the login nodes, all worker node sets, one worker node set, or all nodes. A private registry also requires registry credentials. Resource limits, the start command, environment variables, and files are optional.

![Sidecar container form with a public registry and login nodes selected](/images/docs/everywhere-ai/user/slurm/create-slurm-cluster/slurm-sidecar-form.png)

</Step>

<Step title="Create the cluster">

In the **Cluster settings** section at the bottom of the form, enter a **Cluster Name**. The name must be unique within the project and cannot be changed after creation.

Use **Add Slurm Config** to add Slurm settings that override matching values from the sections above. This configuration can also be adjusted later from the **Slurm Config** tab after the cluster is ready.

![Cluster settings section showing Cluster Name field and Add Slurm Config toggle](/images/docs/everywhere-ai/user/slurm/create-slurm-cluster/slurm-cluster-settings.png)

Click **Create Slurm Cluster**. The cluster progresses from **Pending** to **Deploying** and finally **Ready**.

</Step>

</Steps>

## Connect to the cluster

The cluster must be in **Ready** status and the login node must have **Active** status. Open the cluster detail page — the **Root access** field in the header shows the full SSH command:

```bash
ssh root@<login-node-ip>
```

Once connected, [Submit&nbsp;jobs](/everywhere-ai/user/slurm/submit-jobs) covers `sbatch`, `squeue`, and `scancel` with examples.

---

Open **Training**, then **Slurm**, and click the cluster name. The page opens on **Resources**, where **Root access** is the SSH command for the login node.

## Login nodes and worker sets

Under **Login Nodes**, click **Edit** to change the flavor, node count, or **Root-user SSH keys**. A cluster can have up to five login nodes. The row stays **Updating** while the change is applied.

Raise the node count of an existing set to add capacity with the same hardware. To add capacity with different hardware, click **Add Worker Node Set**, then select **GPU** or **CPU**, a flavor, and a node count. From the row menu, resize that set, switch it to another flavor, or delete it.

## Run an additional container

Click **Add Container** to run an additional container alongside Slurm. Select whether it runs on the login nodes, a specific worker set, all worker sets, or all cluster nodes. A cluster can have up to 16 additional containers. Saving a change recreates that container on every node where it runs. The name cannot be changed after creation.

![Resources tab with login nodes, a worker node set, and additional containers](/images/docs/everywhere-ai/user/slurm/manage-slurm-cluster/slurm-cluster-detail-nodes.png)

## Attach storage

The first volume is the default, mounted at **Root** for the shared home directories. That path is fixed, so the volume cannot be detached or moved.

Click **Add Volume** to attach another disk to the cluster. The mounted volume is available from both login nodes and worker nodes. The mount path has to sit under `/home`, cannot be `/home` itself, and cannot overlap another volume. The size can only grow. Click **Edit mount path** to move the volume to another path under `/home`.

Detaching a later volume only unmounts it, so the disk stays in the project.


<Warning>
Files written outside mounted volume paths are lost when the cluster is deleted.
</Warning>


![Storage tab with the default volume mounted at Root](/images/docs/everywhere-ai/user/slurm/manage-slurm-cluster/slurm-cluster-storage.png)

## Separate workloads with partitions

The `default` partition already covers the cluster's worker node sets. **Create Partition** adds one when a workload needs a different set, a different time limit, or a different priority. On the row, click **Set State** to change what that partition accepts. **Up** takes new jobs, **Down** stops new scheduling, **Drain** lets running jobs finish, and **Inactive** rejects submissions. Use the same menu to edit or delete the partition.

Set **Preempt Mode** to decide what happens to a running job when a higher-priority job needs the same nodes. Cancel the job, requeue it, or suspend it until those nodes are free. **Disabled** leaves the running job in place.

Set **Default memory per GPU** to reserve host memory for each GPU when the job does not request memory. Leave the value empty to set no default.

![Partitions tab with the default partition in the Up state](/images/docs/everywhere-ai/user/slurm/manage-slurm-cluster/slurm-cluster-partitions.png)

## Override the default Slurm configuration

On **Slurm Config**, click **Add custom configuration** to override the default Slurm settings. Clear the field to remove the override and return to the defaults.


<Warning>
Custom Slurm settings are not validated. An invalid setting can make the cluster unavailable.
</Warning>


Open **Logs** when a custom setting does not take effect.

![Slurm Config tab with the custom configuration action](/images/docs/everywhere-ai/user/slurm/manage-slurm-cluster/slurm-cluster-slurm-config.png)

## Delete a cluster

On the **Delete** tab, click **Delete Slurm Cluster**, type `Delete`, and confirm the deletion.


<Warning>
Deletion removes the compute nodes and cluster configuration and cannot be undone. Attached volumes remain in the project. Files written outside mounted volume paths are lost.
</Warning>

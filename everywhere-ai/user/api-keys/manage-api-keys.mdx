---
title: "API Keys"
description: "Create and manage API keys for authenticating requests to inference instances in Everywhere AI."
---

API keys authenticate requests to [inference instances](/everywhere-ai/user/inference-instances/manage-inference-instances). Create a key, attach it to one or more instances, and include it in the `Authorization` header when sending requests. Once at least one key is attached to an instance, requests have to provide a valid key in the `Authorization` header; otherwise they are rejected with 401 Unauthorized.

Keys are project-scoped. A key can be attached to multiple instances, and each instance can have multiple keys.

## View API keys

Navigate to **Inference** > **API Keys** in the sidebar.

![API Keys list showing existing keys with names, descriptions, and expiration dates](/images/docs/everywhere-ai/user/api-keys/manage-api-keys/api-keys-list.png)

The list shows all keys in the current project. Each row displays the key **Name**, a **Description** explaining its purpose, the **Expires at** date (or "Never" for keys with no expiration), and which **Inference instances** use the key. Click a column header to sort by that field, or use the search box to filter keys by name.

## Create an API key

Creating an API key generates a secret token that can authenticate requests once it is attached to an inference instance.

1. Navigate to **Inference** > **API Keys**.
2. Click **Create API Key**.
3. Enter the key details:
   - **Name**: Unique identifier for the key.
   - **Description**: Purpose or owner of the key.
   - **Expires at**: Select **Never expire** for keys that do not expire, or **Set an expiration date** for temporary access (contractor engagements, testing periods).
4. Click **Add**.

![Add API Key dialog with Name, Description, and Expires at fields](/images/docs/everywhere-ai/user/api-keys/manage-api-keys/api-keys-create-form.png)


<Warning>
The key value is displayed only once. Copy it immediately and store in environment variables or a secret manager—never in source code. The value cannot be retrieved later.
</Warning>


## Attach API keys to an instance

API keys must be attached to an inference instance before they can authenticate requests. Once at least one key is attached, the endpoint requires authentication. An instance with no keys attached accepts all requests without authentication.

A single key can protect multiple instances, and an instance can accept multiple keys.

**During instance creation:**

1. In the **API Keys** section, select one or more keys from the dropdown.
2. Complete the instance configuration and click **Create**.

![API Keys section in Create Inference Instance form showing dropdown with available keys](/images/docs/everywhere-ai/user/api-keys/manage-api-keys/api-keys-create-instance.png)

**For existing instances:**

1. Open the instance detail view.
2. Navigate to the **API Key authentication** tab.
3. Select keys from the dropdown and click **Save changes**.

![API Key authentication tab in instance detail view with key selection dropdown](/images/docs/everywhere-ai/user/api-keys/manage-api-keys/api-keys-instance-tab.png)

## Use API keys in requests

Include the key in the `Authorization` header as a Bearer token. The endpoint URL is available in the instance's Overview tab. The path that follows that URL depends on the deployed model.

**GET request:**

```bash
curl https://<endpoint-url>/<path> \
  -H "Authorization: Bearer <API_KEY>"
```

**POST request with JSON payload:**

```bash
curl -X POST https://<endpoint-url>/<path> \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"input": "data"}'
```

If requests return 401 Unauthorized, verify the key is valid, not expired, and attached to the instance in the **API Key authentication** tab.

## Manage API keys

Each key in the list has a menu (three dots) with management options.

![API key context menu showing Edit and Delete options](/images/docs/everywhere-ai/user/api-keys/manage-api-keys/api-keys-menu.png)

To **edit** a key, open the menu and select **Edit**. The description can be edited. The name and expiration date cannot be changed after creation.

To **delete** a key, select **Delete** from the menu and confirm.


<Warning>
Deletion is immediate and cannot be undone. Requests that use this key stop being authenticated immediately. Verify no active integrations depend on the key before proceeding. If a key may be compromised, create a replacement first, update integrations, then delete the old key.
</Warning>


Keys with an expiration date stop authenticating requests as soon as the date passes. Replace a key before it expires to avoid an interruption.

**Deployment** runs the model in a single container — the default for most workloads. When the model is too large for one node and must be sharded across multiple GPUs, **MultiNode** adds a leader pod that coordinates a fixed set of worker pods. For high-throughput LLM serving that requires a disaggregated inference graph with separately configured Router, Prefill, and Decode components, use **Dynamo by NVIDIA** — [Dynamo&nbsp;instance](/everywhere-ai/user/inference-instances/create-dynamo-instance).

Open **Inference**, then **Inference Instances**. On an empty list, click **Create Deployment**, **Create MultiNode**, or **Create Dynamo**. When the list already has instances, those choices are under **Create inference instance**.

![Empty inference list with Create Deployment, Create MultiNode, and Create Dynamo](/images/docs/everywhere-ai/user/inference-instances/create-inference-instance/create-entry-point.png)

<Tabs>

<Tab title="Deployment">

Deployment runs a single container image, replicated and autoscaled per region. The container receives requests directly and returns responses — suitable for any model that fits on one node.

<Steps>

<Step title="Configure the workload">

In the **General** section, enter an **Inference instance name**. The name appears in the instance list and forms part of the endpoint URL.

Select the **Registry type**: **Public Registry** for a public registry, or **Private Registry** for an image in a project registry. Enter the **Image** name or registry path. Enable **Add authorization** and select a [pull&nbsp;secret](/everywhere-ai/user/pull-secrets/manage-pull-secrets) when the registry requires authentication.

Under **Startup command**, enable **Set startup command** to override the container's default entrypoint.

![Exposure section showing Container port, Read timeout, and Disable response buffering fields](/images/docs/everywhere-ai/user/inference-instances/create-inference-instance/create-deploy-exposure.png)

Under **Exposure**, set the **Container port** to the port the application listens on (default: 80). Requests return 502 if the port does not match what the container serves. **Read timeout** sets the maximum wait for a response — increase this for models with long inference times. Enable **Disable response buffering** for streaming or SSE responses.

</Step>

<Step title="Configure resources and scaling">

![Flavor dropdown and Regions section with available capacity per region](/images/docs/everywhere-ai/user/inference-instances/create-inference-instance/create-flavor.png)

Select a **Flavor** with the CPU, memory, and GPU resources the model requires. Under **Regions**, each selected region creates an independent deployment with its own endpoint URL — scaling, logs, and monitoring are per region.

If the model requires stored weights or persistent data, click **Add Volume** under **Storage** to attach a volume in the same region as the instance. Add **Environment variables** next to **Storage**, as key-value pairs for the container.

Under **Autoscaling**, **Global** keeps one **Minimum pods** and **Maximum pods** value for every selected region. **Custom** sets those bounds on each region. Cooldown, the polling interval, and CPU or GPU triggers apply in both.

Under **Health checks**, configure probes to manage the container lifecycle. The **Startup probe** delays liveness and readiness checks during initialization — useful for models that take time to load weights. **Liveness** restarts a non-responding container; **Readiness** removes it from load balancing until it passes.

</Step>

<Step title="Configure access and create">

Under **API keys**, select keys to enforce authentication. With at least one key attached, the endpoint rejects unauthenticated requests.

Click **Create inference instance**. **Deployment status** stays **Provisioning** until the instance is **Active**, when **Endpoint** on **Overview** opens the address for that region.

</Step>

</Steps>

</Tab>

<Tab title="MultiNode">

MultiNode runs one leader pod and N worker pods per replica group, all using the same container image and flavor. The leader is the external endpoint for the group and coordinates the workers, which handle the model computation.

<Steps>

<Step title="Configure the instance">

Name the instance and specify the **Image** that the leader and workers both run, from a **Public Registry** or a **Private Registry**. Enable **Add authorization** and attach a [pull&nbsp;secret](/everywhere-ai/user/pull-secrets/manage-pull-secrets) when that registry requires authentication.

Clients reach the leader, so **Container port** is the port that leader serves. One **Flavor** and the selected **Regions** apply to the leader and the workers together.

</Step>

<Step title="Configure the leader and workers">

![Leader section showing LWS_GROUP_SIZE injection note, Set startup command toggle, and Environment variables fields](/images/docs/everywhere-ai/user/inference-instances/create-inference-instance/create-multinode-leader.png)

**Leader:** The runtime injects `LWS_GROUP_SIZE` at startup. Reference it in the startup command as `$(LWS_GROUP_SIZE)` to pass the replica count to the serving framework. Enable **Set startup command** and add any leader-specific **Environment variables**.

![Workers section showing LWS_LEADER_ADDRESS injection note, Workers per replica field, and Set startup command toggle](/images/docs/everywhere-ai/user/inference-instances/create-inference-instance/create-multinode-workers.png)

**Workers:** Set **Workers per replica** to the number of worker pods per replica group. The runtime injects `LWS_LEADER_ADDRESS` into each worker — reference it as `$(LWS_LEADER_ADDRESS)` in the startup command to register with the leader. Enable **Set startup command** and add worker-specific **Environment variables**.

</Step>

<Step title="Configure scaling and create">

Under **Autoscaling**, **Global** uses one **Minimum pods** and **Maximum pods** range for every region. **Custom** sets that range on each region. Cooldown, the polling interval, and CPU or GPU triggers apply in both.

Under **API keys**, select keys to enforce authentication.

Click **Create inference instance**. **Deployment status** stays **Provisioning** until the instance is **Active**, when **Endpoint** on **Overview** opens the address for that region.

</Step>

</Steps>

</Tab>

</Tabs>

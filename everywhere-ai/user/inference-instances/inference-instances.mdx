Inference instances are containerized AI model deployments that serve predictions through HTTPS endpoints. Container orchestration, load balancing, and autoscaling are handled automatically — deployments scale from zero to multiple pods based on demand and include monitoring, logging, and health checks. Authentication is enforced through API keys when needed.

Each instance runs a container image from a registry and exposes it at a dedicated URL. The container can be a custom model, a vLLM or SGLang serving stack, or a pre-configured application from the [Application&nbsp;Catalog](/everywhere-ai/user/application-catalog/application-catalog).

## Workload types

The creation form starts with a workload type selection. The type determines how the container or containers are orchestrated and which configuration options are available.

| Workload type | Description | Use when |
|---|---|---|
| **Deployment** | A single container image, replicated and autoscaled per region. | Serving any model that fits on one node — the default for most deployments. |
| **MultiNode** | A leader pod coordinates fixed worker pods running the same image. | Large models sharded across multiple GPUs using tensor or pipeline parallelism. |
| **Dynamo by NVIDIA** | A graph of Router, Prefill, and Decode components; topology is either Aggregated (combined prefill and decode) or Disaggregated (separate worker pools). | High-throughput LLM inference — especially when independent scaling of prefill and decode phases is needed. |

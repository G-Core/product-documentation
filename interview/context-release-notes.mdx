## CDN platform v2.14.1

**Released:** 2 weeks ago

### New features

- **Custom error pages (limited rollout).** CDN resources now support configuring a custom URL to serve when specific error codes occur. Supported codes in this release: **404 Not Found**. Additional codes to follow in upcoming releases.
- Purge history retention extended from 14 days to 30 days.
- TLS 1.0 and 1.1 removed from all edge nodes. Minimum TLS version is now 1.2.

### Bug fixes

- Fixed: origin SSL validation was incorrectly rejecting certificates with wildcard SANs.
- Fixed: Cache-Control headers with `s-maxage=0` were sometimes ignored on shared cache nodes.

## CDN platform v2.15.0

**Released:** 5 days ago

### New features

- **Custom error pages: added 503 Service Unavailable and 429 Too Many Requests.** These codes can now be configured alongside 404. Configuration interface unchanged.
- CMCD (Common Media Client Data) header forwarding is now enabled by default on video CDN resources.
- New metric available in statistics: `origin_error_rate_5xx`.

### Bug fixes

- Fixed: CDN-8611 — purge by pattern with nested wildcards now correctly clears all matching objects.
- Fixed: CDN-8629 — purge history API status latency reduced from ~2 min to under 5 seconds.

### Known issues

- Custom error pages on resources with Large files delivery optimization may exhibit delayed fallback on cache miss. Investigation in progress (CDN-8891).

## CDN platform v2.13.4

**Released:** 6 weeks ago

### Changes

- Origin shielding: precache node selection UI updated. Location names now match the data center naming used in the Cloud product.
- Log export: added `cache_status` field to raw log format. Existing integrations are unaffected.

## CDN platform v2.12.0

**Released:** 3 months ago

### New features

- Purge by pattern now supports up to 10 patterns per request (previously 5).
- Added `traceparent` header forwarding for distributed tracing support.

### Removed

- Legacy XML-based statistics API (`/cdn/resources/{id}/stats.xml`) removed. Use the JSON API instead.

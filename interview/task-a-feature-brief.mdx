## Feature brief: Custom error pages

**Product area:** CDN > CDN resource options

**Prepared by:** Product team

---

### Background

When a CDN resource returns an HTTP error — such as 404 Not Found or 503 Service Unavailable — the end user sees a default Gcore error page. This page is generic and not branded.

Custom error pages allow customers to replace that default response with their own HTML page. The page can include the company logo, a helpful message, and a link back to the homepage.

### Where this is configured

Customer Portal: open a CDN resource → go to **Options** → find the **Custom error pages** section.

### How it works

The customer enters a URL pointing to their custom HTML page. When the CDN resource encounters an eligible error, it fetches that URL and serves the response to the end user.

The feature can be configured per CDN resource. A single URL can cover all error codes, or different URLs can be set for different codes.

### Supported error codes

The feature supports 4xx and 5xx HTTP status codes.

### Additional notes from the PM

- The custom page URL must be reachable by the CDN. It can be hosted on the same CDN resource or at an external address.
- There is some behavior related to caching — the custom error page content may be cached by the CDN. Will confirm details with engineering.
- The response status code delivered to the end user can optionally be overridden. For example, a 404 error can be served with a 200 response code if configured that way.
- This feature is available on all CDN plans.

### What the article should cover

1. What custom error pages are and when a user would need them.
2. How to configure the feature in the Customer Portal (step by step).
3. Any limitations or requirements the user needs to know before setting this up.
4. How to verify that the custom error page is working.

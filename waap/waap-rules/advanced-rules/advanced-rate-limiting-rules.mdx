<p>Create a rate-limiting [Advanced Rule](/waap/waap-rules/advanced-rules) on **Custom Rules** to cap how many matching requests a domain accepts in a time window. Start from a Quick Template, configure `request.limit_rate` in the visual builder, or write a CEL expression.</p>

<p>A **Rate Limit** rule type sets a single per-IP threshold without CEL. Use **Advanced Rule** to apply a template, combine conditions, or edit `request.limit_rate` parameters.</p>

## Advanced Rule creation

<Steps>
  <Step title="Custom Rules page">
    In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **WAAP** > **Custom Rules**. Click **Add custom rule**.
  </Step>
  <Step title="Advanced Rule type">
    Enter a **Rule name**. Under **Rule type**, select **Advanced Rule**.

## Quick Templates

<p>Under **Quick Templates**, click **Captcha Rate Limit 100 req/5s** or **Block Rate Limit 200 req/5s**.</p>

<p>**Captcha Rate Limit 100 req/5s** sets the action to **Captcha** and generates:</p>

```text
request.limit_rate(url='.*', interval=5, requests=100, scope='ip')
```

<p>**Block Rate Limit 200 req/5s** sets the action to **Block** and generates:</p>

```text
request.limit_rate(url='.*', interval=5, requests=200, scope='ip')
```

<Frame>![Advanced Rule builder with Captcha action, limit_rate condition, and Quick Templates](/images/docs/waap/waap-rules/advanced-rules/advanced-rate-limiting-rules/captcha-rate-limit-builder.png)</Frame>

<p>Both templates match every URL (`.*`) and count requests per IP. Click **Save** to keep the template values, or adjust the function first.</p>

## Rate-limit configuration

<p>In the visual builder, the condition uses object **request** and attribute **limit_rate**. Click **Edit Config** to change the threshold, time window, URL pattern, scope, and optional filters.</p>

<Frame>![request.limit_rate configuration panel with url, interval, requests, and scope](/images/docs/waap/waap-rules/advanced-rules/advanced-rate-limiting-rules/limit-rate-config.png)</Frame>

<p>The dialog requires a URL pattern, interval, request count (minimum 20), and scope (`ip` or `cluster`). Optional lists narrow the count to specific IPs, methods, status codes, a content type, or a tag.</p>

<p>Click **Apply Configuration**. The **Expression** field updates to the generated CEL. Add more **And** rows to combine the rate limit with other attributes. Click **Save**.</p>

## CEL expression

<p>Click **Edit manually** to replace the visual builder with a CEL editor. The generated `request.limit_rate(...)` expression stays in the field and can be combined with other conditions.</p>

<Frame>![CEL expression editor showing request.limit_rate with Visual builder toggle](/images/docs/waap/waap-rules/advanced-rules/advanced-rate-limiting-rules/edit-manually-expression.png)</Frame>

<p>Click **Visual builder** to return to the condition rows. Additional conditions in the same rule control when the action runs — they do not change how requests are counted. Click **Save**.</p>

<p>Rate-limiting rules use the `request.limit_rate` method in a CEL `source` expression. This is part of [WAAP advanced rules](/waap/waap-rules/advanced-rules).</p>

<p>Rate-limiting conditions are evaluated as part of a rule's condition logic and can be combined with other request attributes to control when an action is triggered.</p>

## Rate limiting method

<p>Use the `request.limit_rate` method to implement rate limiting:</p>

<p>**limit_rate fixed method signature**</p>

```js
request.limit_rate(
    requests = <int>,
    interval = <int>,
    url = <string>,
    ip_list = [<string>, ...],
    method_list = [<string>, ...],
    status_list = [<int>, ...],
    content_type = <string>,
    scope = <string>,
    tag = <string>
)
```

<p>Specify the `tag` parameter when configuring tag-based rate limiting rules.</p>

<p>The method returns `true`, and the enclosing rule condition is satisfied when the request count (4), under the granularity (8), exceeds the configured threshold within the specified time window (3), using the configured filters (1, 2, 5, 6, 7, 9).</p>

| # | Parameter name        | Required                                                                                                | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | --------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | `ip_list`             | False                                                                                                   | List of IP addresses that the rule applies to. If there are no IPs in the list, counting will be done for all IPs.                                                                                                                                                                                                                                                                                                                                    |
| 2 | `url`                 | True                                                                                                    | A regex pattern used to match the request's URI (URL + query_params).                                                                                                                                                                                                                                                                                                                                                                                      |
| 3 | `interval`            | True                                                                                                    | The time limit, in seconds, within which we only allow **n** number of requests to URI matching the pattern.                                                                                                                                                                                                                                                                                                                                               |
| 4 | `requests`            | True                                                                                                    | The maximum number of requests **accepted** within the given period before an action is taken (minimum value is 20 requests).                                                                                                                                                                                                                                                                                                                              |
| 5 | `method_list`         | False                                                                                                   | List of method types the request aggregation will be applied to.                                                                                                                                                                                                                                                                                                                                                                                           |
| 6 | `status_list`         | False                                                                                                   | List of status codes the request aggregation will be applied to.                                                                                                                                                                                                                                                                                                                                                                                           |
| 7 | `content_type`        | False                                                                                                   | Regex pattern to match request content_type against.                                                                                                                                                                                                                                                                                                                                                                                                       |
| 8 | `scope` (granularity) | Optional. If omitted, the scope defaults to `cluster`. | When protecting the origin, rate limit rules can apply to either IPs or all requests that come through the cluster. If set to `ip`, the rule is triggered when one IP exceeds the threshold — this helps against individual attackers. If set to `cluster`, the rule is triggered when the total requests from any IP in that cluster exceed the threshold — this helps protect the origin from getting too many requests. |
| 9 | `tag`                 | False                                                                                                   | Aggregation of tagged ([user-defined tags](/waap/waap-rules/custom-rules/tag-rules#tag-generating-rules)) requests will be applied for each IP.                                                                                                                                                                                                                                                                                                            |

## Implementation

<p>An [API token](/account-settings/api-tokens) is required along with the ID of a [WAAP-protected domain](/waap/getting-started/configure-waap-for-a-domain). For SDK examples, install the [Python](/developer-tools/sdks/python) or [Go](/developer-tools/sdks/go) SDK. Set these as environment variables before running any of the examples:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
export WAAP_DOMAIN_ID="{YOUR_DOMAIN_ID}"
```

<p>To list, update, enable, disable, or delete rules, see [Advanced Rules](/waap/waap-rules/advanced-rules).</p>

### Rate limiting with exclusions

<p>Rate-limit IPs that exceed 200 requests in 5 seconds on any `/events` path, while excluding requests from known mobile and web clients that carry session cookies.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import gcore
    import os

    client = gcore.Gcore()
    domain_id = int(os.environ["WAAP_DOMAIN_ID"])

    rule = client.waap.domains.advanced_rules.create(
        domain_id,
        name="Block Scrapers",
        description="Block IPs that hit more than 200 requests per 5 seconds for any events paths",
        enabled=False,
        phase="access",
        action={"block": {"status_code": 403, "action_duration": "10m"}},
        source=(
            "request.limit_rate(url='.*events', interval=5, requests=200, scope='ip')"
            " and not ('mb-web-ui' in request.headers['Cookie']"
            " or 'mb-mobile-ios' in request.headers['Cookie']"
            " or 'mobile-android' in request.headers['Cookie']"
            " or 'mb-mobile-android' in request.headers['Cookie']"
            " or 'session-token' in request.headers['Cookie'])"
            " and not request.headers['session']"
        ),
    )
    print(f"Created rule ID: {rule.id}")
    ```
  </Tab>
  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "fmt"
        "os"
        "strconv"

        gcore "github.com/G-Core/gcore-go"
        "github.com/G-Core/gcore-go/waap"
    )

    func main() {
        client := gcore.NewClient()
        domainID, err := strconv.ParseInt(os.Getenv("WAAP_DOMAIN_ID"), 10, 64)
        if err != nil {
            panic(fmt.Errorf("invalid WAAP_DOMAIN_ID: %w", err))
        }

        source := "request.limit_rate(url='.*events', interval=5, requests=200, scope='ip')" +
            " and not ('mb-web-ui' in request.headers['Cookie']" +
            " or 'mb-mobile-ios' in request.headers['Cookie']" +
            " or 'mobile-android' in request.headers['Cookie']" +
            " or 'mb-mobile-android' in request.headers['Cookie']" +
            " or 'session-token' in request.headers['Cookie'])" +
            " and not request.headers['session']"

        rule, err := client.Waap.Domains.AdvancedRules.New(
            context.Background(),
            domainID,
            waap.DomainAdvancedRuleNewParams{
                Name:        "Block Scrapers",
                Description: gcore.String("Block IPs that hit more than 200 requests per 5 seconds for any events paths"),
                Enabled:     false,
                Phase:       waap.DomainAdvancedRuleNewParamsPhaseAccess,
                Action: waap.DomainAdvancedRuleNewParamsAction{
                    Block: waap.DomainAdvancedRuleNewParamsActionBlock{
                        StatusCode:     403,
                        ActionDuration: gcore.String("10m"),
                    },
                },
                Source: source,
            },
        )
        if err != nil {
            panic(err)
        }
        fmt.Printf("Created rule ID: %d\n", rule.ID)
    }
    ```

### Per-IP rate limit for any URL

<p>Each request is counted individually per IP. If `203.0.113.10` sends more than 200 requests within 5 seconds, it is blocked. Another IP, `203.0.113.11`, is only blocked when it independently exceeds the same threshold.</p>

    ```python
        domain_id,
        name="Limit Certain IPs",
        description="Limit Certain IPs",
        enabled=False,
        phase="access",
        action={"block": {"status_code": 403}},
        source="request.limit_rate(url='.*', interval=5, requests=200, scope='ip')",
    ```

### Additional conditions

### Complex URL regex

<p>Block requests to any URL that does not end in a known static asset extension — images, fonts, scripts, archives. Requests to dynamic paths are rate-limited at 20 per 120 seconds per IP.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import gcore
    import os

    client = gcore.Gcore()
    domain_id = int(os.environ["WAAP_DOMAIN_ID"])

    url_pattern = (
        r".*(?<!aif|aiff|au|avi|bin|bmp|cab|carb|cct|cdf|class|css|doc|dor|dtd"
        r"|exe|flv|gcf|gff|gif|grv|hdmt|hqx|ico|ini|jpeg|jpg|js|mov|mp3|nc|pct"
        r"|pdf|png|ppc|pws|svg|swa|swf|txt|vbs|w32|wav|wbmp|wml|wmlc|wmls|wmlsc"
        r"|xsd|zip|webp|jxr|hdp|wdp|webm|ogv|mp4|tif|woff|wot)$"
    )

    rule = client.waap.domains.advanced_rules.create(
        domain_id,
        name="Rate limit dynamic paths",
        description="Rate limit complex URL regex",
        enabled=False,
        phase="access",
        action={"block": {"status_code": 403}},
        source=f"request.limit_rate(url='{url_pattern}', interval=120, requests=20, scope='ip')",

    print(f"Created rule ID: {rule.id}")
    ```

### Cluster granularity

<p>Rate-limit all `GET` or `HEAD` requests that return a `302` redirect with a specific content type. The `cluster` scope counts requests across IPs within the same cluster or point of presence (PoP), not necessarily across the entire WAAP network — useful for protecting origin from aggregate traffic spikes on that PoP.</p>

<Tabs>
  <Tab title="Python SDK">
    ```python
    import gcore
    import os

    client = gcore.Gcore()
    domain_id = int(os.environ["WAAP_DOMAIN_ID"])

    rule = client.waap.domains.advanced_rules.create(
        domain_id,
        name="RL GET or HEAD redirected requests cluster",
    ```

### Rate limit aggregation and rule triggering

<p>Rate limit aggregation is defined exclusively by the parameters of the `request.limit_rate(...)` condition, such as the aggregation scope, IP list, or tags.</p>

<p>When `request.limit_rate(...)` is combined with additional conditions in the same rule, those additional conditions control when the rule action is applied, not how requests are aggregated.</p>

<p>For example, if a rate limit condition is configured without an IP list and combined with a condition such as `request.ip == '203.0.113.10'`, request aggregation will still occur according to the rate limit definition. However, the rule action will only be triggered when the full rule condition evaluates to true — in this case, only for requests originating from `203.0.113.10`.</p>

<p>This distinction is important when combining rate limiting with other conditions so the rule behaves as expected.</p>

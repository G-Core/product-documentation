A BGP session connects Gcore to the routers that announce a protected network, so routes update without a support request. The session stores the AS number and the public IP addresses Gcore peers with. The same session can be attached to every protected network that uses that AS number.

## Create a session

Create the session in the [Gcore Customer Portal](https://portal.gcore.com). A [protected network](/ddos-protection/onboarding-service/network-submission) with the required AS number must already be on the account, because the AS number list comes from that network. A network in **Approval pending** does not appear in the list.

1. Go to **DDoS Protection** > **Settings** > **BGP sessions**.

   <Frame>
     ![Settings menu with BGP sessions selected and the session list](/images/docs/ddos-protection/onboarding-service/bgp-sessions/bgp-sessions-list.png)
   </Frame>

2. Click **Add session**.

3. In **New BGP session**, set the session:

   | Field | Value |
   | --- | --- |
   | Name | Name shown in the session list. Letters, digits, spaces, hyphens, and underscores, up to 100 characters. |
   | AS number | AS number of a protected network on the account. Networks in **Approval pending** are omitted. |
   | Endpoint IPs | Public IPv4 addresses of the routers that peer with Gcore. These addresses are the BGP neighbors. Filtered traffic uses the GRE endpoint on the protected network, which is a separate address. One session accepts 1 to 10 unique, globally routable addresses. |

   <Frame>
     ![New BGP session dialog with name fra-router-1](/images/docs/ddos-protection/onboarding-service/bgp-sessions/new-bgp-session.png)
   </Frame>

4. Click **Save session**.

   The session appears in the list. **Status** shows **Active**, **Inactive**, or **Error**. **Used by networks** shows how many protected networks use the session, or a dash when none do.

   Attach the session to a protected network so routes for that network update over BGP.

   <Note>
     The account can hold up to 10 BGP sessions. Change the name and the endpoint addresses from the **…** menu, **Edit**. The AS number cannot be changed.
   </Note>

## Attach the session to a network

Attach the session on the protected network once editing is available. Editing opens when the network status is **Active**, **Inactive**, or **Inactive: need info**.

1. Go to **DDoS Protection** > **Settings** > **Protected networks**.

2. Open the **…** (three dots) menu next to the network and select **Edit**.

3. Turn on **Enable BGP session**. The **BGP session** field appears.

   <Frame>
     ![Edit protected network page with Enable BGP session turned on](/images/docs/ddos-protection/onboarding-service/bgp-sessions/edit-protected-network.png)
   </Frame>

4. Select a session.
   - Only sessions with the same AS number are available.
   - To add a session from this page, click **Create new session**. The AS number is set to this network and cannot be changed.

5. Click **Save changes**.

   The BGP session is attached, so routes for this network propagate through BGP.

   <Note>
     Disconnect the session from each protected network before deleting it.
   </Note>

The BGP session is now attached to the protected network. Continue with [network configuration](/ddos-protection/onboarding-service/network-configuration) to set the GRE endpoint and the protection profile, then configure the GRE tunnel and the BGP neighbor on the local router. See the [GRE tunnel setup](/ddos-protection/onboarding-service/gre-tunneling/set-a-gre-tunnel-with-gcore).

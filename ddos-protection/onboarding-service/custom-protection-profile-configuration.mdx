Custom protection profiles define rules and policies based on network traffic and security requirements.

## Protection profile access

<Steps>
  <Step title="Open protection profiles">
    In the [Gcore Customer Portal](https://portal.gcore.com), navigate to **DDoS Protection** > **Protection profiles**.
  </Step>
  <Step title="Review profiles">
    Review the list of available profiles, shown with their assigned networks and template.

    <Frame>

    </Frame>
  </Step>

## Profile creation

<Steps>
  <Step title="Add a protection profile">
    Click **Add protection profile**.
  </Step>
  <Step title="Select the Basic template">
    Select the **Basic** template, which pre-populates four default catch-all rules for TCP, UDP, ICMP, and other traffic. Other templates provide different default configurations and available policies.
  </Step>
  <Step title="Enter a profile name">
    Enter a profile name. Use a clear and descriptive name for easier identification.

    Example: `High-security web server profile`

    <Frame>
      ![Protection profiles](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/add-protection-profile-2.png)
    </Frame>
  </Step>
</Steps>

## Rule and policy configuration

A protection profile has two connected configuration areas: rules on the **Rules** tab match traffic and choose which policy to apply, while the **Policy** tab sets shared thresholds, including rate limits and the GEOIP list, that some of those policies reference.

<Frame>
  ![Protection profiles rules and policies](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/add-protection-profile-3.png)
</Frame>

### Rule configuration

Rules define traffic-matching criteria and apply a selected policy to matching traffic. Selecting the Basic template pre-populates four default rules that match TCP, UDP, ICMP, and other traffic to the corresponding default policy; add more rules to layer specific protections on top of these defaults. Policy IDs and what each policy does are in the [Policy reference](#policy-reference).

<Frame>![How rules work: an IP packet matches a 5-tuple rule, then a policy passes or drops it](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/how-rules-work.png)</Frame>

After a rule matches traffic and a policy processes it, the packet is either dropped or passed to the destination. Later rules do not evaluate that packet again.

#### Rule creation

Add a rule to match specific traffic and apply a policy to it.

<Warning>
Rules are processed from top to bottom and the first matching rule is applied. Traffic that matches none of the rules in the profile is dropped. Retain an appropriate catch-all rule at the bottom of your rule list to avoid unintentionally dropping legitimate traffic. Place specific rules above the matching catch-all rule, or the catch-all matches first and the specific rule never runs.
</Warning>

<Steps>
  <Step title="Add a rule">
    Click **Add rule**.
  </Step>
  <Step title="Configure the rule">
    Complete the required fields:
    - **Protocol**: Select the protocol (TCP, UDP, ICMP, or other).
    - **Source IP**: Enter a source IP address or range.
    - **Destination IP**: Enter a destination IP address or range.
    - **Source port**: Enter a port number or range.
    - **Destination port**: Enter a port number or range.
    - **Policy**: Select the policy to apply.
  </Step>
  <Step title="Set rule priority">
    Drag the rule up or down to set its priority. Because the Basic template's catch-all TCP, UDP, ICMP, and other rules match broad traffic patterns, a new rule for specific traffic must sit above the corresponding catch-all rule.

    <Frame>
      ![Protection profiles rules order](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/protection-profile-rule-order.png)
    </Frame>
  </Step>
  <Step title="Save the rule">
    Click **Save**.

    <Frame>
      ![Protection profiles save rule](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/protection-profile-save-rule.png)
    </Frame>
  </Step>
</Steps>

Multiple rules can be added to a protection profile.

Example: match TCP traffic on destination port `80` (HTTP) and apply the `tcp-server` policy.

### Policy configuration

The **Policy** tab sets profile-level rate limits and the GEOIP list. Available fields depend on the selected template.

<Frame>
  ![Protection profiles Policy](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/protection-profile-policy-1.png)
</Frame>

For the Basic template, the **Policy** tab includes the following fields. Limits are in thousand packets per second (kpps).

- **GEOIP list**: list of countries used by the `geo` policy. Configure the list and select whether the listed countries are **Allowed** or **Denied** before adding a rule that uses the `geo` policy.
- **Rate limiter low**: packet-rate cap for traffic matched by the `ratelimiter-low` policy, up to 50 kpps. Default: 50 kpps.
- **Rate limiter medium**: packet-rate cap for traffic matched by the `ratelimiter-medium` policy, up to 150 kpps. Default: 150 kpps.
- **Rate limiter high**: packet-rate cap for traffic matched by the `ratelimiter-high` policy, up to 300 kpps. Default: 300 kpps.
- **Rate limiter geo**: packet-rate cap applied to traffic matched by the `geo` policy, up to 300 kpps. Default: 300 kpps.

<Frame>
  ![Protection profiles Policy settings](/images/docs/ddos-protection/onboarding-service/custom-protection-profile-configuration/protection-profile-policy-2.png)
</Frame>

Set the GEOIP list and rate-limiter thresholds on the **Policy** tab before selecting the `geo` or rate-limiter policies in a rule.

To let trusted traffic bypass inspection, add a rule on the **Rules** tab with the `allowlist` policy applied to the trusted source IP range. On Enterprise plans, matching traffic bypasses inspection entirely; on public plans, it remains subject to filtering.

## Policy reference

Select a policy ID that matches the traffic when adding a rule. Game policies inspect that game's protocol. Default and rate-limiter policies cap generic floods. TCP policies run handshake or session countermeasures.

Games without a dedicated policy use the matching default policy. Arma 3 and DayZ use UDP, so they use `default-udp`.

| Policy ID | Policy name | Description |
| --- | --- | --- |
| `minecraft` | Minecraft Protection | Minecraft Java and Bedrock (TCP/UDP): handshake, login, ping, and volumetric floods |
| `counter-strike-16` | Counter-Strike 1.6 | GoldSrc engine (Half-Life 1): UDP floods, query abuse, and malformed packets |
| `counter-strike-go` | Counter-Strike GO | Source engine: floods targeting Valve's A2S server-query protocol, connection floods, and high packet rates |
| `counter-strike-2` | Counter-Strike 2 | UDP floods, query abuse, and abnormal packets |
| `left-4-dead-2` | Left 4 Dead 2 | Source engine: floods targeting Valve's A2S server-query protocol and volumetric UDP |
| `fivem-tcp` | FiveM TCP | TCP connection and handshake floods |
| `fivem-udp` | FiveM UDP | High packet rates and abnormal packets |
| `samp` | San Andreas Multiplayer | SA-MP connection floods, query abuse, and malformed UDP |
| `rust` | Rust Game Protection | UDP floods, connection spikes, and abnormal packets |
| `team-speak3` | TeamSpeak 3 Voice Chat | UDP floods and connection abuse on voice sessions |
| `rust-a2s` | Rust Game A2S Caching | Caches Valve A2S server-query responses |
| `bf2-query` | Battlefield 2 Query Caching | Caches server-browser query responses |
| `bf2` | Battlefield 2 Game | UDP floods and malformed packets on gameplay traffic |
| `unity-unet` | Unity Engine UNET | Malformed packets and high packet rates on Unity's legacy UNet networking system |
| `unity-utp` | Unity Engine UTP | UDP floods on Unity Transport Protocol (UTP) |
| `geo` | Geo Restriction | Allow or deny by client location. Configure the GEOIP list on the **Policy** tab first |
| `ssh-server` | SSH Server | SSH connection floods |
| `default-tcp` | Default TCP | Generic TCP. Per-IP 20 kpps / 50 Mbps; overall 50 kpps / 500 Mbps |
| `default-udp` | Default UDP | Generic UDP. Per-IP 5 kpps / 5 Mbps; overall 50 kpps / 50 Mbps |
| `default-icmp` | Default ICMP | Generic ICMP. Per-IP 100 pps; overall 1 kpps |
| `default-other` | Default Other | Other protocols. Per-IP 200 pps; overall 1 kpps |
| `ratelimiter-low` | Rate Limiter Low | Caps destination rate up to 50 kpps (default: 50 kpps). Configure on the **Policy** tab first |
| `ratelimiter-medium` | Rate Limiter Medium | Caps destination rate up to 150 kpps (default: 150 kpps). Configure on the **Policy** tab first |
| `ratelimiter-high` | Rate Limiter High | Caps destination rate up to 300 kpps (default: 300 kpps). Configure on the **Policy** tab first |
| `allowlist` | Allow List | On Enterprise plans, matching traffic is forwarded without inspection. On public plans, allowlisted traffic remains subject to filtering. |
| `tcp-autodetect` | TCP auto-detect | Passive TCP countermeasure, triggered only during an attack |
| `tcp-server` | TCP Countermeasure | Always-on SYN (synchronize) cookie challenge for incoming TCP |
| `tcp-server-v2` | TCP Flow Track | Experimental. Full-session TCP tracking for applications where SYN cookie challenges cause compatibility issues. Not generally available — enable only under guidance from [Gcore Support](https://support.gcore.com/hc/en-us/requests/new). |
| `tcp-private` | TCP Ephemeral Ports Protection | Protects ephemeral (client source) TCP ports |

## Best practices

Keep the following in mind when building and maintaining protection profiles.

- Start with simple rules and expand them as needed.
- Apply a new profile to a non-critical network first, then check the [events log](/ddos-protection/events-log) before using it on production prefixes.
- Document rules and policies for future maintenance.
- Review and update profiles regularly based on traffic patterns.

Once the profile is saved, continue with [applying the profile](/ddos-protection/onboarding-service/apply-a-custom-profile-to-a-protected-network) to a protected network.

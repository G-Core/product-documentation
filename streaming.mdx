Gcore Video Streaming delivers a live signal or an uploaded file to viewers. The path depends on which source is available.

For a live signal, create a [live&nbsp;stream](/streaming/live-streaming/create-a-live-stream) in [Live&nbsp;Streaming](https://portal.gcore.com/streaming/streaming/list), then publish to the ingest URL with RTMP, SRT, or WebRTC WHIP. Gcore transcodes the incoming signal and returns playback manifests.

For an uploaded file, [upload&nbsp;the&nbsp;video](/streaming/video-hosting/getting-started-with-video-hosting) in [Video&nbsp;Hosting](https://portal.gcore.com/streaming/video/list). After processing finishes and the status is ready, the settings page lists the [playback&nbsp;formats](/streaming/video-hosting/hls-and-mp4): HLS, MPEG-DASH, and MP4.

Both paths run in the [Gcore Customer Portal](https://portal.gcore.com). The [Streaming&nbsp;API](/api-reference/streaming) creates the same streams and videos through HTTP requests.

## Player and access

Change that player's appearance in [Player&nbsp;settings](/streaming/player/customize-appearance-of-the-built-in-player), or play the same manifests with the [Player&nbsp;SDK](/streaming/player/player-api-tutorial). Restrict access to playback with [AES-128](/streaming/video-hosting/protect-your-videos-with-the-aes-128-encryption) or a [secure&nbsp;token](/streaming/interaction-with-cdn/video-secure-token).

## Demo video links

More demo videos and live streams across protocols and latency modes (HLS MPEG-TS, HLS CMAF, MPEG-DASH CMAF, LL-HLS, LL-DASH) are available on the [Demo](/streaming/getting-started/demo) page.

## What's new

- Documentation updates: clarified restream audio/source options, live FPS behavior, and statistics filters.
- Added a new [Demo](/streaming/getting-started/demo) page with sample players and manifest links.
- API changes:
    - Added `no_audio` and `no_audio_mode` to restreams, to drop or silence the audio track.
    - Added `source` to restreams, to restream the original or transcoded (with overlays) version.
    - Added `type` filter (live/vod/playlist) to Statistics aggregation methods.
    - Fixed several response/request schemas (videos, broadcasts, players, restreams, playlists) so generated SDKs work correctly.
    - Added active ingest region fields to live stream responses.
- New JS Video Player & SDK. [Jump to JS Player & SDK](/streaming/player/player-api-tutorial) for details.
- Comparison of SRT and RTMP protocols, as well as the specifics of sending SRT over the public Internet. Jump to ["SRT"](/streaming/live-streaming/protocols/srt) for details.
- New restream to SRT target points feature. [Jump to Restream to SRT target points](/streaming/live-streaming/create-and-configure-a-restream-to-social-media) for details.

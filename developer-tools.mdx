The same Gcore account accepts four kinds of change. A one-off script sends HTTP requests, application code calls a generated client, a reviewed configuration file is applied as the desired state, and an AI assistant runs the operation from a sentence. All four use one [API&nbsp;token](/account-settings/api-tokens).

## Direct requests

HTTP fits a single command, a shell script, or a language without a published client. One token reaches Cloud, CDN, DNS, Storage, FastEdge, and the other products. The [REST&nbsp;API](/developer-tools/rest-api/overview) uses one request shape, one error body, and one page size on every product, and a create or delete call returns a task to poll when the work is not finished in the response. The [first&nbsp;call](/developer-tools/rest-api/first-api-call) confirms the token and returns the project and region IDs that later calls need. The [API&nbsp;reference](/api-reference/overview) lists each operation with its parameters and response fields.

## Application code

Call generated methods from Python and Go instead of assembling URLs, because the method and parameter names stay aligned with the OpenAPI specification. The [SDK&nbsp;overview](/developer-tools/sdks/overview) names the packages, the language versions they require, and the cases where a raw request is still the better fit. JavaScript services use `fetch` or axios against the same endpoints, because no JavaScript client is published.

## Infrastructure as code

Terraform stores Cloud and CDN resources as configuration that can be reviewed, reapplied, and rolled back. Provider v2 tracks the current specification and is the version for a new project, while an existing project stays on v0 until its configuration is migrated. The [provider&nbsp;overview](/developer-tools/terraform/overview) shows the difference in authentication and resource syntax. [Getting&nbsp;started](/developer-tools/terraform/get-started-with-terraform) installs the CLI and applies a first file. A resource that already exists in the account enters that file through [import](/developer-tools/terraform/import-existing-gcore-infrastructure-into-terraform) without being created again.

## AI assistants

An assistant that speaks the Model Context Protocol can provision a resource or read its state from a plain-language request, then chain the lookups that request needs. The [MCP&nbsp;server](/developer-tools/mcp-server/gcore-mcp-server-overview) exposes those operations as tools for Claude Code, Cursor, and MCP Inspector. [Server&nbsp;setup](/developer-tools/mcp-server/install-and-configure-gcore-mcp-server) connects the server to a client with an API token. Clients that load every tool schema at once stay within their context limit through [tool&nbsp;filtering](/developer-tools/mcp-server/filter-tools-with-gcore-tools).

<p>A usage report summarizes customer product consumption over a chosen date range, useful for calculating customer costs based on that consumption.</p>

## Generate a report

<Steps>
  <Step title="Open the report dialog">
  1. Navigate to **Billing** > **Reports**.
  2. Click **Create new report** in the upper-right corner.

  <Frame>
  <img src="/images/docs/reseller-support/manuals/generate-monthly-reports/generate-monthly-reports-image1.png" alt="Reports page with the Create new report button and report history table" width="70%"/>
  </Frame>
  </Step>
  <Step title="Configure the report">
  Select **Reseller Statistics V2** from the **Report template** dropdown to generate a usage report; the **Expenses** template covers a different, billing-focused report type.

  1. Under **Group data**, select **Client**, **Resource**, **Region**, or any combination, to control how the usage data is broken out. At least one selection is required.
  2. In the **Date from** and **Date to** fields, enter the reporting period.
  3. Optionally, select a **Product** to limit the report to a single product.
  4. Click **Create**.

  <Frame>
  <img src="/images/docs/reseller-support/manuals/generate-monthly-reports/generate-monthly-reports-image2.png" alt="Create new report dialog with the Reseller Statistics V2 template selected" width="60%"/>
  </Frame>
  </Step>
</Steps>

<p>Generating a report can take a few minutes; the **Status** column on the **Reports** page shows the progress and switches to **Completed** once the report is ready. Because of a short delay in stats collection, generate a report for the previous period a day or two into the new one rather than immediately.</p>

## Read a report

<p>Once a report is **Completed**, its row's action menu downloads the report as CSV, JSON, or Excel.</p>

<p>The CSV file lists one row per usage metric for each of the reseller's customers, grouped by client:</p>

| Column | Description |
|---|---|
| Client ID | The customer account's identifier. |
| Company name | The customer's company name. |
| Feature ID | The internal identifier for the usage metric. |
| Feature name | The name of the usage metric, for example Origin Shielding or CDN - Number of requests. |
| Resource ID | The resource the metric applies to, populated when the report groups by resource. |
| Resource name | The name of that resource. |
| Region external name | The region the metric applies to, populated when the report groups by region. |
| Region name | The internal name of that region. |
| Metric value | The measured usage value for the row. |
| Unit name | The unit the metric value is measured in, for example GB or PC. |

<p>An example of two rows from a CSV report:</p>

```csv
Client ID,Company name,Feature ID,Feature name,Resource ID,Resource name,Region external name,Region name,Metric value,Unit name
00001,Example Company,2296,Origin Shielding,,,,,0.0000,PC
00001,Example Company,12953,CDN - Number of requests (per 10 000 requests),,,,,0.0000,TTS
```

  <MethodSection id="api" label="REST API">

<p>The WAAP Reseller API reports billable consumption for a reseller's clients by metric: number of protected domains, data volume, or request count. Two endpoints expose this data, one aggregated into a single total and one broken down per client.</p>

<p>An [API&nbsp;token](/account-settings/api-tokens) is required. Set it as an environment variable before running the examples:</p>

```bash
export GCORE_API_KEY="{YOUR_API_KEY}"
```

## Get aggregated consumption

<p>Returns the selected metric aggregated across all matching clients into a single daily total for the date range.</p>

| Parameter | Description |
|---|---|
| `metric` | Path parameter: `domains`, `volume`, or `requests` |
| `from` | Report start date (inclusive), in ISO 8601 format; required |
| `to` | Report end date (exclusive), in ISO 8601 format; required |
| `client_ids` | Client IDs to filter by, omitted to include every client |
| `limit` | Number of items to return, up to 100, defaults to 100 |
| `offset` | Number of items to skip, defaults to 0 |

```bash
curl -s "https://api.gcore.com/waap/v1/prebilling/total/requests?from=2026-07-01&to=2026-07-08" \
  -H "Authorization: APIKey $GCORE_API_KEY"
```

<p>The API returns:</p>

```json
{
  "limit": 100,
  "offset": 0,
  "count": 7,
  "results": [
    {"date": "2026-07-01", "amount": 128340},
    {"date": "2026-07-02", "amount": 131980}
  ]
}
```

<p>The `amount` field reports the accrued value of the selected metric for that date. `{TODO: verify in live environment - confirm the exact unit for the "volume" metric, since the spec does not state it}`</p>

## Get consumption broken down per client

<p>Returns the same metric keyed by client ID, with one list of daily entries per client instead of a single aggregated total. It accepts the same parameters as the aggregated total endpoint.</p>

```bash
curl -s "https://api.gcore.com/waap/v1/prebilling/breakdown/requests?from=2026-07-01&to=2026-07-08" \
  -H "Authorization: APIKey $GCORE_API_KEY"
```

<p>The API returns:</p>

```json
{
  "limit": 100,
  "offset": 0,
  "count": 2,
  "results": {
    "clients": {
      "12345": [
        {"date": "2026-07-01", "amount": 54200},
        {"date": "2026-07-02", "amount": 55830}
      ],
      "67890": [
        {"date": "2026-07-01", "amount": 74140},
        {"date": "2026-07-02", "amount": 76150}
      ]
    }
  }
}
```

<p>Each key under `clients` is a client ID, and its value is the same `date` and `amount` pairs returned by the aggregated total endpoint, scoped to that one client.</p>

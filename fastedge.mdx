FastEdge runs custom code on Gcore edge servers close to end users, with no servers to set up or maintain. The code is one of two [application&nbsp;types](/fastedge/getting-started): an HTTP application answers requests sent to its own URL, and a CDN application changes the requests and responses passing through a CDN resource.

## Build and deploy

Choose between two application types:

<CardGroup cols={2}>

<Card title="Respond to requests" href="/fastedge/getting-started/get-started-http">
Build an HTTP application that answers requests at its own URL, with the logic written in Rust or JavaScript. It can send end users to the regional version of a site based on their country, or return data as an API.
</Card>

<Card title="Extend a CDN resource" href="/fastedge/getting-started/get-started-cdn">
Build a CDN application to act on traffic that already flows through a CDN resource. It can rewrite URLs, add headers, or reject requests without a valid token.
</Card>

</CardGroup>

CDN applications must be attached to a CDN resource before they can process live traffic.

HTTP applications can also be deployed without code from built-in templates: [Geolocation&nbsp;redirect](/fastedge/geolocation-redirect) sends end users to a URL chosen by country, and [Markdown&nbsp;renderer](/fastedge/render-markdown) turns Markdown files into HTML pages.

## Manage and reuse applications

Change a deployed application and reuse its setup.

<CardGroup cols={2}>

<Card title="Manage applications" href="/fastedge/manage-apps">
The management page changes the settings of an application without a rebuild, shows its metrics and logs, and stops, updates, or deletes it.
</Card>

<Card title="Templates" href="/fastedge/create-manage-templates">
A template saves a compiled WebAssembly binary together with its parameters, so the same application can be deployed again, each time with its own values.
</Card>

</CardGroup>

## Local development

An application can be built and tested on a local machine before it is deployed. The [local&nbsp;development&nbsp;tools](/fastedge/local-development/overview) fit different workflows: asking a coding agent (Claude Code, Codex, or Cursor), working in VS Code, running automated tests in CI, or running a binary from a terminal with `fastedge-run`.

## Data and secrets

Decide where an application keeps the data and credentials it uses at runtime.

<CardGroup cols={3}>

<Card title="Edge Storage" href="/fastedge/kv-stores/how-it-works">
Edge Storage keeps durable data available to applications at every FastEdge location: configuration, feature flags, and lookup tables.
</Card>

<Card title="Cache" href="/fastedge/cache">
Cache keeps temporary data inside one location (Point of Presence, POP). It suits request counters for rate limiting and results that are worth reusing.
</Card>

<Card title="Secrets" href="/fastedge/secrets-manager/manage-secrets">
Secrets Manager stores API keys, access tokens, and passwords in encrypted form for an application to read at runtime, and supports credential rotation.
</Card>

</CardGroup>

## Monitoring and troubleshooting

Check how an application is behaving, find the cause of a failed request, and follow how long requests take.

- [Metrics&nbsp;and&nbsp;logs](/fastedge/manage-apps#metrics): response status counts and the log entries for each request.
- [Troubleshooting](/fastedge/troubleshooting): FastEdge status codes 530 to 533 and debug logging.
- [Grafana](/fastedge/grafana/view-fastedge-statistics-in-grafana): how long applications take to run, and how that duration changes over time.
